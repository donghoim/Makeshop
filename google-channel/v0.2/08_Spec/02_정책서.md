# [사양 정의서] 구글 채널 연동

## 1. 문서 정보

메이크샵 관리자 **마케팅 > 마케팅 채널 관리** 메뉴(통합 현황, 통합 상품 피드, Meta, Google, TikTok 탭)에 적용하는 정책서입니다. Google 탭은 연결관리·상품피드·구글애즈의 정책 전체를 이 문서에서 정의합니다. Meta 탭은 현재 서비스 정책을 그대로 따르며, 이 문서에서는 Meta에 적용되는 진입 경로·GPC 공통값만 정의합니다.

| 작성일 | 2026-10-22 |

## 2. 변경 사항 요약

### 2.1 한 줄 요약

광고 채널 연동 기능을 **마케팅 > 마케팅 채널 관리** 한 메뉴로 모으고 채널 현황을 한 화면에서 보는 통합 현황·통합 상품 피드를 추가하며, Google 채널을 Meta 채널과 같은 화면 구조와 상품 피드 운영 방식으로 정리합니다.

### 2.2 변경 목적

- 운영자가 광고 채널 연동 기능을 마케팅 메뉴 한곳에서 찾고, 채널별 연결 상태와 채널 등록 상품 수를 한 화면에서 확인하게 합니다.
- 같은 상품이 채널마다 어떤 상태인지 상품 한 행에서 비교하게 합니다.
- Google 채널의 화면 구성과 상품 전송 방식을 Meta 채널과 맞춰, 채널이 달라도 같은 방식으로 운영하게 합니다.
- 신규 채널을 탭과 통합 화면 항목 추가만으로 붙일 수 있는 구조를 만듭니다.

### 2.3 변경 전·후

| 구분 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 메뉴 위치 | 부가서비스 > 부가서비스 > 채널 아래 채널별 메뉴 | 마케팅 > 마케팅 채널 관리, 채널은 탭으로 구분 |
| 기존 메뉴 | 부가서비스 > 채널 > Meta, 구글 상품 피드 | Meta·구글 상품 피드 메뉴 삭제(기존 URL은 새 화면으로 이동, 권한 이관) |
| 채널 현황 | 채널 화면에 하나씩 들어가 확인 | 통합 현황에서 계정·상품 피드·광고 연결 상태와 채널 등록 상품 수를 한 번에 확인 |
| 상품 상태 비교 | 채널별 상품피드 화면에서 각각 확인 | 통합 상품 피드에서 상품 1행에 채널별 상태를 함께 표시 |

| Google 상품 전송 | 동기화 배치(전체·증분·정합성 점검) 단위로 전송 | 전송 대상 상품을 반영대기 상태로 전송 큐에 등록해 자동 전송 |
| Google 상품 상태 | 전송 전 대기 상품도 검토중으로 표시 | 반영대기 상태를 따로 두어 메이크샵 대기와 Google 심사 중을 구분 |
| Google 카테고리 매칭 | 자동 분류·직접 매칭 중 선택, [자동 매칭하기]로 카테고리 없이 바로 전송 | Meta와 같이 카테고리 매칭 필수, 미매칭 상품은 노출제한, [상품 피드 반영] 시 저장 후 전송 큐 등록 |
| GPC | Google은 자동 분류 또는 채널별 직접 매칭 | Meta·Google 공통값 하나로 관리(Meta 정책과 같음). Google 전송 시 Google 공식 택소노미로 검증 |
| Google 관리 범위 | 별도 규칙 없음 | 메이크샵이 전송한 상품만 조회·집계·수정·삭제 |
| TikTok | 없음 | 준비 중 탭 |

## 3. 적용 대상 및 범위

### 적용 대상

- 메이크샵 입점 쇼핑몰 관리자
- 마케팅 > 마케팅 채널 관리 메뉴 전체

### 포함 범위

- 마케팅 채널 관리 메뉴 신설, 탭 구성, 탭 위치 유지, 브레드크럼, 메뉴 권한
- 기존 Meta·구글 상품 피드 메뉴 삭제, 기존 URL 이동, 메뉴 권한 이관
- 통합 현황: 채널 연결 현황, 채널별 운영 현황
- 통합 상품 피드: 메이크샵 상품 기준 채널별 상태 조회, 검색, 채널 상품피드 이동
- Google 탭: 홈 신규, 연결관리·상품피드·구글애즈 정책 전체(Meta 채널 운영 방식 반영 포함)
- Meta·Google GPC 공통값 사용과 Google 택소노미 검증
- TikTok 탭: 준비 중 안내

### 제외 및 예외 범위

- 부가서비스 > 채널 > 네트워크 광고 메뉴 변경(Google Ads ID 설정, 카테고리/상품 예외 설정 포함)
- Meta 탭의 화면·기능·정책 변경. 진입 경로만 바뀝니다.
- TikTok 연동 기능(연결, 상품 피드, 광고)
- 통합 현황·통합 상품 피드에서의 전송, 수정, 카테고리 매칭, 사용여부 변경
- Google Ads 캠페인 생성·수정, 예산·입찰 변경, 권장사항 적용
- 채널 간 광고 성과 합산

### 이용 조건

- 마케팅 채널 관리 메뉴 권한이 있는 운영자만 이용할 수 있습니다.
- Google 채널의 판매 국가는 대한민국, 통화는 KRW로 고정합니다.

## 4. 상세 정책

### 4.1 메뉴와 탭 구성

마케팅 채널 관리 메뉴의 위치, 탭 순서, 화면 이동 규칙입니다.

| 항목 | 정책 |
| --- | --- |
| 메뉴 | GNB **마케팅** 아래 LNB에 **마케팅 채널 관리** 메뉴를 추가합니다. |
| 탭 구성 | 통합 현황 / 통합 상품 피드 / Meta / Google / TikTok 순서로 표시합니다. |
| 기본 진입 | 메뉴를 클릭하면 통합 현황 탭을 엽니다. |
| 채널 탭 진입 | Meta·Google 탭을 누르면 각 채널의 첫 화면(홈)을 엽니다. 통합 화면에서 특정 하위 화면(연결관리, 상품피드 등)으로 이동할 때는 그 하위 화면을 바로 엽니다. |
| 탭 위치 유지 | 현재 탭과 채널 하위 탭을 URL에 남깁니다. 새로고침·뒤로가기·링크 이동 시 같은 화면을 엽니다. |
| 브레드크럼 | 마케팅 > 마케팅 채널 관리 > {탭명} > {채널 하위 탭명} 형식으로 표시합니다. 하위 탭이 없는 화면은 {탭명}까지만 표시합니다. |
| 채널 표시 순서 | 탭, 연결 현황 카드, 운영 현황 행, 통합 상품 피드 컬럼 모두 Meta, Google, TikTok 순서로 맞춥니다. 신규 채널은 뒤에 추가합니다. |
| 권한 | 마케팅 채널 관리 메뉴 권한이 없는 운영자에게는 LNB 메뉴를 비활성화(클릭 불가)로 표시합니다. URL로 직접 접근하면 메이크샵 관리자 공통 권한 처리를 따릅니다. |
| 채널 추가 | 신규 채널은 채널 탭, 연결 현황 카드, 운영 현황 행, 통합 상품 피드 상태 컬럼을 추가하는 방식으로 붙입니다. |

관련 정책: POL-001, POL-002, POL-003, POL-004, POL-005, POL-006, POL-007

### 4.2 기존 메뉴 정리

부가서비스 > 부가서비스 > 채널 아래의 기존 메뉴 중 마케팅 채널 관리로 대체되는 메뉴를 배포와 함께 정리하는 정책입니다.

#### 4.2.1 메뉴 정리

| 기존 메뉴 | 처리 | 정책 |
| --- | --- | --- |
| 부가서비스 > 채널 > Meta | 삭제 | 배포 시점에 삭제합니다. 안내 기간을 두지 않습니다. 기능은 마케팅 채널 관리 Meta 탭에서 제공합니다. |
| 부가서비스 > 채널 > 구글 상품 피드 | 삭제 | 배포 시점에 삭제합니다. 안내 기간을 두지 않습니다. 기능은 마케팅 채널 관리 Google 탭에서 제공합니다. |

- 삭제한 메뉴가 만들어 외부에서 사용 중인 상품 피드 등 연동이 있으면, 메뉴 삭제와 함께 중단하지 않습니다.

#### 4.2.2 기존 URL과 권한

| 항목 | 정책 |
| --- | --- |
| 기존 Meta 메뉴 URL | Meta 탭의 같은 하위 화면으로 이동합니다. 대응하는 하위 화면이 없으면 Meta 홈으로 이동합니다. |
| 기존 구글 상품 피드 메뉴 URL | Google 탭 상품피드로 이동합니다. |
| 메뉴 권한 | 기존 Meta 메뉴 또는 구글 상품 피드 메뉴 중 하나라도 권한이 있던 운영자(부운영자 포함)에게 마케팅 채널 관리 메뉴 권한을 부여합니다. 두 메뉴 모두 권한이 없던 운영자에게는 부여하지 않습니다. |

관련 정책: POL-008, POL-009, POL-010, POL-011, POL-012

### 4.3 통합 현황

모든 채널의 연결 상태와 운영 지표를 한 화면에서 보여주는 대시보드입니다. 화면은 **채널 연결 현황**(카드)과 **채널별 운영 현황**(표) 두 영역으로 구성하며, 채널을 넘나드는 합산 지표(전체 등록 상품 수, 연동 확인 필요 건수, 전송 대기 건수 등)는 두지 않습니다. 모든 값은 각 채널 탭이 이미 조회하는 값을 그대로 사용하고 조회 전용입니다.

#### 4.3.1 채널 연결 현황

| 채널 | 연결 상태 표시 | 버튼 |
| --- | --- | --- |
| Meta | Meta 연결관리 화면에서 확인해 저장한 연결 상태를 표시합니다. | 연결됨: [관리하기] → Meta 탭 첫 화면<br>미연결: [연동하기] → Meta 연결관리 |
| Google | Google 연결관리 화면에서 확인해 저장한 Google 계정 연결 상태를 표시합니다.<br>연결됨 / 재인증 필요 / 미연결 | 연결됨·재인증 필요: [관리하기] → Google 홈<br>미연결: [연동하기] → Google 연결관리 |
| TikTok | 준비 중 | 없음 |

- 카드에는 채널 로고, 채널명, 제공 기능, 연결 상태, 버튼을 표시합니다.

#### 4.3.2 채널별 운영 현황

연동 기능을 제공하는 채널(Meta, Google)만 행으로 표시합니다. TikTok은 표시하지 않습니다.

| 컬럼 | 값 |
| --- | --- |
| 채널 | 채널 로고와 채널명 |
| 계정 연결 상태 | Meta: Meta 비즈니스 연결 상태 / Google: Google 계정 연결 상태 |
| 상품 피드 연결 상태 | Meta: 제품 카탈로그 연결 상태 / Google: Merchant Center 연결 상태 |
| 광고 연결 상태 | Meta: 광고 계정 연결 상태 / Google: Google Ads 연결 상태 |
| 채널 등록 상품 수 | 채널에 전송되어 채널에 등록된 메이크샵 상품 수(아래 집계 기준) |
| 관리 | 연동된 채널: [바로가기] → 해당 채널 탭 첫 화면<br>미연동 채널: [연동하기] → 해당 채널 연결관리 |

- 연결 상태 값은 연결됨 / 재인증 필요 / 미연결입니다. Meta는 FBE로 계정·카탈로그·광고 계정을 한 번에 연결하므로 세 값이 Meta 연결 상태와 같습니다.
- Google 계정이 재인증 필요이면 Google의 세 연결 상태를 모두 재인증 필요로 표시합니다.
- 광고비·ROAS 등 광고 성과는 통합 현황에 두지 않고 각 채널 광고 화면에서 확인합니다.

채널 등록 상품 수 집계 기준

| 채널 | 집계에 포함 | 집계에서 제외 |
| --- | --- | --- |
| Meta | 활동중, 검토중, 미승인 | 반영대기, 노출제한, 사용안함 |
| Google | 활동중, 검토중, 미승인 | 반영대기, 노출제한, 사용안함 |

- 채널에서 직접 등록한 상품은 세지 않습니다.

#### 4.3.3 값 출처와 표시 규칙

통합 현황은 외부 API를 호출하지 않고, 각 채널 화면에서 확인·판정해 메이크샵에 저장한 연결 상태와 상품 상태로 표시합니다. 저장값은 운영자가 채널 화면에 들어가 상태를 확인하거나 상품 상태를 판정할 때 갱신됩니다.

| 상황 | 표시 |
| --- | --- |
| 채널 미연동 | 세 연결 상태는 미연결, 채널 등록 상품 수는 '-', 관리 컬럼은 [연동하기] |
| 상품 피드만 미연결 (예: Google Merchant Center 미연결) | 상품 피드 연결 상태는 미연결, 채널 등록 상품 수 '-' |
| 재인증 필요 | 해당 연결 상태는 재인증 필요. 채널 등록 상품 수는 저장된 값 표시 |

- 채널 간 상품 수를 더하지 않습니다.

관련 정책: POL-013, POL-014, POL-015, POL-016, POL-017, POL-018, POL-019, POL-020, POL-021, POL-022

### 4.4 통합 상품 피드

메이크샵에 등록된 상품을 기준으로 채널별 상품 상태를 한 행에서 비교하는 조회 전용 목록입니다.

| 항목 | 정책 |
| --- | --- |
| 조회 대상 | 메이크샵에 등록된 상품 전체(삭제된 상품 제외) |
| 행 단위 | 메이크샵 상품 1개를 1행으로 표시합니다. 옵션 단위로 행을 나누지 않습니다. |
| 컬럼 | 상품정보(이미지·상품명·상품번호) / Meta 상태 / Google 상태 / 관리 |
| 채널 상태 값 | 각 채널 상품피드 화면에서 그 상품에 표시하는 상태 라벨을 그대로 표시합니다. 채널 간 상태를 합치거나 공통 상태를 만들지 않습니다. |
| 상태가 없는 경우 | 채널이 연동되지 않았거나, 채널 상품 피드가 아직 연동되지 않았거나, 채널 상품피드 목록에 없는 상품은 '-'로 표시합니다. Google은 Merchant Center가 연결되어야 상품 피드가 연동된 것으로 봅니다. |
| 관리 | 채널별 [관리 ↗]를 표시하고, 클릭하면 해당 채널 탭의 상품피드 화면으로 이동합니다. 채널 상품 피드가 연동되지 않았으면 [관리 ↗]를 표시하지 않습니다. |
| 작업 기능 | 전송, 수정, 카테고리 매칭, 사용여부 변경 기능을 두지 않습니다. |
| TikTok | 연동 기능이 생기기 전까지 상태 컬럼을 두지 않습니다. |

#### 4.4.1 검색조건

| 조건 | 정책 |
| --- | --- |
| 상품명 | 입력한 문자열을 포함하는 상품을 조회합니다. |
| 상품번호 | 입력한 상품번호와 일치하는 상품을 조회합니다. |
| 연동 상태 | 채널을 먼저 고르고, 그 채널의 상태값을 고릅니다. 예: Google + 미승인<br>채널만 고르고 상태를 고르지 않으면 해당 채널 조건을 적용하지 않습니다.<br>상품 피드가 연동되지 않은 채널은 선택할 수 없습니다. |

- 검색조건은 모두 AND로 결합합니다.
- [초기화]를 누르면 모든 검색조건을 비우고 전체 상품을 다시 조회합니다.
- 조회 결과가 없으면 '조회된 상품이 없습니다.'를 표시합니다.
- 채널 상태는 각 채널 상품피드에서 판정해 메이크샵에 저장한 값을 표시하며 외부 API를 호출하지 않습니다(POL-021).
- 목록은 상품 등록일 최신순으로 정렬하고, 페이지당 20 / 50 / 100개 중 선택합니다(기본 20개).
- 채널 컬럼이 늘어 화면 폭을 넘으면 표를 가로 스크롤로 표시하고 상품정보 컬럼은 고정합니다.

관련 정책: POL-023, POL-024, POL-025, POL-026, POL-027, POL-028, POL-029

### 4.5 Meta 탭

Meta 탭은 이미 개발이 완료된 Meta 채널 화면을 그대로 표시합니다.

- 아래 항목을 제외한 Meta 화면 구성, 기능, 정책은 현재 서비스 기준 그대로입니다.
- 진입 경로와 브레드크럼만 마케팅 채널 관리 기준으로 바뀝니다.
- GPC는 Meta 정책과 같이 Meta·Google 공통값입니다. Google에서 바꾼 GPC는 Meta에도 같이 적용됩니다.

관련 정책: POL-030, POL-071, POL-072

### 4.6 TikTok 탭

TikTok 연동은 일정이 정해지지 않아 탭만 두고 준비 중으로 안내합니다.

- TikTok 탭을 누르면 연동 기능을 준비 중이라는 안내만 표시합니다. 연동·설정 버튼은 두지 않습니다.
- 통합 현황 채널 연결 현황에는 '준비 중' 카드로 표시하고 버튼은 두지 않습니다.
- 채널별 운영 현황 표와 통합 상품 피드에는 TikTok을 표시하지 않습니다.

관련 정책: POL-031

### 4.7 Google 탭 공통

Google 탭은 Meta 채널 화면과 같은 디자인 기준(레이아웃, 페이지 헤드, 하위 탭, 카드, 표, 버튼, 팝업, 상태 배지)과 탭 구조를 사용합니다. 연동 절차는 Google 방식(계정 연동 후 서비스별 개별 연동)을 유지합니다.

#### 4.7.1 하위 탭과 홈

| 항목 | 정책 |
| --- | --- |
| 하위 탭 | 홈 / 연결관리 / 상품피드 / 구글애즈. Google 탭을 누르면 홈을 엽니다. |
| 홈 구성 | 연결관리·상품피드·구글애즈 카드 3개. 카드마다 영역 설명과 버튼 1개를 표시합니다. |
| 홈 카드 버튼 | 카드별로 연동 여부를 따로 판정해 [설정하기] 또는 [자세히 보기]를 표시합니다. |

| 카드 | [설정하기] 표시 조건 | [자세히 보기] 표시 조건 | [설정하기] 이동 |
| --- | --- | --- | --- |
| 연결관리 | Google 계정 미연결 | Google 계정 연결됨 또는 재인증 필요 | 연결관리 |

- [자세히 보기]는 해당 카드의 하위 탭으로 이동합니다.

#### 4.7.2 하위 탭 진입 조건

하위 탭은 연동 상태와 관계없이 항상 진입할 수 있고, 탭 안에 보여주는 내용만 연동 상태에 따라 달라집니다.

| 하위 탭 | 조건 | 표시 내용과 버튼 동작 |
| --- | --- | --- |
| 상품피드 | Google 계정 미연결 | 연동 안내와 버튼 표시. 클릭 시 연결관리로 이동하고 Google 계정 연동 팝업을 자동으로 엽니다. |
| 상품피드 | Google 계정 연결, Merchant Center 미연결 | 연동 안내와 버튼 표시. 클릭 시 연결관리 Merchant Center 영역으로 이동합니다(Google 로그인 팝업은 다시 열지 않음). |
| 구글애즈 | Google 계정 미연결 | 연동 안내와 버튼 표시. 클릭 시 연결관리로 이동하고 Google 계정 연동 팝업을 자동으로 엽니다. |
| 구글애즈 | Google 계정 연결, Google Ads 미연결 | 연동 안내와 버튼 표시. 클릭 시 연결관리로 이동하고 Google Ads 연결 모달을 자동으로 엽니다. |

- Google 계정이 미연결이면 다른 조건보다 Google 계정 미연결 안내를 먼저 표시합니다.
- 구글애즈 탭의 표시 조건에는 Merchant Center 연결 여부를 포함하지 않습니다.

관련 정책: POL-032, POL-033, POL-034

### 4.8 Google 연결관리

Google 계정, Merchant Center, Google Ads의 연결과 연결 이후 관리 정책입니다.

#### 4.8.1 연동 절차

| 대상 | 선행 조건 | 정책 |
| --- | --- | --- |
| Google 계정 | 없음 | Merchant Center·Google Ads를 쓰기 위한 공통 선행 단계입니다. |
| Merchant Center | Google 계정 연결 | Google Ads와 별개로 진행합니다. |
| Google Ads | Google 계정 연결 | Merchant Center와 별개로 진행합니다. Merchant Center가 없어도 연결할 수 있습니다. |

- Meta처럼 한 번에 모든 자산을 연동하는 방식으로 바꾸지 않습니다. Google 계정 연동 후 Merchant Center와 Google Ads를 각각 따로 연동하며, 둘 중 하나만 연동해도 연동된 기능은 사용할 수 있습니다.
- Google 계정 연동이 끝나면 연결관리를 카드형 화면으로 바꾸고 Google 계정, Merchant Center, Google Ads 영역을 표시합니다. Merchant Center·Google Ads는 미연결 상태로 시작합니다.
- 상품 피드 영역은 Merchant Center 연결이 끝난 뒤에만 표시합니다. 미연결 상태를 나타내는 빈 영역도 표시하지 않습니다.

#### 4.8.2 연결 상태

Google 계정, Merchant Center, Google Ads는 각각 독립된 연결 상태를 가집니다. 연결 상태는 화면에 진입할 때마다 Google API로 다시 확인하며, 결정 주체는 Google입니다.

| 대상 | 상태(화면 표시) | 의미 | 다음 상태 |
| --- | --- | --- | --- |
| Google 계정 | 미연결(-) | 연결하지 않았거나 연결을 해제한 상태 | [Google 계정으로 시작하기] → 연결중 |
| Google 계정 | 연결중(-) | Google 로그인·권한 동의 진행 중 | 동의 완료 → 연결됨<br>사용자 취소 → 미연결 |
| Google 계정 | 연결됨 | 인증이 정상 유지되는 상태 | 인증 문제 → 재인증 필요<br>연결 해제 → 미연결 |
| Google 계정 | 재인증 필요 | Google 계정 인증이 만료되었거나 확인되지 않는 상태 | [다시 연결하기] → 연결중 |
| Merchant Center | 미연결(-) | 연결하지 않았거나 연결을 해제한 상태 | [Merchant Center 연동하기] → 연결중 |
| Merchant Center | 연결중(-) | 준비사항 확인 또는 연결 마법사 진행 중 | 완료 → 연결됨<br>취소 → 미연결 |
| Merchant Center | 연결됨 | 연결이 정상 완료된 상태 | 인증 문제 → 재인증 필요<br>연결 해제 → 미연결 |
| Merchant Center | 재인증 필요 | Google 계정은 정상이지만 Merchant Center 접근 권한이 없는 상태 | [다시 연결하기] → 연결중 |
| Merchant Center | 계정 정지됨 | Google이 Merchant Center 계정 사용을 정지한 상태. 연결은 유지됩니다. | Google에서 정지 해제 → 연결됨 |
| Google Ads | 미연결(-) | 연결하지 않았거나 연결을 해제한 상태 | [Google Ads 연결하기] → 연결중 |
| Google Ads | 연결중(-) | Google Ads 연결 모달 진행 중 | 완료 → 연결됨 |
| Google Ads | 연결됨 | 접근 권한 오류가 확인되지 않은 상태 | 인증 문제 → 재인증 필요<br>연결 해제 → 미연결 |
| Google Ads | 재인증 필요 | Google Ads 접근 권한 오류 | [다시 연결하기] → 연결중 |

문제 위치 판정

| 문제 위치 | 판정 근거 | 적용 범위 |
| --- | --- | --- |
| Google 계정 | Google Ads API AuthenticationError, Merchant API 401 UNAUTHENTICATED 등 인증 오류 | Google 계정·Merchant Center·Google Ads 모두 재인증 필요 |
| Merchant Center | Merchant API PERMISSION_DENIED_ACCOUNT 등 접근 권한 오류 | Merchant Center만 재인증 필요 |
| Google Ads | Google Ads API AuthorizationError(권한·토큰 문제, 계정 비활성화, 계정 정지 포함) | Google Ads만 재인증 필요 |

- Google Ads AuthorizationError는 원인을 나누지 않고 '재인증 필요' 하나로 표시합니다.
- Merchant Center가 없다는 이유만으로 Google Ads를 미연결이나 오류 상태로 처리하지 않습니다. 이때 Google Ads는 연결됨, 쇼핑 광고는 사용 불가(Merchant Center 연결 필요)로 표시합니다.

#### 4.8.3 Google 계정 연동

| 순서 | 단계 | 처리 주체 | 내용 |
| --- | --- | --- | --- |
| 1 | 개인정보 수집·이용 동의 | 메이크샵 | [Google 계정으로 시작하기] 클릭 시 동의 모달 표시 |
| 2 | Google 로그인 | Google | 기존 Google 계정 선택 또는 신규 로그인 |
| 3 | 접근 권한 확인·동의 | Google | 기본 프로필·이메일 등 필요한 권한 동의 |
| 4 | 연결 완료 | 메이크샵 | 연결관리를 카드형 화면으로 전환 |

- Google이 제공하는 로그인·권한 동의 화면은 메이크샵에서 내용을 바꾸지 않습니다.
- 운영자가 매번 다시 로그인하지 않아도 상품 전송, 연결 상태 확인, 광고 데이터 조회를 할 수 있도록 인증 코드 방식(Authorization Code Model)으로 연결합니다. 발급받은 인증 정보는 안전하게 보관하고, 만료되거나 쓸 수 없게 되면 다시 연결이 필요하다고 안내합니다.
- Google 계정 영역에는 로그인 이메일과 프로필 사진, [전체 연결 해제]를 표시합니다.

#### 4.8.4 Merchant Center 연동

준비사항 확인 → 연결 마법사 → 쇼핑몰 도메인 인증 → 판매국가·배송 설정 순서로 진행합니다. 연결 과정은 연결관리 화면 위 모달과 카드 안에서 진행하며 별도 페이지로 이동하지 않습니다.

준비사항(판매자센터 정보 설정)

| 항목 | 내용 | 확인 방식 |
| --- | --- | --- |
| 커넥트 정보 등록 | Google 로그인 정보로 자동 등록 | 자동 완료 |
| SSL 인증 도메인 사용 | 쇼핑몰이 HTTPS를 사용하고 체크아웃이 유효한 SSL 인증서로 보호되는지 | 운영자 자가 확인 |
| 쇼핑몰 이용약관·환불정책 등록 | 이용약관과 환불정책 게시 여부 | 운영자 자가 확인 |
| 결제 수단 등록 | 쇼핑몰에서 사용할 수 있는 결제 수단 등록 여부(통합 PG만 해당) | 운영자 자가 확인 |

- [Merchant Center 연동하기]를 누르면 4개 항목 완료 여부를 확인해, 미완료 항목이 있으면 준비사항 체크리스트를, 모두 완료했으면 바로 연결 마법사를 엽니다.
- 4개 항목을 모두 완료해야 [Merchant Center 연결하기]가 활성화되고, 미완료 항목이 있으면 비활성화한 채 '체크리스트 완료 후 활성화'를 안내합니다.
- 준비사항은 Merchant Center 연결에만 적용하며 Google Ads 연결에는 영향을 주지 않습니다.

연결 마법사

| 순서 | 단계 | 처리 주체 | 내용 |
| --- | --- | --- | --- |
| 0 | 연결 시작 안내 | 메이크샵 | 연결 순서 안내 |
| 1 | 계정 선택·생성 | Google + 메이크샵 | 로그인한 Google 계정의 기존 Merchant Center 계정을 조회해 선택하거나, 없으면 신규 생성 |
| 2 | 사업자정보 제공 동의 | 메이크샵 | 사업장 주소·대표 전화번호를 Google에 제공하는 데 대한 동의 |
| 3 | 대표 전화번호 인증 | Google + 메이크샵 | 운영자가 [Google에서 인증하기]로 Google 화면에서 직접 인증하고, 메이크샵은 [인증 확인]을 누르면 인증 상태를 조회해 표시. 이미 인증된 계정은 이 단계를 건너뜀 |
| 4 | 서비스 약관 동의 | Google + 메이크샵 | Google 판매자 서비스 약관 동의. 완료 시 Merchant Center 설정 카드로 진행 |

- 메이크샵은 제3자 제공업체로서 판매자의 Merchant Center 계정에 접근합니다(OAuth scope: https://www.googleapis.com/auth/content).
- 신규 계정은 Merchant API accounts.createAndConfigure로 생성하며, 비즈니스 이름은 account.accountName으로 전달합니다. 생성에 실패하면 계정이 생성되지 않은 것으로 처리하고 다음 단계로 진행하지 않습니다.
- Google이 제공하는 계정 선택·서비스 약관 화면은 메이크샵에서 내용을 바꾸지 않습니다.

대표 전화번호 인증 상태

| 상태 | 구분 | 화면 표시 |
| --- | --- | --- |
| 미인증 | Google 인증 상태(UNVERIFIED) | 미인증 + [Google에서 인증하기] + [인증 확인] |
| 인증 완료 | Google 인증 상태(VERIFIED) | 인증 완료 + 마스킹된 전화번호, [다음] 활성화 |
| 확인 중 | 메이크샵 조회 상태 | [인증 확인] 자리에 로딩 표시 |
| 확인 실패 | 메이크샵 조회 오류 | 확인 실패 안내 + [인증 확인] 다시 누름 |

- 인증번호 받기와 입력은 운영자가 Google 화면에서 직접 합니다. 메이크샵은 인증번호를 발송하거나 확인하지 않습니다.
- [Google에서 인증하기]는 Merchant Center 비즈니스 정보(전화번호 인증) 화면을 새 창으로 엽니다.
- [인증 확인]을 누르면 Merchant API accounts.businessInfo.getBusinessInfo의 phoneVerificationState를 조회해 VERIFIED는 인증 완료, UNVERIFIED는 미인증으로 표시합니다. UNSPECIFIED는 미인증과 같이 표시합니다.
- 인증 상태는 [인증 확인]을 누를 때만 조회합니다. 상시 조회하지 않습니다.
- 인증 상태 조회에 실패하면 미인증으로 바꾸지 않고 확인 실패로 처리합니다.
- 전화번호 인증을 마쳐야 다음 단계로 진행할 수 있으며 건너뛸 수 없습니다.

쇼핑몰 도메인 인증

| 순서 | 처리 | 주체 |

| 1 | [도메인 인증하기] 클릭 | 운영자 |
| 2 | 쇼핑몰 대표 도메인 확인 | 메이크샵 |
| 3 | HTTPS 및 도메인 접속 가능 여부 확인 | 메이크샵 |

- 인증 대상은 메이크샵에 설정된 쇼핑몰 대표 도메인이며 운영자가 입력하지 않습니다. Merchant Center 홈페이지 URL이 대표 도메인과 다르면 대표 도메인으로 바꾼 뒤 인증합니다(내부 처리, 별도 단계로 표시하지 않음).
- HTTP 파일 업로드나 DNS 설정은 운영자에게 요구하지 않습니다.
- 처리 중에는 카드 안에 진행 단계를 표시합니다. 오류가 나면 이후 단계를 진행하지 않고 실패한 단계와 안내 문구, [다시 시도]를 표시합니다. 다시 시도할 때는 이미 완료된 단계를 다시 처리하지 않습니다.
- API 요청 성공만으로 인증 완료 처리하지 않고, Homepage.claimed 값을 다시 조회해 Google이 확인한 최종 상태로 처리합니다.

| Merchant Center [계정 변경] | 계정 선택 단계부터 연결 마법사를 다시 진행합니다. 계정이 바뀌면 메이크샵의 Google 상품 피드 정보(상품 상태, 전송 정보)를 초기화하고, 새 계정 기준으로 전송 대상 상품을 반영대기로 바꿔 전송 큐에 등록합니다. |

- 연결 해제 전에는 확인 모달을 표시합니다. 해제 대상과 관계없는 서비스는 그대로 유지합니다.
- Merchant Center 계정 변경·해제와 관계없이 이미 Google에 전달된 상품의 삭제는 Google 정책을 따릅니다.

연결관리 상품 피드 영역

Meta 연결관리의 상품 피드 요약과 같은 구성입니다. Merchant Center가 연결되지 않았으면 영역을 표시하지 않습니다.

| 항목 | 표시 |
| --- | --- |
| 카테고리 설정 | 설정완료: 사용여부 ON인 매칭 대상 카테고리에 모두 Google 카테고리가 저장된 상태<br>미설정: 사용여부 ON인데 Google 카테고리가 저장되지 않은 매칭 대상 카테고리가 하나라도 있는 상태<br>[상품 카테고리 매칭]으로 카테고리 매칭 모달을 엽니다. |
| 연동 상품 | 상품개수(메이크샵 상품 기준 상태별 상품 수의 합)와 최근 업데이트 일시(메이크샵 동기화 로그)를 표시합니다. 아직 전송한 상품이 없으면 최근 업데이트 일시는 '-'입니다. |

### 4.9 Google 상품피드

메이크샵 상품을 Merchant Center로 전송하고, 상품별 상태와 전송 결과를 관리하는 정책입니다. 상품 전송은 Meta 채널과 같이 전송 대상 상품을 반영대기 상태로 전송 큐에 등록해 자동으로 전송하는 방식입니다.

#### 4.9.1 상품 상태

| 상태 | 결정 주체 | 판정 기준 |
| --- | --- | --- |
| 활동중 | Google | Google 심사를 통과해 노출 가능한 상태. DEMOTED·NOT_IMPACTED 같은 경고성 문제가 있어도 활동중을 유지합니다. |
| 검토중 | Google | Merchant API로 전송했지만 destinationStatuses[].pendingCountries가 남아 있어 Google 심사가 끝나지 않은 상태 |
| 미승인 | Google | itemLevelIssues[].severity가 DISAPPROVED이거나 destinationStatuses[].disapprovedCountries가 있는 상태 |
| 노출제한 | 메이크샵 | 전송 전에 메이크샵이 자체 데이터로 판정한 노출제한 사유에 해당해 전송하지 않는 상태 |
| 사용안함 | 메이크샵 | 카테고리 단위 매칭 제외 또는 상품 단위 사용여부 OFF로 운영자가 피드 사용을 중지한 상태 |
| 반영대기 | 메이크샵 | 전송 조건을 충족해 전송 큐에 등록되었고 아직 Merchant API로 전송되기 전인 상태 |

상태 판정 순서

| 순서 | 확인 | 결과 |
| --- | --- | --- |
| 1 | 사용여부 OFF 또는 카테고리 매칭 제외 | 사용안함 |
| 2 | 노출제한 사유 해당 | 노출제한 |
| 3 | 전송할 변경이 있고 아직 전송 전 | 반영대기 |
| 4 | Google 판정: DISAPPROVED 또는 disapprovedCountries 존재 | 미승인 |
| 5 | Google 판정: pendingCountries 존재 또는 전송 후 결과 미수신 | 검토중 |
| 6 | Google 판정: DEMOTED·NOT_IMPACTED만 있거나 문제 없음 | 활동중 |

- 노출제한·사용안함·반영대기는 메이크샵이 판정하는 상태로, 최초 전송 전에도 생길 수 있고 이미 활동중이던 상품이 조건에 해당해 바뀔 수도 있습니다. 예: 전송된 상품을 미진열로 바꾸면 다음 판정에서 노출제한으로 바뀝니다.
- 활동중·검토중·미승인은 Google 심사 결과로 전송 이후에만 생깁니다.
- 반영대기 상품도 Google에 이전에 전송된 이력이 있으면 Google에서는 마지막으로 전송된 정보가 노출 중일 수 있습니다.
- 이미 전송된 상품이 사용안함으로 바뀌면 다음 전송을 기다리지 않고 Merchant API productInputs.delete로 즉시 삭제합니다.
- DEMOTED·NOT_IMPACTED의 경고 배지와 상세 사유는 이번 범위에서 제공하지 않습니다.

#### 4.9.2 노출제한 사유

Merchant API에 전송하기 전에 메이크샵 데이터만으로 판정해 전송을 막는 사유입니다. 불필요한 API 호출과 미승인 누적을 막기 위해 아래 사유에 해당하는 상품은 전송하지 않습니다.

| 표기명 | 판정 조건 | 조치 방법 |
| --- | --- | --- |
| 진열 안 함 | 상품 노출 여부 = 노출안함 | 상품 노출 여부를 노출함으로 변경 |
| 판매 안 함 | 판매 가능 여부 = 판매불가능 | 판매 가능 여부를 판매가능으로 변경 |
| 판매가 0원 | 판매가격 = 0원 | 판매가 입력 |
| 판매가 대체문구 체크 | 가격 대체문구 설정됨 | 가격 대체문구 설정 해제 후 실제 판매가 입력 |
| 상품명에 '개인 결제' 문구 포함 | 상품명에 '개인결제' 포함 | 상품명 수정 |
| 상품 상세이미지 없음 | 상세이미지 미등록 | 이미지 등록 |
| 상품 상세설명 없음 | 상세설명 미등록 | 상세설명 등록 |
| 카테고리 미매칭 | 상품 단위·대표 카테고리 모두 Google 카테고리가 저장되지 않음 | Google 카테고리 매칭 후 [상품 피드 반영] |

- 품절(재고 0)은 노출제한 사유가 아닙니다. availability=out_of_stock으로 전송하고 일반 상품과 같이 검토중 → 활동중·미승인 판정을 거칩니다.

#### 4.9.3 미승인 사유

Merchant API itemLevelIssues[].code를 운영자가 이해하기 쉬운 11개 사유 그룹으로 바꿔 미승인 상품에만 표시합니다.

| 표기명 | 판정 코드(대표 예시) |
| --- | --- |
| 가격 불일치 | price_mismatch, price_mismatch_regional_offer |
| 재고 불일치 | availability_mismatch, availability_mismatch_regional_offer |
| 필수 속성 누락 | item_missing_required_attribute 등 |
| 잘못된 속성값 | invalid_attribute_value, incorrect_color_error, incorrect_size_error, invalid_enum_value, invalid_currency, non_product_data |
| 방문 페이지 오류 | landing_page_error, mobile_landing_page_error, landing_page_roboted, url_does_not_match_homepage |
| 이미지 문제 | image_link_broken, image_link_too_small, image_link_too_big, image_link_unwanted_overlays |
| Google 정책 위반 | 실제 Merchant API 응답 확인 후 코드 추가 |
| 상품 식별자 문제 | invalid_gtin, incorrect_identifier, strong_id_inaccurate, incorrect_mpn_error, reserved_gtin, identifier_exists_false_misuse |
| 카테고리/속성 문제 | google_category_unrecognized, item_has_unsupported_attribute |
| 중복 또는 상품 식별 문제 | item_duplicate_by_gtin, item_duplicate_by_visible_attributes, id_reuse |
| 기타 상품 데이터 문제 | 위 그룹에 매핑되지 않은 코드 |

- 상세 설명과 조치 안내에는 Google이 반환한 description, detail, documentation을 사용합니다.

#### 4.9.4 상품 전송과 동기화

전송 대상 상품은 반영대기 상태로 전송 큐에 등록하고, 큐가 순서대로 Merchant API로 자동 전송합니다. 운영자가 상품을 골라 다시 보내는 단계는 없습니다.

| 발생 상황 | 처리 |
| --- | --- |
| 최초 카테고리 매칭 모달 [상품 피드 반영] | 매칭값을 저장하고, 매칭된 상품 중 전송 조건을 충족한 상품을 반영대기로 바꿔 큐에 등록(최초 동기화) |
| 카테고리 매칭 설정 [상품 피드 반영] | 매칭값을 저장하고, 매칭값이 바뀐 상품 중 전송 조건을 충족한 상품을 큐에 등록 |
| 상품 단위 [상품 피드 반영]([상세]·[선택 수정]) | 상품 단위 값을 저장하고 전송 조건을 충족한 상품을 큐에 등록 |
| 상품 등록·수정(가격·재고·이미지·설명 등) | 변경 시점 정보로 상태를 다시 판정하고, 전송 대상이면 큐에 등록(자동 동기화) |
| 상품 삭제, 사용안함 전환 | 해당 상품을 Merchant API productInputs.delete로 즉시 삭제 |
| [다시 동기화] | 확인 팝업 후 전송 조건을 충족한 전체 상품을 큐에 등록(전체 동기화). 큐에 전송 중인 상품이 있으면 버튼을 비활성화합니다. |
| 정합성 점검(1일 1회) | 메이크샵 상품과 Merchant Center 상품의 차이를 확인해 차이가 있는 상품을 큐에 등록(자동 동기화) |
| Merchant Center 계정 변경 | 피드 정보를 초기화하고 전체 전송 대상을 큐에 등록 |

- 전송 시점의 최신 상품 정보로 전송 조건을 다시 판정합니다. 큐에 같은 상품이 여러 번 등록되면 최신 1건만 전송합니다.
- 전송이 접수되면 검토중으로 바꾸고, Google 판정 결과에 따라 활동중·미승인으로 바꿉니다.
- 전송에 실패한 상품은 반영대기를 유지하고 다음 전송에서 다시 보냅니다. 실패 사유는 동기화 이력에 기록합니다.
- 전송은 상품 식별값 기준으로 있으면 갱신하고 없으면 생성합니다. 피드 전체를 지우고 다시 올리는 방식은 쓰지 않습니다.
- Google 계정 재인증이 필요한 동안에는 큐 전송을 일시 중단하고, 재인증 후 다시 전송합니다.
- 1일 1회 정합성 점검의 실행 시각은 개발팀과 정합니다.

#### 4.9.5 상품 관리 범위

- 메이크샵이 Merchant Center에 전송한 상품만 조회·집계·수정·삭제합니다.
- 운영자가 Merchant Center에서 직접 등록했거나 다른 데이터 소스로 등록한 상품은 상품피드 목록, 상태 집계, 채널 등록 상품 수에 포함하지 않고 수정·삭제하지 않습니다.

#### 4.9.6 최초 카테고리 매칭

Meta 채널과 같은 방식으로, Merchant Center 연결이 끝나면 카테고리 매칭 모달을 한 번 자동으로 열고 운영자가 매칭한 상품부터 전송합니다. Google 자동 분류에 맡겨 바로 전송하는 방식은 두지 않습니다.

| 상황 | 처리 |
| --- | --- |
| Merchant Center 연결 완료 | 카테고리 매칭 모달을 1회 자동으로 엽니다. |
| 모달 [상품 피드 반영] | 매칭값을 저장하고, 매칭된 카테고리의 상품 중 전송 조건을 충족한 상품을 반영대기로 바꿔 전송 큐에 등록합니다(최초 동기화). |
| 모달 [다음에 반영]·닫기(미매칭 카테고리 있음) | 확인 모달("카테고리를 매칭하지 않은 상품은 피드에서 제외되어 Google에 노출되지 않습니다. 다음에 반영하시겠습니까?")을 표시합니다. [확인]을 누르면 입력값을 저장하지 않고 모달을 닫으며, 카테고리가 매칭되지 않은 상품은 노출제한(카테고리 미매칭)으로 표시합니다. [취소]를 누르면 모달을 유지합니다. |
| 이후 매칭 | 연결관리 상품 피드 영역의 [상품 카테고리 매칭] 또는 상품피드 목록의 [상세]·[선택 수정]으로 매칭하고 [상품 피드 반영]을 누릅니다. |

#### 4.9.7 카테고리 매칭

메이크샵 카테고리를 Google 상품 카테고리(GPC)에 연결하는 정책입니다. 메이크샵 카테고리 하나에는 Google 상품 카테고리 하나만 매칭할 수 있습니다.

| 매칭 상태 | 조건 | 선택란 | 상품 처리 |
| --- | --- | --- | --- |
| 매칭 | 사용여부 ON, Google 카테고리를 선택하고 [상품 피드 반영]으로 저장 | 선택한 카테고리 | 전송 대상. 선택한 GPC를 googleProductCategory로 전송 |
| 미매칭 | 사용여부 ON, Google 카테고리가 저장되지 않음 | '카테고리를 선택해주세요' | 노출제한(카테고리 미매칭), 전송하지 않음 |
| 매칭 제외 | 사용여부 OFF | 비활성화 | 사용안함, 전송하지 않음 |

- Google 카테고리를 매칭하지 않은 상품은 Google 자동 분류에 맡겨 전송하지 않고, 노출제한(카테고리 미매칭)으로 처리합니다.
- 매칭은 유효한 Google 카테고리 목록에서만 선택할 수 있습니다. 저장된 매칭값이 더 이상 유효하지 않으면 선택란을 '카테고리를 선택해주세요'로 바꾸고, 해당 상품은 다음 판정에서 노출제한(카테고리 미매칭)으로 바뀝니다.
- Merchant API 전송 중 카테고리 오류가 나면 매칭값은 유지하고, 해당 상품만 전송 실패로 처리해 동기화 이력에 사유를 표시합니다.
- 사용여부를 OFF로 바꾸면 Google 카테고리·성별·연령대 선택란을 비활성화하고, 다시 ON으로 바꾸면 매칭값이 있는 상품은 다음 전송부터 다시 전송합니다.

Meta와 GPC 공통값

Meta 정책과 같이 GPC는 채널별 값이 아니라 Meta·Google 공통값 하나로 관리합니다. Google에 보낼 때는 Google 공식 택소노미로 값을 검증합니다.

| 항목 | 정책 |
| --- | --- |
| 공통 대상 | 카테고리 단위·상품 단위 GPC. 성별·연령대·사용여부는 채널별로 따로 관리합니다. |
| 표시 | 어느 채널 선택란이든 저장된 공통값을 표시합니다. 값이 없으면 '카테고리를 선택해주세요'를 표시합니다. |
| 변경 | 어느 채널에서든 [상품 피드 반영]으로 GPC를 바꾸면 공통값이 바뀌고, 두 채널 모두 해당 상품의 전송 조건을 다시 판정해 전송 대상을 각 채널 전송 큐에 등록합니다. 연동되지 않은 채널은 값만 저장하고 연동 후 적용합니다. |
| 선택 목록 | 메이크샵 DB에 적재한 Google 공식 택소노미(taxonomy-with-ids) 현재 버전의 카테고리만 선택할 수 있습니다. 택소노미 ID는 언어와 관계없이 같습니다. |
| Google 전송 검증 | Google로 보낼 때 GPC ID가 택소노미 현재 버전에 있는지 확인하고, 있으면 googleProductCategory에 GPC ID로 보냅니다. 없으면 Google 쪽은 노출제한(카테고리 미매칭)으로 처리하고 선택란을 '카테고리를 선택해주세요'로 표시합니다. |
| Google 응답 | Merchant API는 메이크샵이 보낸 값만 돌려주며, Google이 자동으로 지정한 카테고리는 조회할 수 없습니다. 목록과 상세에는 저장된 공통값을 표시합니다. Google이 카테고리 관련 이슈를 돌려주면 미승인 사유 '카테고리/속성 문제'로 표시하고 공통값은 유지합니다. |

매칭 단위와 우선순위

| 매칭 단위 | 적용 범위 | 진입 시점 |
| --- | --- | --- |
| 카테고리 단위 | 메인 분류 트리의 최하위 카테고리에 속한 상품 전체 | 최초 설정 시, 연동 후 [상품 카테고리 매칭] |
| 상품 단위 | 선택한 상품 1건 또는 체크한 상품들 | 상품피드 목록 [상세]·[선택 수정] |

- 적용 우선순위는 상품 단위 설정 → 대표 카테고리 설정 순서이며, 둘 다 없으면 미매칭(노출제한)입니다.
- 상품이 여러 카테고리에 속하면 대표 카테고리의 설정값만 적용합니다.
- 상위 카테고리의 매칭값은 하위 카테고리로 자동 이어지지 않습니다.
- 카테고리 단위 화면에는 성별·연령대를 두지 않고, 성별·연령대는 상품 단위 화면에서만 설정합니다.
- [선택 수정]에서는 체크한 상품의 사용여부·성별·연령대를 일괄로 바꿀 수 있습니다. [적용]은 모달 입력값만 바꾸고, [상품 피드 반영]을 눌러야 저장과 전송 큐 등록이 됩니다.
- 상품 단위([상세]·[선택 수정])에서 사용여부 ON인데 Google 상품 카테고리가 없으면 저장하지 않고 얼럿 "상품 피드를 사용하려면 Google 상품 카테고리를 선택해 주세요."를 띄웁니다. 선택한 상품 없이 [선택 수정]을 누르면 얼럿 "선택된 상품이 없습니다."를 띄웁니다(Meta와 같음).
- 저장 완료 얼럿: 카테고리 단위 "선택한 카테고리가 상품 피드에 반영되었습니다.", 상품 단위 "선택한 상품이 상품 피드에 반영되었습니다."(Meta와 같음)

### 4.10 Google 구글애즈

Google Ads 계정의 광고 측정 상태, 캠페인·상품 광고 성과, 운영 상태를 조회하는 정책입니다. 모든 값은 Google Ads API와 Merchant API에서 실제 조회한 값을 사용하며 메이크샵이 임의로 계산하거나 생성하지 않습니다.

#### 4.10.1 계정 정보와 Merchant Center 연결 단계

- Google Ads 연동 완료 후 계정명·고객 ID·연결한 Google 계정·결제통화·시간대를 표시합니다. 연결관리의 Google Ads 계정명과 항상 같은 값입니다.
- Google Ads 연결은 연결관리에서만 진행합니다. 구글애즈 탭의 [Google Ads 연결하기]는 연결관리로 이동한 뒤 연결 모달을 자동으로 엽니다.

| 상태 | 판정 조건 | 제공 기능 |
| --- | --- | --- |
| Google Ads만 연결 | Google Ads 연동 완료, 메이크샵 Merchant Center 연동 기록 없음, Google Ads에서 ENABLED Merchant Center 연결 미감지 | 계정 정보, 광고 성과 요약, 캠페인 현황, 광고 측정, 광고 운영 상태. 쇼핑 캠페인·상품 기반 성과는 '추가 설정 필요' 안내 |
| Merchant Center 연결 감지, 메이크샵 미연동 | 메이크샵 Merchant Center 연동 기록 없음, Google Ads에서 ENABLED Merchant Center 연결 감지 | Google Ads만 연결 기능 + 이미 연결된 Merchant Center 안내 + [이 Merchant Center를 메이크샵에 연결] |
| Merchant Center 연동 완료 | 메이크샵 Merchant Center 연동 완료, Google Ads와 Merchant Center 간 연결 승인 완료 | 위 기능 + 상품 기준 탭 |

- Merchant Center 연결 감지는 Google Ads API MerchantCenterLink 상태가 ENABLED인 경우만 해당합니다. PENDING은 별도 상태로 안내하지 않고 'Google Ads만 연결'로 처리합니다.
- [이 Merchant Center를 메이크샵에 연결]을 누르면 감지된 계정을 대상으로 연동합니다. 계정 선택 단계는 생략하고 사업자정보 제공 동의 → 전화번호 인증 → 서비스 약관 동의 순서로 진행합니다.

| 장바구니 추가 전환 상태 | ADD_TO_CART 전환 액션 존재 + 활성 | 없음 또는 비활성 |
| 결제 시작 전환 상태 | BEGIN_CHECKOUT 전환 액션 존재 + 활성 | 없음 또는 비활성 |
| 향상된 전환 상태 | 메이크샵이 웹용 향상된 전환 설정을 완료함 | 설정이 완료되지 않음 |

- '정상'은 설정 상태가 정상이라는 뜻이며, 전환 데이터가 계속 수집되고 있음을 보장하지 않습니다.
- Google Tag 상태는 ConversionAction.tag_snippets가 실행 상태를 나타내지 않으므로 메이크샵의 Google Tag 설정 완료 결과로 판정합니다.
- 향상된 전환 상태는 enhanced_conversions_for_leads_enabled를 사용하지 않고 메이크샵의 설정 완료 결과로 판정합니다.
- 최근 수집 일시는 구매·장바구니 추가·결제 시작 전환 액션 중 가장 최근에 전환 태그 요청을 받은 일시(metrics.conversion_last_received_request_date_time)를 표시하고, 이력이 없으면 '-'로 표시합니다. 측정 상태 판정에는 쓰지 않습니다.

- Performance Max는 advertising_channel_type = PERFORMANCE_MAX, Shopping 캠페인은 SHOPPING으로 구분합니다. 상품 기반 PMax는 PERFORMANCE_MAX이면서 shopping_setting.merchant_id가 있는 캠페인입니다.

상품 기준

- 집계 대상은 Shopping 캠페인과 Merchant Center 상품 데이터를 쓰는 Performance Max 캠페인이며, 특정 상품과 연결되지 않은 일반 캠페인은 제외합니다.
- 상품 광고 성과 요약은 노출수·클릭수·CTR·광고비·전환수·전환율·전환가치·ROAS를 표시하고, 증감 표시는 광고 기준과 같습니다.
- 상품 광고 현황은 조회 기간 안에 노출·클릭·전환 등 성과가 있는 상품을 상품 1행으로 표시합니다. 상품정보(이미지·상품명·상품번호·분류)·캠페인명·노출수·클릭수·CTR·전환수·광고비·전환가치·ROAS를 기본으로 표시합니다.
- 상품 성과는 shopping_performance_view의 segments.product_item_id로 메이크샵 상품과 매칭하고, 상품정보는 현재 메이크샵 상품 정보로 표시합니다. 매칭되는 메이크샵 상품이 없으면 행을 빼지 않고 '삭제된 상품'으로 표시합니다.
- 정렬은 전환가치 높은순(기본) / 광고비 높은순 / 전환수 높은순 / 클릭수 높은순 / 노출수 높은순입니다. 정렬은 조회 대상 전체에 적용하고, 정렬을 바꾸면 조회 기간과 검색 조건을 유지한 채 첫 페이지부터 다시 조회합니다. 정렬값이 같으면 상품 ID 순서로 표시합니다.

| 구분 | API 상태 | 표시 | 안내 문구 |
| --- | --- | --- | --- |
| 계정 문제 | CRITICAL | 조치 필요 | Merchant Center 계정에 조치가 필요한 문제가 있습니다. |
| 계정 문제 | ERROR | 주의 | Merchant Center 계정에 확인이 필요한 문제가 있습니다. |
| 계정 문제 | SUGGESTION | 주의 | Merchant Center 계정에 개선이 필요한 항목이 있습니다. |
| 상품 문제 | DISAPPROVED | 조치 필요 | 상품 피드를 사용하는 광고에 확인이 필요한 상품이 있습니다. |
| 상품 문제 | DEMOTED | 주의 | 일부 상품의 광고 노출에 영향을 주는 문제가 있습니다. |

- 계정 문제는 Merchant API 계정 Issue를 기준으로, 여러 문제가 있으면 CRITICAL → ERROR → SUGGESTION 순서로 가장 높은 심각도 하나의 알림으로 표시합니다.
- 상품 문제는 Merchant Reports API product_view.itemIssues(reportingContext = SHOPPING_ADS)의 severity.aggregatedSeverity를 기준으로 하나의 알림으로 표시합니다. DISAPPROVED와 DEMOTED가 함께 있으면 DISAPPROVED를 우선하고, PENDING은 포함하지 않습니다.
- 개별 상품명, 문제 코드, 미승인 사유는 이 영역에 표시하지 않고 상품피드에서 확인합니다.
- API를 다시 조회해 문제가 모두 해소되면 알림을 없애고, 표시할 문제가 없으면 빈 상태 안내를 표시합니다. API 데이터를 조합해 새로운 문제를 만들지 않습니다.
- 일부 API 조회에 실패해도 모달 전체를 오류로 처리하지 않고, 정상 조회된 영역은 그대로 표시합니다.

### 4.11 처리 흐름

1. 배포 시 기존 Meta·구글 상품 피드 메뉴를 삭제하고, 메뉴 권한을 마케팅 채널 관리 메뉴로 옮깁니다.
2. 운영자가 마케팅 > 마케팅 채널 관리에 진입하면 통합 현황을 표시하고, 메이크샵에 저장된 채널별 연결 상태와 채널 등록 상품 수를 보여줍니다.
3. 운영자가 Google 카드의 [연동하기]를 누르면 Google 연결관리로 이동하고, Google 계정 연동(동의 → 로그인 → 권한 동의)을 진행합니다.
4. Google 계정 연동 후 Merchant Center 연동(준비사항 → 연결 마법사 → 도메인 인증 → 판매국가·배송 설정)과 Google Ads 연동(동의 → 권한 → 계정 선택 → 10개 항목 확인 → 완료)을 각각 진행합니다.
5. Merchant Center 연결이 완료되면 카테고리 매칭 모달을 1회 자동으로 엽니다. Meta에서 이미 저장한 GPC(공통값)는 선택된 상태로 보여주고, 운영자가 [상품 피드 반영]을 누르면 매칭된 상품을 반영대기로 바꿔 전송 큐에 등록합니다. 매칭하지 않은 상품은 노출제한(카테고리 미매칭)입니다.
6. 전송 큐가 상품을 Merchant API로 전송하면 검토중으로 바꾸고, Google 판정에 따라 활동중·미승인으로 바꿉니다.
7. 이후 상품 등록·수정, 매칭 변경, 1일 1회 정합성 점검으로 변경된 상품을 다시 큐에 등록해 자동 전송합니다.
8. 통합 상품 피드에서는 상품별 Meta·Google 상태를 비교하고, [관리 ↗]로 해당 채널 상품피드로 이동해 조치합니다.

| GPC가 Google 택소노미 현재 버전에 없음 | Google 쪽 노출제한(카테고리 미매칭), 선택란 '카테고리를 선택해주세요' |
| 상품 품절 | 노출제한으로 처리하지 않고 out_of_stock으로 전송 |
| 전송된 상품 삭제 또는 사용안함 전환 | productInputs.delete로 즉시 삭제 |
| Google Ads 상품 성과의 상품이 메이크샵에 없음 | 행을 유지하고 '삭제된 상품'으로 표시 |
| 최적화 점수 미제공 | '-' 표시 |
| 메뉴 권한 없음 | LNB 메뉴 비활성화(클릭 불가), URL 직접 접근은 메이크샵 관리자 공통 권한 처리 |
| 삭제한 기존 메뉴 URL 접근 | 마케팅 채널 관리의 대응 화면으로 이동, 대응 화면이 없으면 해당 채널 홈 |

## 5. 고객 영향 및 안내

| 대상 | 영향 |
| --- | --- |
| 쇼핑몰 운영자 | 광고 채널 연동 기능을 마케팅 > 마케팅 채널 관리에서 이용합니다. 통합 현황과 통합 상품 피드로 채널 현황을 한 화면에서 확인할 수 있습니다. |
| Google 채널 이용 운영자 | Google 화면이 Meta와 같은 구성(홈 포함)으로 바뀌고, 상품 상태에 반영대기가 추가됩니다. Meta와 같이 카테고리를 매칭해야 상품이 전송되며, GPC는 Meta와 공통값이라 Meta에서 저장한 카테고리가 그대로 적용됩니다. 상품 등록·수정 내용은 전송 큐를 거쳐 자동으로 반영됩니다. |
| Meta 채널 이용 운영자 | 진입 경로가 바뀌며 기능과 연동 정보는 그대로 유지됩니다. |
| 쇼핑몰 구매 고객 | 변화 없음 |

- 배포 전 공지로 마케팅 채널 관리 메뉴 위치, 기존 Meta·구글 상품 피드 메뉴 삭제, Google 상품 상태 변경(반영대기 추가)을 안내합니다.
- TikTok 탭은 준비 중으로만 안내하며 연동 일정은 안내하지 않습니다.
