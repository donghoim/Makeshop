# 상품 품목 고유 식별자(품목코드) 정책

## 1. 문서 정보

상품과 품목(판매·재고 관리 단위)에 시스템이 발급하는 불변 고유 식별자를 추가할 때 적용하는 정책서입니다. 식별자의 발급·유지·종료 기준, 변경 경로별 처리, 기존 상품 적용 기준을 정의합니다.

| 항목 | 내용 |
| --- | --- |
| 문서 유형 | 기능 개선 |
| 대상 서비스 | 상품 등록·수정·복사·삭제, 상품 엑셀 업로드·다운로드, Open API 상품·옵션 변경 |
| 작성일 | 2026-10-19 |
| 근거 자료 | 사내 요구사항·현행 분석·방향성 문서(원문은 사내 문서라 공개하지 않습니다) |
| 문서 상태 | 정책 확정, 기획 리뷰 전 |

## 2. 변경 사항 요약

### 2.1 한 줄 요약

상품과 품목에 시스템이 발급하는 불변 고유 식별자를 추가해, 옵션을 수정·삭제·재조합한 뒤에도 같은 품목을 계속 식별하고 삭제된 품목의 식별값이 다른 품목에 다시 쓰이지 않게 합니다.

### 2.2 변경 목적

- 현행 재고 행 번호는 상품 안에서만 유일하고, 옵션을 재조합하면 다시 채번되거나 삭제된 번호가 재사용될 수 있어 품목을 장기간 식별할 수 없습니다.
- 품목 단위로 바뀌지 않는 식별자를 두어 재고·외부 연동·후속 기능(통합 엑셀, 재입고 알림)이 같은 품목을 일관되게 가리키게 합니다.
- 기존 식별값(상품번호, 옵션 항목 번호, 재고 행 번호, 관리코드)과 이를 쓰는 기능은 그대로 둡니다.

### 2.3 변경 전·후

| 구분 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 품목 식별값 | 재고 행 번호(상품별 순번). 재조합 시 재채번, 최대 번호 삭제 시 재사용 가능 | 품목 고유 식별자. 발급 후 바뀌지 않고, 종료된 값은 다시 쓰지 않음 |
| 옵션값 이름 변경 | 옵션값 문자열이 바뀌면 다른 조합으로 보고 재고 행 번호를 새로 생성 | 관리자 화면에서 변경하면 식별자 유지, 상품 엑셀 업로드로 변경하면 새로 발급 |
| 옵션값 추가·삭제 | 남은 조합도 저장 과정에서 재생성될 수 있음 | 남은 품목은 유지, 추가된 품목만 새로 발급, 삭제된 품목만 종료 |
| 옵션 없는·노조합 옵션 상품 | 품목 식별값 없음 | 기본 품목 1개에 식별자 발급 |
| 식별자 형식 | 없음 | 품목코드 `{상품번호}-{순번}`(예: `123456789-0001`). 순번은 최소 4자리, 상품 안에서 발급 순서대로 매기고 다시 쓰지 않음 |
| 상품 복사 | 상품 번호는 새로 발급, 재고 행 번호 숫자는 그대로 복사될 수 있음 | 상품·품목 식별자 모두 새로 발급 |
| 관리자 화면·엑셀 다운로드 | 품목 식별값 표시 없음 | 품목·상품 식별자를 읽기 전용으로 제공 |
| 기존 식별값 | 상품번호, 옵션 항목 번호, 재고 행 번호, 관리코드 | 변경 없음(현행 유지) |

## 3. 적용 대상 및 범위

### 적용 대상

- 메이크샵 프리미엄·코어(같은 상품 데이터를 사용합니다)
- 조합옵션 상품, 노조합 옵션 상품, 옵션 없는 상품
- 관리자 상품 등록·수정 화면, 상품 엑셀 업로드·다운로드, Open API 상품·옵션 변경, 상품 복사·삭제
- 적용 시점에 이미 등록돼 있는 기존 상품

### 포함 범위

- 상품·품목 고유 식별자의 정의와 발급·유지·종료 기준
- 변경 경로·변경 유형별 품목 식별자 처리
- 기존 상품·품목에 대한 최초 식별자 부여와 기존 식별값 연결 기준
- 관리자 화면·상품 엑셀 다운로드의 식별자 읽기 전용 제공

### 제외 및 예외 범위

- 기존 상품번호, 옵션 항목 번호, 재고 행 번호, 관리코드의 생성·변경 방식 변경
- 상품 엑셀 업로드의 기존 처리 방식(상품 단위 전체 필드 갱신 등) 변경
- 오래된 엑셀 파일 감지, 동시 수정 충돌 감지
- 엑셀·Open API에서 식별자를 수정 대상 지정용으로 받는 기능, Open API 식별자 조회
- 옵션 순서 변경, 조합 개수 상한, 옵션 엑셀 업·다운로드 개선 등 옵션 기능 자체의 개선
- 상품·옵션 DB 전체 정규화, 기존 주문 데이터 구조 변경
- 옵션 항목(색상·사이즈 등)과 옵션값(블랙·S 등) 단위의 식별자 발급. 판매·재고 단위가 아니므로 품목에만 발급합니다.
- 식별자 저장 구조, 채번 구현 방식(번호 관리·동시 발급 처리), 이력 저장 방식, 마이그레이션 방식(개발 설계 범위). 식별자 형식과 채번 규칙은 4.5에서 정합니다.

### 이용 조건

- 식별자는 시스템만 발급·종료합니다. 운영자와 내부 관리자는 식별자를 입력·수정·삭제할 수 없습니다.
- 관리자 화면·엑셀 다운로드의 식별자 조회 권한은 현행 상품 관리 메뉴 권한과 같습니다.

## 4. 상세 정책

### 4.1 용어 정의

이 정책서에서 쓰는 용어입니다.

| 용어 | 정의 |
| --- | --- |
| 품목 | 독립적으로 판매되거나 재고가 관리되는 최소 단위입니다. 조합옵션 상품은 조합 1개가 품목 1개입니다. |
| 기본 품목 | 옵션 없는 상품과 노조합 옵션 상품이 갖는 품목 1개입니다. 모든 상품은 품목을 1개 이상 가집니다. |
| 상품 고유 식별자 | 상품 1개에 발급하는 불변 값입니다. |
| 품목 고유 식별자 | 품목 1개에 1개만 발급하는 불변 값입니다. |
| 활성 품목 / 종료 품목 | 현재 상품에 있는 품목 / 삭제·구조 변경 등으로 더 이상 상품에 없는 품목입니다. 종료 품목의 식별자는 보존하고 다시 쓰지 않습니다. |
| 구조 변경 | 옵션 항목의 추가·삭제·교체, 옵션 사용↔미사용 전환, 조합옵션↔노조합 옵션 전환처럼 품목을 구성하는 방식이 바뀌는 변경입니다. |
| 대상 지정 경로 | 운영자가 어떤 옵션 항목·옵션값을 고치는지 시스템이 특정할 수 있는 경로입니다. 관리자 상품 등록·수정 화면, 수정 대상을 특정하는 정보를 담은 Open API 요청입니다. |
| 이름 대응 경로 | 옵션 항목·옵션값을 이름으로만 받는 경로입니다. 상품 엑셀 업로드, 이름만 담은 Open API 요청입니다. |

기존 식별값과 신규 식별자의 역할은 아래와 같이 나눕니다.

| 값 | 역할 | 변경 |
| --- | --- | --- |
| 상품번호, 옵션 항목 번호, 재고 행 번호 | 기존 DB 내부 식별·데이터 연결 | 현행 유지 |
| 상품·품목 고유 식별자 | 상품·품목의 시스템 표준 식별 | 발급 후 변경하지 않음 |
| 관리코드 | 운영자 관리코드·외부 SKU | 현행 유지(운영자 수정 가능) |

### 4.2 식별자 공통 규칙

상품·품목 고유 식별자에 공통으로 적용하는 규칙입니다.

| 규칙 | 내용 |
| --- | --- |
| 불변 | 발급 후 값을 바꾸지 않습니다. 품목이 바뀌어야 하면 기존 값을 고치지 않고 기존 품목을 종료한 뒤 새 품목에 새 값을 발급합니다. |
| 유일 | 상점 안에서 서로 다른 상품·품목에 같은 값을 발급하지 않습니다. 상점 밖(통합 연계·외부 시스템)에서는 상점과 식별자를 함께 써서 가리킵니다. |
| 재사용 금지 | 종료된 상품·품목의 값은 영구히 다른 상품·품목에 발급하지 않습니다. |
| 보존 | 종료된 상품·품목의 식별자는 삭제하지 않고 종료 상태로 보존합니다. |
| 내부 값과 독립 | 상품번호, 옵션 항목 번호, 재고 행 번호, 관리코드의 값이 바뀌거나 DB 재고 행이 다시 만들어졌다는 이유만으로 식별자를 발급·종료하지 않습니다. 유지·종료·신규 발급은 변경 경로별 품목 대응 결과로만 정합니다. |

### 4.3 상품 고유 식별자

상품 단위 식별자의 발급·유지·종료 기준입니다.

| 상황 | 처리 |
| --- | --- |
| 상품 신규 등록(화면·엑셀·Open API) | 상품 고유 식별자를 발급합니다. |
| 상품명·가격·분류·진열 등 상품 정보 수정 | 유지합니다. 분류 변경으로 상품코드가 다시 채번돼도 유지합니다. |
| 옵션 구성 변경(구조 변경 포함) | 유지합니다. 품목 식별자만 품목 대응 결과에 따라 처리합니다. |
| 상품 복사 | 복사한 상품에 새 상품 고유 식별자를 발급합니다. |
| 상품 삭제(복구할 수 있는 상태) | 유지합니다. 그 상품의 품목 식별자도 그대로 유지하며, 관리자 화면에는 상품과 함께 표시되지 않습니다. |
| 삭제한 상품 복구 | 같은 상품 고유 식별자로 복구합니다. 품목은 삭제 전 품목 식별자를 그대로 다시 씁니다. |
| 상품 완전 삭제 | 상품 고유 식별자를 종료 상태로 보존하고, 그 상품의 활성 품목도 모두 종료합니다. |

- 상품 고유 식별자는 기존 상품번호를 그대로 씁니다. 상품번호는 상점 안에서 유일하고 발급 후 바뀌지 않습니다. 삭제한 상품을 복구하면 같은 번호로 돌아오며, 다른 상품이 그 번호를 다시 쓰지 않습니다. 완전 삭제한 상품의 번호도 다시 쓰지 않습니다.

### 4.4 품목 단위와 발급 대상

품목 식별자를 발급하는 단위를 상품 옵션 유형별로 정의합니다.

| 상품 옵션 유형 | 품목 단위 | 연결 대상 |
| --- | --- | --- |
| 조합옵션 상품 | 조합 1개 = 품목 1개 | 해당 조합의 재고 데이터(상점 + 상품번호 + 재고 행 번호) |
| 노조합 옵션 상품 | 기본 품목 1개 | 상품 단위로 만들어진 재고 행 1개(상점 + 상품번호 + 재고 행 번호) |
| 옵션 없는 상품 | 기본 품목 1개 | 상품 단위로 만들어진 재고 행 1개(상점 + 상품번호 + 재고 행 번호) |

- 품목을 새로 만드는 시점(상품 신규 등록, 옵션값 추가, 구조 변경 등)에 저장이 완료되면 발급합니다.
- 옵션 항목과 옵션값에는 식별자를 발급하지 않습니다. 품목 식별자에 그 품목의 "옵션 항목명 = 옵션값" 정보가 함께 연결되므로, 특정 옵션값의 품목은 이 정보로 찾습니다.

### 4.5 품목 식별자 형식과 채번

운영자에게 "품목코드"로 표시되는 품목 식별자의 형식과 번호를 매기는 기준입니다. 상품번호 뒤에 상품 안의 발급 순번을 붙여, 코드만 보고도 어느 상품의 품목인지 알 수 있게 합니다.

| 항목 | 규칙 |
| --- | --- |
| 형식 | `{상품번호}-{순번}`입니다. 예: `123456789-0001` |
| 상품번호 | 상품 고유 식별자(상품번호)를 그대로 씁니다. 앞에 영문 접두어를 붙이지 않습니다. |
| 순번 자릿수 | 최소 4자리입니다. 앞을 0으로 채워 `0001`부터 `9999`까지 쓰고, `9999` 다음은 `10000`처럼 자릿수가 늘어납니다. |
| 첫 번호 | 상품에서 처음 발급하는 품목의 순번은 `0001`입니다. |
| 다음 번호 | 그 상품에서 지금까지 발급한 가장 큰 순번 + 1입니다. 종료된 품목의 순번도 포함해 계산하므로, 종료된 번호는 다시 나오지 않습니다. |
| 한 번에 여러 품목 발급 | 한 번의 저장으로 품목이 여러 개 생기면 저장 후 옵션 표시 순서(옵션 항목 순서, 그 안의 옵션값 순서)대로 순번을 매깁니다. |
| 표시 순서와의 관계 | 순번은 발급 순서이며 현재 표시 순서나 활성 품목 수를 뜻하지 않습니다. 옵션 순서를 바꿔도 품목코드는 바뀌지 않습니다. |
| 기본 품목 | 같은 규칙을 적용합니다. 상품의 첫 품목이면 `0001`이고, 구조 변경으로 기본 품목을 다시 만들면 다음 순번을 씁니다. 기본 품목이 항상 `0001`인 것은 아닙니다. |
| 상품 복사 | 복사한 상품은 새 상품번호를 받고 순번도 `0001`부터 시작합니다. 원본 상품의 품목코드는 그대로입니다. |
| 기존 상품 최초 부여 | 현재 있는 조합에 재고 행 번호 오름차순으로 `0001`부터 순번을 매깁니다. 재고 행 번호 값 자체는 품목코드에 넣지 않습니다. 최초 부여 때만 적용하며, 이후 재고 행이 다시 만들어지거나 부여 작업을 다시 실행해도 순번을 다시 매기지 않습니다. |

예시: 상품번호 `123456789`, 색상(블랙) × 사이즈(S, M, L)

| 순서 | 변경 | 결과 |
| --- | --- | --- |
| 1 | 처음 등록 | `123456789-0001` 블랙/S, `-0002` 블랙/M, `-0003` 블랙/L |
| 2 | 색상에 화이트 추가 | `-0004` 화이트/S, `-0005` 화이트/M, `-0006` 화이트/L 신규 발급. 기존 3개 유지 |
| 3 | 블랙/L 삭제 | `-0003` 종료 |
| 4 | 이후 저장에서 블랙/L 다시 추가 | `-0007` 블랙/L 신규 발급. `-0003`은 복원하지 않습니다. |
| 5 | 관리자 화면에서 블랙 → 다크블랙 이름 변경 | `-0001`, `-0002`, `-0007` 유지 |
| 6 | 옵션 항목 "소재" 추가(구조 변경) | 활성 품목 모두 종료. 변경 후 조합마다 `-0008`부터 신규 발급 |

| 상품 유형 | 예시 |
| --- | --- |
| 옵션 없는 상품(상품번호 `223456789`) 등록 | `223456789-0001` |
| 위 상품에 색상(블랙, 화이트) 추가 | `-0001` 종료. `-0002` 블랙, `-0003` 화이트 신규 발급 |
| 위 상품의 옵션을 모두 삭제 | `-0002`, `-0003` 종료. 기본 품목 `-0004` 신규 발급 |

### 4.6 변경 유형별 품목 식별자 처리

운영자가 상품·옵션을 바꿨을 때 각 품목의 식별자를 유지·종료·신규 발급하는 기준입니다. 대응되는 변경 전 품목이 있으면 유지하고, 사라진 품목은 종료하며, 새로 생긴 품목에는 신규 발급합니다.

예시 상품: 색상(블랙, 화이트) × 사이즈(S, M) → 품목 4개(블랙/S, 블랙/M, 화이트/S, 화이트/M)

**속성·이름 변경** — 품목의 판매·재고 단위가 바뀌지 않는 변경입니다. 옵션 항목명·옵션값 이름 변경만 경로에 따라 결과가 다릅니다.

| 변경 | 관리자 화면 등 대상 지정 경로 | 상품 엑셀 업로드 등 이름 대응 경로 |
| --- | --- | --- |
| 상품 정보, 품목 판매가·옵션 추가금액·재고·품절·노출 상태, 관리코드 수정 | 모든 품목 유지 | 모든 품목 유지 |
| 옵션 항목 순서·옵션값 순서 변경 | 모든 품목 유지 | 모든 품목 유지 |
| 옵션 항목명 변경(사이즈 → SIZE) | 모든 품목 유지 | 구조 변경. 기존 품목 모두 종료, 모든 품목 신규 발급 |
| 옵션값 이름 변경(블랙 → 다크블랙) | 모든 품목 유지(블랙/S·블랙/M이 이름만 바뀌고 같은 식별자 유지) | 블랙/S·블랙/M 종료, 다크블랙/S·다크블랙/M 신규 발급, 화이트 품목 유지 |

**옵션값 추가·삭제** — 옵션 항목 구성은 그대로이고 옵션값만 늘거나 줄어드는 변경입니다. 두 경로의 결과가 같습니다.

| 변경 | 처리 결과 |
| --- | --- |
| 옵션값 추가(사이즈에 L 추가) | 기존 4개 유지. 블랙/L·화이트/L 신규 발급 |
| 옵션값 삭제(사이즈 M 삭제) | 블랙/M·화이트/M 종료. 블랙/S·화이트/S 유지 |
| 개별 조합 삭제(화이트/M만 삭제) | 화이트/M 종료. 나머지 3개 유지 |
| 삭제를 저장한 뒤 이후 저장에서 같은 이름으로 다시 추가 | 이전 품목을 복원하지 않고 신규 발급합니다. |
| 한 번의 저장 안에서 지웠다가 같은 값을 다시 넣음 | 저장 결과만 봅니다. 저장 전후에 같은 품목이 남아 있으면 유지합니다. |

**구조 변경** — 품목을 구성하는 방식이 바뀌는 변경입니다. 기존 활성 품목을 모두 종료하고 변경 후의 품목마다 신규 발급합니다.

| 변경 | 처리 결과 |
| --- | --- |
| 옵션 항목 추가(소재 항목 추가) | 기존 4개 종료. 변경 후 조합마다 신규 발급 |
| 옵션 항목 삭제(사이즈 항목 삭제) | 기존 4개 종료. 블랙·화이트 신규 발급 |
| 옵션 항목 교체(같은 저장에서 항목 삭제와 추가) | 기존 4개 종료. 변경 후 조합마다 신규 발급 |
| 옵션 없는 상품에 옵션 추가 | 기본 품목 종료. 조합마다 신규 발급 |
| 옵션 상품의 옵션을 모두 삭제 | 기존 품목 모두 종료. 기본 품목 신규 발급 |
| 옵션 없음 → 옵션 사용 → 옵션 없음 | 전환할 때마다 종료·신규 발급. 처음 기본 품목의 식별자를 복원하지 않습니다. |
| 조합옵션 → 노조합 옵션 | 기존 조합 품목 모두 종료. 기본 품목 1개 신규 발급 |
| 노조합 옵션 → 조합옵션 | 기본 품목 종료. 조합마다 신규 발급 |

**상품 단위 변경**

| 변경 | 처리 결과 |
| --- | --- |
| 상품 복사 | 복사한 상품의 모든 품목에 신규 발급. 원본 상품의 품목은 유지 |
| 상품 삭제(복구할 수 있는 상태) | 상품·품목 식별자 유지 |
| 삭제한 상품 복구 | 삭제 전 상품·품목 식별자를 그대로 사용 |
| 상품 완전 삭제 | 상품과 모든 활성 품목 종료 |

### 4.7 한 번의 저장에 여러 변경이 있을 때

여러 변경을 한 번에 저장한 경우의 판정 순서입니다. 먼저 변경 경로의 대응 기준으로 변경 전후 품목을 대응한 뒤 아래 순서를 위에서부터 적용하며, 앞 단계에서 결과가 정해진 품목은 뒤 단계를 적용하지 않습니다.

| 순서 | 판정 | 결과 |
| --- | --- | --- |
| 1 | 구조 변경이 하나라도 있는가(조합↔노조합 전환, 이름 대응 경로의 옵션 항목명 변경 포함) | 기존 활성 품목 모두 종료, 저장 후 품목 모두 신규 발급 |
| 2 | 대응되는 변경 후 품목이 없는 변경 전 품목인가(옵션값·조합 삭제, 이름 대응 경로의 옵션값 이름 변경) | 해당 품목 종료 |
| 3 | 대응되는 변경 전 품목이 없는 변경 후 품목인가(옵션값 추가, 저장 완료 후 재추가, 이름 대응 경로의 바뀐 이름) | 신규 발급 |
| 4 | 나머지 품목 | 유지 |

예시: 블랙 → 다크블랙 이름 변경, 사이즈 L 추가, 옵션값 순서 변경을 한 번에 저장(구조 변경 없음)

| 저장 후 품목 | 관리자 화면 등 대상 지정 경로 | 상품 엑셀 업로드 등 이름 대응 경로 |
| --- | --- | --- |
| 다크블랙/S, 다크블랙/M | 유지(기존 블랙/S·블랙/M 식별자) | 신규 발급 |
| 화이트/S, 화이트/M | 유지 | 유지 |
| 다크블랙/L, 화이트/L | 신규 발급 | 신규 발급 |
| 기존 블랙/S, 블랙/M | 이름만 바뀌어 존속 | 종료 |

### 4.8 변경 경로별 품목 대응 기준

변경 전 품목과 변경 후 품목을 같은 품목으로 볼지 정하는 기준입니다. 어느 경로에서도 표시 순서·행 위치·문자열 유사성으로 품목을 대응하지 않으며, 대응 판정을 이유로 저장을 보류하지 않습니다.

**관리자 화면 등 대상 지정 경로**

| 운영자 동작 | 처리 결과 |
| --- | --- |
| 기존 옵션값·옵션 항목명의 이름을 고쳐 저장 | 이름 변경으로 보고 해당 품목 유지 |
| 두 옵션값의 이름을 서로 바꿈(블랙 ↔ 화이트) | 각 옵션값의 품목이 자기 식별자를 유지하고 이름만 바뀝니다. |
| 기존 옵션값을 지우고 새 옵션값을 넣어 저장 | 삭제 후 추가로 보고 지운 값의 품목 종료, 새 값의 품목 신규 발급 |
| 옵션 항목을 추가·삭제·교체해 저장 | 구조 변경. 기존 품목 모두 종료, 변경 후 품목 모두 신규 발급 |

- 관리자 화면에서는 옵션값 단위로 수정 대상을 특정할 수 있어야 하며, 이름 맞교환을 삭제 후 추가로만 처리하는 구현이 되지 않아야 합니다.

**상품 엑셀 업로드 등 이름 대응 경로 — 처리 범위**

| 항목 | 기준 |
| --- | --- |
| 비교 대상 상품 | 업로드 파일(또는 요청)에 포함된 상품만 비교합니다. 파일에 없는 상품은 바뀌지 않습니다. |
| 비교 기준 상태 | 업로드를 처리하는 시점에 저장돼 있는 최신 상태와 비교합니다. 이전에 내려받은 파일을 다시 올리면 그 내용으로 덮어쓰고, 그 결과에 이름 대응 기준을 적용합니다. |
| 수정 범위 | 상품 엑셀은 상품 1행에 옵션 항목·옵션값을 모두 담고 전체 필드 값으로 상품을 다시 갱신하는 방식(현행)이므로, 파일에 포함된 상품은 옵션 구성 전체를 파일 내용으로 교체합니다. 파일 내용에 없는 기존 조합은 종료합니다. |
| 부분 수정 경로 | 일부 조합만 골라 수정하는 업로드·API 경로가 있다면 그 경로에 포함되지 않은 조합은 유지합니다. |

**이름 대응 경로 — 대응 기준과 이름 비교**

| 항목 | 기준 |
| --- | --- |
| 옵션 항목 대응 | 항목명으로 대응합니다. 옵션 항목 수가 바뀌거나 변경 전 항목명 중 하나라도 변경 후에 없으면 구조 변경입니다. |
| 품목 대응 | "옵션 항목명 = 옵션값" 쌍의 묶음으로 비교하고 순서는 보지 않습니다. 같은 묶음은 유지, 새 묶음은 신규 발급, 빠진 묶음은 종료합니다. |
| 파일 편집 과정 | 파일 안에서 지웠다가 다시 쓴 과정은 식별하지 않고 업로드한 최종 내용만 비교합니다. |
| 화면과의 차이 | 이름 맞교환을 엑셀로 올리면 이름별로 기존 식별자를 유지합니다(블랙이라는 이름의 품목은 기존 블랙 품목의 식별자를 가집니다). 화면의 맞교환 결과와 다르며, 경로에 따른 의도된 차이입니다. |
| 공백 | 상품 엑셀 업로드가 콤마 구분 옵션값을 해석·저장하는 기존 방식(앞뒤 공백 처리 포함)을 적용한 뒤 비교합니다. 옵션 항목명도 같습니다. |
| 일치 기준 | 해석 후 저장될 문자열이 정확히 같으면 같은 이름입니다. 대소문자만 다른 이름(Black, black)은 다른 이름입니다. |

**Open API** — 요청에 수정 대상 옵션 항목·옵션값을 특정하는 정보가 있으면 대상 지정 경로 기준을, 이름만 있으면 이름 대응 경로 기준을 적용합니다.

### 4.9 처리 흐름

저장 1회에 대한 식별자 처리 흐름입니다.

```
상품·옵션 저장 요청
 └ 식별 체계 적용 상품인가?
     ├ 아니오(미부여 상품) → 현행 저장 방식대로 저장, 식별자 발급·종료 없음
     └ 예 → 변경 경로 확인
         ├ 대상 지정 경로(관리자 화면 등) → 수정 대상 기준으로 변경 전후 품목 대응
         └ 이름 대응 경로(상품 엑셀 등) → "항목명=옵션값" 쌍 묶음 기준으로 변경 전후 품목 대응
     → 중복 조합 검사(있으면 저장 오류)
     → 판정: 구조 변경 → 대응 없는 변경 전 품목 종료 → 대응 없는 변경 후 품목 신규 발급 → 나머지 유지
     → 저장 성공 조건 확인(모든 활성 품목이 식별자를 갖고 연결 대상과 연결) → 성공 처리
```

### 4.10 오류 및 예외 처리

저장 실패, 재전송, 내부 재생성, 잘못된 입력 등 정상 흐름을 벗어난 경우의 처리입니다.

| 상황 | 처리 |
| --- | --- |
| 상품·옵션 저장 실패 | 기존 식별자를 그대로 둡니다. 종료·신규 발급을 하지 않습니다. |
| 저장 실패 후 재시도 | 같은 변경에 식별자를 중복 발급하지 않습니다. 재시도가 성공하면 그 시점의 저장 상태와 비교해 판정합니다. |
| 저장은 성공했으나 응답이 끊겨 같은 요청을 다시 보냄 | 품목을 추가로 만들거나 식별자를 중복 발급하거나 품목을 추가로 종료하지 않습니다. 결과는 처음 성공한 저장과 같아야 합니다. |
| 저장 과정에서 DB 재고 행이 삭제 후 다시 만들어짐 | 정책상 삭제로 보지 않습니다. 변경 경로의 대응 기준으로 대응된 품목이면 같은 식별자를 유지하고 현재 연결을 새 재고 행으로 갱신합니다. |
| 식별자 발급·연결 실패 | 성공으로 안내하지 않으며, 식별자가 없거나 잘못 연결된 품목이 저장된 상태로 남지 않게 합니다. 실패 처리 단위는 개발 설계에서 정합니다. |
| 저장 결과 같은 상품에 같은 옵션값 조합이 둘 이상 생김 | 저장 오류로 처리합니다. 식별자를 합치거나 서로 바꾸지 않습니다. 이름 맞교환처럼 편집 중에만 잠시 같아지는 경우는 오류가 아닙니다. |
| 같은 상품을 두 운영자가 동시에 수정 | 현행 저장 방식대로 처리하고 각 저장 시점의 저장 상태와 비교해 판정합니다. |
| 저장 전 취소(저장하지 않고 화면을 벗어남) | 변경이 없으므로 식별자를 그대로 둡니다. |

### 4.11 기존 상품 적용

적용 시점에 이미 등록된 상품·품목에 식별자를 처음 부여하는 기준입니다.

**공통 기준**

- 최초 부여 시점에 현재 존재하는 상품·품목만 부여합니다. 이미 삭제된 과거 조합에는 부여하지 않습니다.
- 상품번호, 옵션 항목 번호, 재고 행 번호, 관리코드는 바꾸지 않습니다. 관리코드를 식별자로 전환하지 않으며, 관리코드 입력·중복 여부와 관계없이 부여합니다.
- 부여 작업을 다시 실행해도 이미 식별자가 있는 상품·품목에는 다시 발급하지 않습니다.
- 부여 작업 중에 운영자가 상품을 등록·수정·삭제해도 작업이 끝난 시점의 현재 품목마다 식별자가 1개씩 누락·중복·잘못된 연결 없이 부여돼야 합니다.
- 기존 주문 데이터에는 신규 식별자를 연결하지 않습니다.
- 상품 고유 식별자는 유형과 관계없이 현재 존재하는 상품마다 1개 부여합니다.

**유형별 부여 기준** — A·B·C는 옵션 유형이고, D·E는 옵션 유형과 겹쳐서 적용하는 추가 조건입니다.

| 유형 | 대상 | 부여 기준 | 기존 값 연결 |
| --- | --- | --- | --- |
| A | 조합옵션 상품 | 현재 조합마다 1개. 순번은 재고 행 번호 오름차순으로 `0001`부터 매깁니다(4.5). | 상점 + 상품번호 + 재고 행 번호 1개 ↔ 품목 식별자 1개 |
| B | 노조합 옵션 상품 | 기본 품목 1개 | 상품 단위 재고 행 1개(상점 + 상품번호 + 재고 행 번호) |
| C | 옵션 없는 상품 | 기본 품목 1개 | 상품 단위 재고 행 1개(상점 + 상품번호 + 재고 행 번호) |
| D(추가 조건) | 특수 옵션코드 사용 상점(재고 행 번호를 관리코드로 자동 생성하거나 별도 옵션코드 규칙을 쓰는 상점 등) | 옵션 유형(A·B·C)에 맞게 부여하고 기존 특수 코드는 바꾸지 않습니다. 일괄 부여 전 상점별 영향을 확인합니다. | 옵션 유형의 연결 기준과 같음 |
| E(추가 조건) | 비정상 데이터(옵션 정보와 재고 조합 불일치, 중복 조합, 재고 행 번호 이상, 옵션 관계값 불일치, 재조합 잔존 데이터) | 자동 부여에서 제외하고 보정 대상 목록으로 관리합니다. 보정해 유효한 판매·재고 단위로 확인되면 옵션 유형에 맞게 부여합니다. 중복 데이터는 임의로 하나를 골라 부여하지 않습니다. | 보정 후 옵션 유형의 연결 기준과 같음 |

- 보정 완료 조건: 보정 대상 목록의 모든 항목이 "부여 완료" 또는 "부여 제외"가 돼야 합니다. "부여 제외"는 실제 판매·재고 단위가 아닌 잔존 데이터로 확인된 경우에만 쓰며 사유와 확인자를 기록합니다.

**미부여 상품(유형 E 보정 전)**

| 항목 | 처리 |
| --- | --- |
| 기존 기능 | 판매·주문·재고·상품 수정(화면·엑셀·Open API) 등 기존 기능은 현행대로 동작하고 편집도 허용합니다. |
| 편집 시 식별자 | 품목 식별자를 발급·종료하지 않으며 현행 저장 방식대로 저장합니다. |
| 표시 | 관리자 화면과 엑셀 다운로드의 품목 식별자 칸은 빈 값입니다. |
| 적용 전환 | 보정을 마치면 그 시점의 현재 품목 기준으로 최초 부여하고 식별 체계 적용 상품으로 전환합니다. |

**적용 시작과 완료**

- 유형 A·B·C(유형 D 포함, 유형 E 제외)의 최초 부여를 마치면 신규 등록·수정에 이 정책을 적용합니다. 유형 E 상품이 남아 있어도 적용을 시작합니다.
- 유형 E 보정 완료 조건을 충족하면 전체 적용 완료로 봅니다.

### 4.12 식별자 제공 범위

운영자와 다른 기능에 식별자를 제공하는 범위입니다.

| 제공처 | 제공 방식 |
| --- | --- |
| 관리자 상품 관리 화면(상품 등록·수정) | 활성 품목의 품목 식별자와 상품 식별자를 읽기 전용으로 제공합니다. 관리코드와 다른 항목으로 표시합니다. 화면·엑셀 표기명은 "품목코드"입니다. 표시 위치는 와이어프레임 초안에서 정합니다. |
| 상품 엑셀 다운로드 | 상품·품목 식별자를 다운로드 항목으로 제공합니다. 미부여 상품은 빈 값입니다. |
| 상품 엑셀 업로드 | 식별자 칸에 값이 있어도 반영하지 않습니다. 수정 대상 지정에도 쓰지 않고 이름 대응 기준으로 처리합니다. |
| Open API | 식별자 조회를 제공하지 않으며, 식별자 값을 지정·변경하는 기능도 제공하지 않습니다. |
| 종료 품목 | 관리자 화면에 표시하지 않습니다. 내부 조회(운영·CS·장애 대응)는 가능해야 합니다. |
| 후속 과제(통합 엑셀, 재입고 알림) | 관리자 화면·엑셀 다운로드 값과 내부 조회로 식별자를 사용합니다. |

### 4.13 이력 관리

식별자의 발급·종료와 기존 값 연결을 추적하기 위해 남기는 정보입니다. 식별자와 아래 정보는 영구 보존합니다.

| 항목 | 내용 |
| --- | --- |
| 식별자·소속 상품·상태 | 발급한 값, 품목이 속한 상품의 식별자, 활성/종료 |
| 발급 일시·사유 | 상품 등록, 옵션값 추가, 구조 변경, 상품 복사, 기존 데이터 최초 부여, 미부여 상품 적용 전환 등 |
| 종료 일시·사유 | 옵션값 삭제, 조합 삭제, 이름 대응 경로의 이름 변경, 구조 변경, 상품 완전 삭제 등 |
| 현재 연결 | 활성 품목은 옵션 유형별 연결 대상과 연결합니다. 재고 행이 다시 만들어져 재고 행 번호가 바뀌어도 유지되는 품목이면 새 값으로 갱신합니다. |
| 종료 시점 연결 | 종료 품목은 종료 시점의 연결 값을 고정합니다. 같은 재고 행 번호가 새 품목에 다시 채번돼도 종료 식별자는 새 품목을 가리키지 않습니다. |
| 변경 경로·변경자 | 관리자 화면·엑셀 업로드·Open API·기존 데이터 부여 구분, 운영자 계정 또는 시스템 작업 구분 |

- 식별자 외 상세 변경 이력(옵션명·가격 변경 내역 등)의 보관 기간은 개발 설계에서 정합니다.

## 5. 고객 영향 및 안내

### 고객이 반드시 알아야 할 내용

| 대상 | 내용 |
| --- | --- |
| 상점 운영자 | 상품 등록·수정 화면과 상품 엑셀 다운로드에서 품목마다 시스템이 발급한 품목코드(예: `123456789-0001`)를 확인할 수 있습니다. 앞부분은 상품번호, 뒷부분은 상품 안의 발급 순번이며 옵션 순서와는 관계없습니다. 운영자가 바꿀 수 없으며, 직접 관리하는 관리코드와는 별개입니다. |
| 상점 운영자 | 관리자 상품 수정 화면에서 옵션 항목명·옵션값 이름을 고치거나 순서·가격·재고를 바꿔도 품목 식별자는 바뀌지 않습니다. |
| 상점 운영자 | 상품 엑셀 업로드로 옵션 항목명·옵션값 이름을 바꾸면 해당 품목은 종료되고 새 식별자가 발급됩니다. 식별자를 유지하려면 이름 변경은 관리자 화면에서 해야 합니다. |
| 상점 운영자 | 옵션 항목을 추가·삭제하거나, 옵션값을 삭제한 뒤 다시 추가하면 새 식별자가 발급됩니다. |
| 쇼핑몰 구매자 | 영향 없음. 상품 상세·주문 화면과 구매 흐름은 바뀌지 않습니다. |
| 외부 연동(ERP·WMS 등) | 기존 관리코드 등 기존 값은 그대로 유지되므로 현행 연동에는 영향이 없습니다. |
