## 2. 배경과 문제

| 항목 | 내용 |
|---|---|
| 배경 | 고객이 실제로 사는 것은 상품이 아니라 "블랙 티셔츠 XS"처럼 옵션이 정해진 판매 단위입니다. 상품명·판매가 등은 판매 단위를 감싸는 공통 정보입니다. |
| 해결할 문제 | 판매 단위에 불변 식별자가 없습니다. 옵션을 수정·재조합하면 저장된 조합을 지우고 다시 만들어 번호(조합 순번)가 바뀌고, 지운 번호가 다른 옵션에 다시 쓰일 수 있습니다. 옵션 없는·미조합 상품은 판매 단위를 가리킬 번호가 없습니다. |
| 사용자·운영 영향 | 재고, 재입고 알림처럼 옵션을 번호로 기억하는 기능의 연결이 끊기거나 다른 옵션에 잘못 연결될 수 있습니다. 후속 과제인 통합 엑셀(관련 Task)과 재입고 알림(관련 Task)은 불변 식별자가 먼저 있어야 진행할 수 있습니다. |
| 확인 근거 | 테스트 상점 관리자 화면 확인(2026-10-29): 기본옵션·하이브리드·개별옵션 팝업의 재고 행 단위, 상품 메뉴 검색 4개 화면의 현재 검색 항목 |

## 3. 목표와 범위

### 3.1 목표

- 판매 단위마다 옵션코드 1개를 발급하고, 같은 판매 단위는 옵션을 수정·재조합해도 같은 코드를 유지합니다.
- 한 번 쓴 옵션코드는 다른 판매 단위에 다시 쓰지 않습니다.
- 기존 식별값과 기존 기능은 그대로 둡니다.

### 3.2 포함 범위

- 옵션코드의 발급 단위·형식·순번·발급 시점, 유지·신규 발급·종료 기준
- 상품 복사·삭제·복구 시 처리, 이미 등록된 상품의 일괄 발급
- 옵션 팝업 3종과 상품 수정 요약 박스의 읽기 전용 표시
- 전체 상품 관리·삭제 상품 조회·재고 일괄 관리·재입고 알림 관리의 옵션코드 검색

### 3.3 제외 범위

- 다중 상품 옵션 불러오기로 가져온 옵션(OPEN-001)
- 상품 엑셀 업로드·다운로드(통합 엑셀 프로젝트 관련 Task 소관, CON-002)
- 주문 메뉴의 옵션코드 검색·표시(추후 업데이트)
- Open API 조회·지정, 옵션 순서 변경·조합 상한 등 옵션 기능 개선, 기존 주문 데이터
