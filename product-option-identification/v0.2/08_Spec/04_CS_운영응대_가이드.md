# [CS 운영·응대 가이드] 원본 요청 상품 옵션 식별 체계 개선

상점 운영자 문의에 응대하기 위한 가이드입니다. 판단 기준은 사양 정의서 14장 정책 원장(POL)이며, 이 문서는 새로운 조건을 만들지 않습니다.

## 1. 변경사항 한눈에 보기

| 항목 | 내용 |
|---|---|
| 변경 목적 | 판매 단위(옵션 조합 등)마다 바뀌지 않는 식별 코드를 붙여, 옵션을 수정해도 같은 옵션을 계속 정확하게 가리키게 합니다. |
| 적용 대상 | 메이크샵 프리미엄·코어의 모든 상품(신규·기존) |
| 적용 시점 | 배포 일정 확정 후 공지 |
| 고객 영향 | 관리자 옵션 화면에 "옵션코드"가 추가되고, 상품 메뉴 4곳에서 옵션코드로 검색할 수 있습니다. 구매자 화면은 바뀌지 않습니다. |
| 기존 고객 처리 | 배포 시 기존 상품에 일괄로 옵션코드가 붙습니다. |
| 상담 핵심 포인트 | 옵션코드는 시스템이 붙이며 수정할 수 없습니다. 운영자가 입력하는 관리코드와는 다릅니다. |

## 2. 필수 정책·고지 및 상담 범위

| CON·POL ID | 적용 대상 | 고객에게 안내할 내용 | 필수 확인·고지 시점 | 상담원이 판단하면 안 되는 내용 | 이관 부서 |
|---|---|---|---|---|---|
| POL-001 | 옵션코드 | 옵션코드는 시스템이 자동으로 붙이며 수정·삭제할 수 없습니다. | 수정 요청 시 | 코드 변경·재발급 약속 | 해당 없음 |
| POL-018 | 삭제 후 다시 추가한 옵션 | 지웠다가 다시 추가한 옵션은 새 코드를 받습니다. 예전 코드로 되돌릴 수 없습니다. | 코드 변경 문의 시 | 예전 코드 복원 약속 | 해당 없음 |
| POL-026 | 삭제 상품 복구 | 삭제한 상품을 복구하면 삭제 전 코드를 그대로 씁니다. | 복구 문의 시 | 없음 | 해당 없음 |
| POL-029 | 데이터 보정 대기 상품 | 일부 기존 상품은 데이터 확인 후 옵션코드가 붙습니다. 그동안 판매·수정은 평소처럼 됩니다. | 코드 빈 값 문의 시(개발 확인 후) | 빈 값 원인 단정, 발급 완료 시점 약속 | 개발 |

## 4. 문의 유형별 응대 가이드

| 문의 유형·증상 | 먼저 확인할 정보 | 확인 경로 | 처리 절차 | 고객 안내 문구 | 관련 POL |
|---|---|---|---|---|---|
| 옵션코드를 고치고 싶다 | 상품번호, 옵션 | 옵션 팝업 | 수정 불가 안내. 기본옵션 조합 상품이면 관리코드 칸 안내(하이브리드·개별옵션은 관리코드 칸이 없으므로 안내하지 않음) | "옵션코드는 시스템이 자동으로 붙이는 값이라 수정하실 수 없습니다." 기본옵션 조합 상품: "직접 관리하실 코드는 옵션 조합 목록의 관리코드 칸을 이용해 주세요." | POL-001 |
| 옵션을 바꿨더니 코드가 달라졌다 | 옵션 유형, 어떤 변경을 했는지(옵션값 추가·삭제와 그 저장 여부, 옵션명 추가·삭제, 옵션 사용 방식 변경) | 옵션 팝업 | 옵션 유형과 변경 종류로 신규 발급 여부 설명 | "같은 옵션은 코드가 유지됩니다. 조합 옵션에서 옵션명(예: 소재)을 추가·삭제하시면 조합 코드가 모두 새로 붙습니다. 하이브리드·개별옵션은 추가·삭제하신 옵션명의 값만 영향을 받습니다. 옵션 삭제를 저장하신 뒤 다시 추가하신 옵션과 옵션 사용 방식을 바꾸신 경우에도 새 코드가 붙습니다." | POL-016, POL-018 부터 POL-022 |
| 새로 추가한 옵션 코드가 "자동생성"으로 보인다 | 상품 저장 여부 | 상품 수정 화면 | 저장 후 다시 확인 안내 | "옵션코드는 저장이 완료되면 붙습니다. 신규 상품은 상품등록까지 완료하신 뒤 상품 수정 화면에서 확인해 주세요." | POL-012, POL-013, POL-033 |
| 기존 상품 옵션코드가 비어 있다 | 상품번호 | 옵션 팝업 | 보정 대기 상품인지 개발에 확인 요청. 확인 전에는 원인을 단정하지 않음 | 확인 전: "데이터 보정 대기 여부를 확인한 후 안내드리겠습니다." 보정 대기로 확인된 경우: "해당 상품은 데이터 확인 후 옵션코드가 붙을 예정입니다. 판매와 상품 수정은 평소처럼 하실 수 있습니다." | POL-029, POL-034 |
| 코드 순서가 뒤죽박죽이다 | 옵션 추가 이력 | 옵션 팝업 | 순번은 발급 순서임을 설명 | "옵션코드 번호는 만들어진 순서대로 붙습니다. 나중에 추가하신 옵션은 뒤 번호를 받으며, 쇼핑몰에 보이는 옵션 순서는 바뀌지 않습니다." | POL-009, POL-036 |
| 옵션코드로 검색이 안 된다 | 입력한 코드, 검색한 메뉴 | 해당 메뉴 | 전체 입력·사용 중 코드인지 확인 | "옵션코드는 하이픈을 포함한 전체 코드를 입력하셔야 검색됩니다. 삭제한 상품의 코드는 삭제 상품 조회에서 검색해 주세요." | POL-040, POL-041 |
| 엑셀에서 옵션코드를 보고 싶다 | 사용 메뉴 | 해당 없음 | 범위 밖 안내 | "상품 엑셀의 옵션코드는 이번 업데이트에 포함되지 않았습니다. 지원 여부는 공지로 안내드리겠습니다." | CON-002 |

## 5. 상태·오류별 안내

| 화면 문구·상태 | 의미 | 상담원 조치 | 고객 조치 | 재시도 조건 | 관련 POL |

## 6. 상담원 확인 체크리스트

- [ ] 상점과 상품번호 확인
- [ ] 문의 화면(옵션 팝업·상품 수정·검색 메뉴) 확인
- [ ] 옵션 유형(기본옵션 조합·미조합, 하이브리드, 개별옵션, 옵션 없음) 확인
- [ ] 최근에 한 옵션 변경(추가·삭제·옵션명 추가·유형 변경) 확인
- [ ] 저장 완료 여부 확인

## 10. 공지 및 운영 준비

- 고객 공지 필요 여부와 시점: 필요. 배포 전 관리자 공지로 옵션코드 추가·수정 불가·검색 메뉴를 안내합니다.
- 도움말·매뉴얼 수정: 옵션 등록 매뉴얼에 옵션코드 열과 도움말 문구를 추가합니다.
- 상담 도구·관리자 조회 기능: 상담원은 상점 관리자 화면과 같은 옵션 팝업·검색으로 확인합니다. 종료된 코드는 개발 내부 조회로만 확인할 수 있습니다.
- 장애·대량 문의 발생 시 공지 기준: 같은 옵션의 코드가 바뀌거나 다른 옵션과 겹치는 사례가 여러 상점에서 확인되면 공지합니다.
- 알려진 제한사항과 임시 우회 방법: 상품 엑셀·주문 메뉴·Open API에서는 옵션코드를 제공하지 않습니다.
