# [정책서] 원본 요청 상품 옵션 식별 체계 개선

## 1. 문서 정보

실제 판매·재고 단위마다 바뀌지 않는 식별 코드(옵션코드)를 추가할 때 적용하는 정책입니다.

| 항목 | 내용 |
| --- | --- |
| 문서 유형 | 기능 개선 |
| 대상 서비스 | 상품 등록·수정·복사·삭제, 상품 옵션 팝업(기본옵션·하이브리드 옵션·개별옵션) |
| 작성자 | 담당자 |
| 작성일 | 2026-10-29 |
| 관련 Jira | Epic 원본 요청 · 기획 관련 Task |
| 정책 원장 | [원본 요청] 상품 옵션 식별 체계 개선 사양 정의서 14장 정책 원장 |

## 2. 변경 사항 요약

이번 개선으로 무엇이 바뀌는지 요약합니다.

### 2.1 한 줄 요약

재고가 관리되는 단위마다 시스템이 옵션코드를 1개 발급하고, 옵션을 수정·재조합해도 같은 단위는 같은 코드를 유지합니다.

### 2.2 변경 목적

- 현재는 옵션을 수정하거나 재조합하면 저장된 조합을 삭제하고 다시 만들기 때문에, 같은 옵션인데도 번호(조합 순번)가 바뀌고 지운 번호가 다른 옵션에 다시 쓰일 수 있습니다.
- 재고, 재입고 알림, 통합 엑셀처럼 옵션을 번호로 기억하는 기능이 같은 판매 단위를 계속 정확하게 가리키게 합니다.

### 2.3 변경 전·후

| 구분 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 판매 단위 식별값 | 조합 순번. 재조합하면 다시 매겨지고 재사용될 수 있습니다. | 옵션코드. 발급 후 바뀌지 않고 다시 쓰지 않습니다. |
| 옵션 없는·미조합 상품 | 판매 단위 식별값이 없습니다. | 상품당 옵션코드 1개를 발급합니다. |
| 기존 식별값 | 상품번호, 옵션 번호, 조합 순번, 관리코드 | 변경하지 않습니다. |

## 3. 적용 대상 및 범위

옵션코드를 적용하는 상품과 이번에 다루지 않는 범위입니다.

### 적용 대상

- 메이크샵 프리미엄·코어의 모든 상품(신규 상품과 이미 등록된 상품)
- 기본옵션(조합·미조합), 하이브리드 옵션, 개별옵션, 옵션을 사용하지 않는 상품

### 포함 범위

- 옵션코드의 발급 단위, 형식, 유지·신규 발급·종료 기준
- 이미 등록된 상품에 대한 최초 발급
- 관리자 화면에서 옵션코드를 읽기 전용으로 제공
- 상품 메뉴 4개 화면(전체 상품 관리, 삭제 상품 조회, 재고 일괄 관리, 재입고 알림 관리)의 검색 조건에 옵션코드 추가

### 제외 범위

- 다중 상품 옵션 불러오기로 가져온 옵션의 처리(별도 결정 후 추가합니다)
- 주문 메뉴의 옵션코드 검색·표시(추후 업데이트로 진행합니다)
- 기존 식별값(상품번호, 옵션 번호, 조합 순번, 관리코드)의 생성·변경 방식
- 상품 엑셀 업로드·다운로드의 옵션코드 처리. 메이크샵 통합 엑셀 프로젝트(관련 Task)에서 별도로 진행하므로 이번 프로젝트에서 제외합니다.
- Open API의 옵션코드 조회와 옵션코드로 상품·옵션을 지정해 수정하는 기능
- 옵션 순서 변경, 조합 개수 상한 등 옵션 기능 자체의 개선
- 기존 주문 데이터

### 이용 조건

- 옵션코드는 시스템만 발급하고 종료합니다. 운영자는 입력·수정·삭제할 수 없습니다.
- 옵션코드 조회 권한은 현재 상품 관리 메뉴 권한과 같습니다.

관련 정책: POL-001, POL-047

## 4. 상세 정책

옵션코드를 언제, 어떤 단위로, 어떤 형식으로 발급하고 유지하는지 정의합니다.

### 4.1 발급 단위

재고가 관리되는 행 1개에 옵션코드 1개를 발급합니다.

| 옵션 유형 | 발급 단위 | 예시 |
| --- | --- | --- |
| 기본옵션 · 조합 | 조합마다 1개 | 블랙/S, 블랙/M 각각 1개 |
| 기본옵션 · 미조합 | 상품당 1개 | 상품 전체 1개 |
| 옵션 사용 안 함 | 상품당 1개 | 상품 전체 1개 |
| 하이브리드 옵션 | 옵션값마다 1개 | 사이즈 S, 사이즈 M 각각 1개 |
| 개별옵션 | 개별 옵션값마다 1개 | 포장: 선물포장 1개 |

- 원클릭 옵션은 옵션을 버튼·이미지로 보여 주는 표시 방식이므로 별도로 발급하지 않습니다. 해당 옵션의 옵션코드를 그대로 씁니다.
- 옵션명(색상·사이즈 등)과 조합옵션의 개별 옵션값(블랙, S 등)에는 발급하지 않습니다.

관련 정책: POL-002, POL-003, POL-004, POL-005, POL-006

### 4.2 형식과 순번

옵션코드는 상품번호와 그 상품 안의 발급 순번으로 만듭니다.

| 항목 | 규칙 |
| --- | --- |
| 형식 | `{상품번호}-{순번}`입니다. 예: `123456789-0001` |
| 하이픈 | 상품번호와 순번 사이에 항상 하이픈(`-`)을 넣습니다. |
| 순번 자릿수 | 최소 4자리입니다. `0001`부터 `9999`까지 앞을 0으로 채우고, 그 다음은 `10000`처럼 자릿수가 늘어납니다. |
| 다음 순번 | 그 상품에서 지금까지 발급한 가장 큰 순번 + 1입니다. 종료된 순번도 포함해 계산하므로 같은 번호가 다시 나오지 않습니다. |
| 순번 범위 | 기본옵션, 하이브리드 옵션, 개별옵션 모두 상품 하나 안에서 같은 순번을 이어서 씁니다. |
| 발급 시점 | 신규 상품은 상품 최종 저장(상품등록)이 완료될 때 발급합니다. 기존 상품은 옵션을 저장할 때 새로 생긴 판매 단위에 발급합니다. 옵션 재조합이나 신규 상품의 옵션 팝업 저장만으로는 발급하지 않습니다. |
| 여러 개 동시 발급 | 한 번 저장으로 여러 개가 생기면 화면에 표시되는 옵션 순서대로 순번을 매깁니다. |
| 정렬 | 순번을 숫자로 비교해 정렬합니다. 문자 순서로 정렬하지 않습니다. |
| 표시 순서와의 관계 | 순번은 발급 순서일 뿐입니다. 옵션 순서를 바꿔도 옵션코드는 바뀌지 않습니다. 관리자 옵션 목록의 표시 순서는 아래 "옵션 목록 표시 순서"를 따릅니다. |

**옵션 목록 표시 순서**

관리자 옵션 팝업의 옵션 목록을 어떤 순서로 보여 줄지 정합니다. 운영자가 순서를 직접 정할 수 있는 화면에서는 그 순서를 가장 먼저 적용하고, 순서를 정할 수 없는 화면에서는 옵션코드 순서로 보여 줍니다.

| 옵션 유형 | 표시 순서 |
| --- | --- |
| 기본옵션 · 조합 | 옵션코드 순번 오름차순입니다. 조합 목록에는 순서를 바꾸는 기능이 없으므로 별도 순서 항목을 두지 않습니다. 옵션값을 나중에 추가하면 새 조합은 기존 조합 뒤에 표시됩니다. |
| 개별옵션 | 옵션코드 순번 오름차순입니다. |
| 하이브리드 옵션 | 운영자가 이동 기능으로 정한 순서를 가장 우선합니다. 옵션코드 순번과 관계없이 운영자가 정한 순서대로 표시합니다. |
| 저장 전 새 옵션 | 옵션코드가 없으므로 기존 옵션 뒤에 추가된 순서대로 표시합니다. 저장 후에는 위 기준을 따릅니다. |

- 이 기준은 관리자 옵션 목록에만 적용합니다. 구매자 화면의 옵션 노출 순서는 바꾸지 않습니다.
- 조합 목록에 순서 변경 기능이 추가되면, 옵션코드와 별도로 표시 순서 항목을 두고 그 순서를 우선합니다. 이때도 옵션코드는 바뀌지 않습니다.

관련 정책: POL-007, POL-008, POL-009, POL-010, POL-011, POL-012, POL-013, POL-036, POL-037, POL-038

### 4.3 유지·신규 발급·종료

옵션을 저장하거나 재조합할 때 저장 전 옵션과 저장 후 옵션을 비교해 옵션코드를 처리합니다. 같은 판매 단위면 유지하고, 새로 생긴 단위에만 신규 발급하며, 사라진 단위는 종료합니다. 종료된 옵션코드는 다시 쓰지 않습니다.

| 변경 | 처리 |
| --- | --- |
| 가격, 재고, 상태(판매·품절 등), 관리코드, 비고 변경 | 유지합니다. |
| 옵션 순서 변경 | 유지합니다. |
| 관리자 화면에서 옵션명·옵션값 이름 변경 | 유지합니다. 어떤 옵션의 이름을 바꿨는지 화면에서 특정할 수 있기 때문입니다. |
| 옵션값 추가(재조합 포함) | 기존 옵션은 유지하고, 새로 생긴 조합·옵션값에만 신규 발급합니다. |
| 옵션값·조합 삭제 | 삭제한 것만 종료하고, 나머지는 유지합니다. |
| 삭제를 저장한 뒤 같은 이름으로 다시 추가 | 이전 옵션코드를 복원하지 않고 신규 발급합니다. |
| 한 번의 저장 안에서 지웠다가 다시 넣음 | 저장 결과만 비교합니다. 저장 전후에 같은 옵션이 있으면 유지합니다. |
| 기본옵션 · 조합에서 옵션명 추가·삭제(예: 소재 추가) | 조합 자체가 바뀌므로 기존 조합을 모두 종료하고 변경 후 조합마다 신규 발급합니다. |
| 하이브리드 옵션·개별옵션에서 옵션명 추가·삭제 | 옵션값끼리 독립적이므로 추가된 옵션명의 옵션값만 신규 발급하고, 삭제된 옵션명의 옵션값만 종료합니다. |
| 옵션 유형 전환(조합↔미조합, 기본옵션↔하이브리드, 옵션 사용↔사용 안 함) | 기존 기본옵션 옵션코드를 모두 종료하고 전환 후 단위마다 신규 발급합니다. |
| 개별옵션 사용 → 사용 안 함 | 개별옵션 옵션코드를 모두 종료합니다. 기본옵션 옵션코드는 영향이 없습니다. |

관련 정책: POL-014, POL-015, POL-016, POL-017, POL-018, POL-019, POL-020, POL-021, POL-022, POL-023

### 4.4 상품 복사·삭제·복구

상품 단위 작업에서 옵션코드를 처리하는 기준입니다.

| 작업 | 처리 |
| --- | --- |
| 상품 복사 | 복사한 상품은 새 상품번호를 받고, 모든 옵션에 `0001`부터 신규 발급합니다. 원본 상품의 옵션코드는 그대로입니다. |
| 상품 삭제(복구할 수 있는 상태) | 옵션코드를 그대로 보관합니다. |
| 삭제한 상품 복구 | 삭제 전 옵션코드를 그대로 다시 씁니다. |
| 상품 완전 삭제 | 옵션코드를 모두 종료하고 다시 쓰지 않습니다. |

관련 정책: POL-024, POL-025, POL-026, POL-027

### 4.5 이미 등록된 상품

기능 배포 시점에 이미 등록된 상품에 옵션코드를 발급하는 기준입니다.

- 배포할 때 현재 존재하는 상품·옵션에 한 번에 발급합니다. 화면 진입이나 수정·저장 시점을 기다리지 않습니다.
- 이미 삭제된 과거 옵션에는 발급하지 않습니다.
- 순번은 현재 옵션의 조합 순번 오름차순으로 `0001`부터 매깁니다.
- 같은 조합이 중복되는 등 옵션과 재고가 맞지 않는 상품은 보정한 뒤 발급합니다. 보정 전에도 판매와 상품 수정은 평소처럼 할 수 있으며, 옵션코드는 빈 값으로 둡니다.
- 발급 작업을 다시 실행해도 이미 옵션코드가 있는 옵션에는 다시 발급하지 않습니다.

관련 정책: POL-028, POL-029, POL-030

### 4.6 표시와 제공

운영자가 옵션코드를 확인하는 방식입니다.

| 대상 | 기준 |
| --- | --- |
| 관리자 상품 옵션 팝업(기본옵션·하이브리드 옵션·개별옵션) | 옵션마다 옵션코드를 읽기 전용으로 표시합니다. 선택·복사는 가능하고 수정은 불가합니다. 운영자가 입력하는 관리코드와는 다른 항목으로 표시합니다. |
| 관리자 상품 수정 화면 | 옵션 없는 상품과 기본옵션 · 미조합 상품의 옵션코드를 읽기 전용으로 표시합니다. |
| 저장 전 새 옵션 | 실제 값이 없으므로 "자동생성" 안내만 표시합니다. 신규 상품은 상품 최종 저장이 끝나야 발급하며, 옵션 팝업 저장만으로는 발급하지 않습니다. |
| 보정 전 기존 상품 | 빈 값으로 표시하고 "자동생성" 안내를 쓰지 않습니다. |
| 종료된 옵션코드 | 관리자 화면에 표시하지 않습니다. 운영·CS·장애 대응용 내부 조회는 가능해야 합니다. |

도움말 문구는 "상품 저장이 완료되면 옵션코드가 자동으로 부여됩니다. 발급된 코드는 수정할 수 없으며, 운영자가 입력하는 관리코드와 다릅니다."입니다.

관련 정책: POL-031, POL-032, POL-033, POL-034, POL-035

### 4.7 옵션코드로 상품 검색

운영자가 옵션코드를 입력해 상품을 찾을 수 있도록 상품 메뉴의 검색 조건에 "옵션코드"를 추가합니다.

| 메뉴 | 추가 위치 | 검색 결과 |
| --- | --- | --- |
| 상품 > 상품 관리 > 전체 상품 관리 | 상품리스트 검색 > 상품 검색 선택 항목 | 입력한 옵션코드를 가진 상품을 표시합니다. |
| 상품 > 상품 관리 > 삭제 상품 조회 | 상품리스트 검색 > 상품 검색 선택 항목 | 입력한 옵션코드를 가진 삭제 상품(복구할 수 있는 상태)을 표시합니다. |
| 상품 > 일괄 관리 > 재고 일괄 관리 | 상품/옵션 재고 수량 검색 > 상품검색 선택 항목 | 입력한 옵션코드가 있는 상품 리스트를 표시합니다. |
| 상품 > 부가 기능 > 재입고 알림 관리 | 상품검색 > 검색어 선택 항목 | 입력한 옵션코드에 해당하는 옵션의 재입고 알림 내역만 표시합니다. 같은 상품의 다른 옵션 알림 내역은 표시하지 않습니다. |

- 입력값 전체가 옵션코드와 정확히 일치할 때만 검색됩니다. 앞뒤 공백은 제거하고 비교합니다.
- 현재 사용 중인 옵션코드만 검색됩니다. 종료된 옵션코드로는 검색되지 않습니다. 단, 삭제 상품 조회에서는 삭제 상품이 보관 중인 옵션코드로 검색됩니다.
- 검색 결과가 없으면 각 화면의 기존 "결과 없음" 안내를 그대로 표시합니다.
- 다른 검색 조건(분류, 진열 여부 등)과 함께 쓰면 모든 조건을 만족하는 결과만 표시합니다.

관련 정책: POL-039, POL-040, POL-041, POL-042, POL-043

### 4.8 오류 및 예외

저장이 실패하거나 판단할 수 없는 경우의 처리입니다.

| 상황 | 처리 |
| --- | --- |
| 저장 결과에 같은 조합·같은 옵션값이 새로 중복됨 | 저장 오류로 처리하고 기존 옵션코드를 바꾸지 않습니다. 단, 데이터 보정 전 기존 상품이 원래 가지고 있던 중복은 오류로 보지 않습니다. 중복을 늘리지 않는 가격·재고 등의 변경은 저장하며 옵션코드는 발급하지 않습니다. |
| 저장이 실패하거나 저장 전에 취소함 | 옵션코드와 순번을 바꾸지 않습니다. |
| 옵션코드 발급이 실패함 | 저장 성공으로 안내하지 않습니다. 옵션코드가 없거나 잘못 연결된 옵션이 저장된 상태로 남지 않게 합니다. 데이터 보정 전 기존 상품에 옵션코드를 발급하지 않는 것은 발급 실패가 아닙니다. |

관련 정책: POL-044, POL-045, POL-046

## 5. 고객 영향 및 안내

운영자와 구매자에게 달라지는 점입니다.

- 구매자 화면은 바뀌지 않습니다.
- 운영자는 옵션 팝업과 상품 수정 화면에서 옵션코드를 확인할 수 있습니다. 옵션코드는 수정할 수 없습니다.
- 운영자는 전체 상품 관리, 삭제 상품 조회, 재고 일괄 관리, 재입고 알림 관리에서 옵션코드로 상품을 검색할 수 있습니다.
- 기존 관리코드와 기존 기능은 그대로 동작합니다.

## 참고. 옵션코드에 하이픈을 넣는 이유

상품번호와 순번을 하이픈 없이 바로 붙이지 않는 이유입니다.

| 이유 | 설명 |
| --- | --- |
| 코드 중복 방지 | 순번은 9999를 넘으면 자릿수가 늘어나므로, 하이픈 없이 붙이면 상품번호와 순번의 경계를 알 수 없습니다. 예를 들어 상품번호 `11`의 `0001`번과 상품번호 `1`의 `10001`번이 모두 `110001`이 되어 서로 다른 옵션이 같은 코드를 갖게 됩니다. 하이픈을 넣으면 `11-0001`과 `1-10001`로 항상 구분됩니다. |
| 엑셀 값 보존 | 숫자만 14자리 이상이 되면 엑셀이 숫자로 인식해 `1.10001E+13`처럼 지수로 표시하거나 끝자리를 잃습니다. 하이픈이 있으면 문자로 인식되어 값이 그대로 유지됩니다. |
| 정확한 분리 | 마지막 하이픈 앞은 상품번호, 뒤는 순번이므로 코드만 보고도 어느 상품의 몇 번째 옵션인지 정확히 나눌 수 있습니다. |
