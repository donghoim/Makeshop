# [정책서] 원본 요청 상품 옵션 식별 체계 개선

## 1. 문서 정보

판매 단위마다 이미 있는 번호를 옵션코드로 보여 주고, 옵션을 바꿔도 같은 판매 단위는 같은 코드를 유지하게 하는 정책입니다.

| 항목 | 내용 |
| --- | --- |
| 문서 유형 | 기능 개선 |
| 대상 서비스 | 상품 옵션 팝업(기본옵션·하이브리드 옵션·개별옵션), 옵션 재조합, 상품 수정, 상품 복사·삭제·복구, 재고 일괄 관리, 상품 검색, Open API 조회 |
| 작성자 | 담당자 |

## 2. 변경 사항 요약

이번 개선으로 무엇이 바뀌는지 요약합니다.

### 2.1 한 줄 요약

판매 단위마다 이미 있는 번호를 `M{상품번호}-{9자리 순번}` 형식의 옵션코드로 보여 주고, 옵션을 바꿔도 같은 판매 단위는 같은 코드를 유지합니다.

### 2.2 변경 목적

- 판매 단위마다 내부 번호(조합 순번)가 이미 있지만 운영자가 볼 수 없고, 가장 큰 번호의 옵션을 지우거나 옵션 사용 안 함으로 바꾸면 같은 번호를 다시 씁니다.
- 재고, 재입고 알림, 통합 엑셀처럼 옵션을 번호로 기억하는 기능이 같은 판매 단위를 계속 정확하게 가리키게 합니다.
- 재조합할 때 같은 조합의 재고·상태를 유지할지 운영자가 고를 수 있게 합니다.

### 2.3 변경 전·후

| 구분 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 판매 단위 식별값 | 내부 번호만 있고 화면에 보이지 않습니다. 지운 번호를 다시 쓸 수 있습니다. | 같은 번호를 옵션코드로 보여 줍니다. 지운 번호는 다시 쓰지 않습니다. |
| 재조합 확인창 | 일반 상점은 "초기화됩니다" 확인 후 재고·상태를 초기화합니다. 일부 상점만 기존 데이터를 가져올지 한 번 더 묻습니다. | 레이어 팝업 하나에서 [기존 데이터 유지]·[초기화]·[취소]를 고릅니다. 일부 특별처리 상점은 기존 확인창을 그대로 씁니다. |
| 옵션코드 검색 | 없습니다. | 전체 상품 관리·삭제 상품 조회·재고 일괄 관리에서 옵션코드로 찾습니다. |

## 3. 적용 대상 및 범위

옵션코드를 적용하는 상품과 이번에 다루지 않는 범위입니다.

### 적용 대상

- 메이크샵 프리미엄·코어의 모든 상품(신규 상품과 이미 등록된 상품)
- 기본옵션(조합·미조합), 하이브리드 옵션, 개별옵션, 옵션을 사용하지 않는 상품

### 포함 범위

- 옵션코드의 형식과 유지·새 부여·종료 기준
- 재조합 확인창 변경(특별처리 상점 제외)
- 상품 복사·삭제·복구 시 처리
- 관리자 화면 읽기 전용 표시: 옵션 팝업 3종, 상품 수정 요약 박스, 재고 일괄 관리 옵션별 재고 수정 팝업
- 검색 조건 추가: 전체 상품 관리, 삭제 상품 조회, 재고 일괄 관리
- Open API 조회 응답에 옵션코드 추가

### 제외 및 예외

- 상품 엑셀 업로드·다운로드. 메이크샵 통합 엑셀 프로젝트(관련 Task)에서 진행합니다.
- 재입고 알림 관리의 옵션코드 검색. 신청 내역에 번호가 저장되지 않아 재입고 알림 과제에서 진행합니다.
- 다중 상품 옵션 불러오기로 가져온 옵션. 현행 동작을 유지합니다.
- 관리자앱. 옵션코드를 노출하지 않고 검색 항목도 추가하지 않습니다.
- 주문 메뉴의 옵션코드 검색·표시(추후 업데이트), Open API로 옵션코드 수정, 기존 주문 데이터
- 개별옵션 재조합 시 순서 값이 겹치거나 반영되지 않는 기존 문제. 개별옵션 위치 변경 요청(관련 Task)과 함께 후속으로 진행합니다.

### 이용 조건

- 옵션코드는 시스템만 부여하고 종료합니다. 운영자는 화면과 Open API 어디에서도 입력·수정·삭제할 수 없습니다.
- 옵션코드 조회 권한은 현재 상품 관리 메뉴 권한과 같습니다.

관련 정책: POL-002, POL-044, POL-049, POL-050

## 4. 상세 정책

옵션코드를 어떤 단위로, 어떤 형식으로 보여 주고 언제 유지·새로 부여·종료하는지 정의합니다.

### 4.1 정의와 단위

옵션코드는 새로 만드는 번호가 아니라, 판매 단위마다 이미 있는 번호를 보여 주는 것입니다. 재고가 관리되는 행 1개에 옵션코드 1개입니다.

| 옵션 유형 | 단위 | 예시 |
| --- | --- | --- |
| 기본옵션 · 조합 | 조합마다 1개 | 블랙/S, 블랙/M 각각 1개 |
| 기본옵션 · 미조합 | 상품당 1개 | 상품 전체 1개 |
| 옵션 사용 안 함 | 상품당 1개 | 상품 전체 1개 |
| 하이브리드 옵션 | 옵션값마다 1개 | 사이즈 S, 사이즈 M 각각 1개 |
| 개별옵션 | 개별 옵션값마다 1개 | 포장: 선물 포장 1개 |

- 원클릭 옵션은 옵션을 버튼·이미지로 보여 주는 표시 방식이므로 따로 두지 않습니다. 해당 옵션의 옵션코드를 그대로 씁니다.
- 배포 시점에 이미 있는 상품은 기존 번호를 그대로 보여 줍니다. 번호를 다시 매기지 않으며 중간에 빈 번호가 있어도 그대로 둡니다.

관련 정책: POL-001, POL-003, POL-004, POL-005, POL-006, POL-007, POL-028

### 4.2 형식과 번호

옵션코드는 영문 `M`, 상품번호, 하이픈, 순번으로 만듭니다.

| 항목 | 규칙 |
| --- | --- |
| 형식 | `M` + 상품번호 + `-` + 순번입니다. 예: `M123456789-000000001` |
| 순번 자릿수 | 9자리입니다. 모자란 자리는 앞에 0을 채웁니다. 999999999 다음은 `1000000000`처럼 자릿수가 늘어나며, 저장·표시를 막거나 코드를 자르지 않습니다. |
| 다음 번호 | 그 상품에서 지금까지 쓴 가장 큰 번호 + 1입니다. 지운 번호도 포함해 계산하므로 같은 번호가 다시 나오지 않습니다. |
| 번호 범위 | 기본옵션, 하이브리드 옵션, 개별옵션이 상품 하나 안에서 번호를 이어서 씁니다. |
| 부여 시점 | 신규 상품은 상품등록이 완료될 때 부여합니다. 기존 상품은 옵션을 저장할 때 새로 생긴 판매 단위에 부여합니다. 재조합이나 신규 상품의 옵션 팝업 저장만으로는 부여하지 않습니다. |
| 정렬 | 순번을 숫자로 비교합니다. `-1000000000`은 `-999999999` 뒤에 옵니다. |

관련 정책: POL-008, POL-009, POL-010, POL-011, POL-012

### 4.3 옵션을 바꿀 때

저장 전 옵션과 저장 후 옵션을 비교해 같은 판매 단위면 유지하고, 새로 생긴 단위에만 새 번호를 부여하며, 사라진 단위는 종료합니다. 종료된 번호는 다시 쓰지 않습니다.

| 변경 | 처리 |
| --- | --- |
| 가격, 재고, 상태(판매·품절 등), 관리코드, 비고, 순서 변경 | 유지합니다. |
| 기본옵션 · 조합의 옵션값 이름 변경 | 글자가 같은 옵션값만 유지합니다. 이름을 바꾼 옵션값이 들어간 조합은 새 코드를 받고, 이전 코드는 종료합니다. 입력 순서로 맞추지 않습니다. |
| 기본옵션 · 미조합의 옵션값 이름 변경 | 유지합니다. 미조합은 재고를 상품 단위로 관리해 옵션코드가 상품에 1개이기 때문입니다. 예: 미조합 상품의 색상 옵션값을 "베이지,블랙"에서 "베이지,차콜"로 바꿔 저장해도 옵션코드 M1100006926-000000001은 그대로입니다. |
| 옵션값 추가(재조합 포함) | 기존 옵션은 유지하고, 새로 생긴 조합·옵션값에만 새 코드를 부여합니다. |
| 옵션값·조합 삭제 | 삭제한 것만 종료하고 나머지는 유지합니다. |
| 삭제를 저장한 뒤 같은 이름으로 다시 추가 | 이전 코드를 되살리지 않고 새 코드를 부여합니다. |
| 한 번의 저장 안에서 지웠다가 다시 넣음 | 저장 결과만 비교합니다. 저장 전후에 같은 옵션이 있으면 유지합니다. |
| 기본옵션 · 조합에서 옵션명 추가·삭제(예: 소재 추가) | 조합 자체가 바뀌므로 기존 조합을 모두 종료하고 변경 후 조합마다 새 코드를 부여합니다. |
| 하이브리드 옵션 | 옵션값 줄을 그대로 고치는 구조라 옵션값 이름을 바꿔도 유지합니다. 옵션 항목을 추가·삭제하면 그 옵션값만 새로 부여·종료합니다. |
| 개별옵션 | 개별 옵션명과 옵션값 글자가 모두 같을 때만 유지합니다. 하나라도 다르면 새 코드를 받습니다. |
| 옵션 유형 전환(조합↔미조합, 기본옵션↔하이브리드, 옵션 사용↔사용 안 함) | 기존 기본옵션 코드를 모두 종료하고 전환 후 단위마다 새 코드를 부여합니다. |
| 개별옵션 사용 → 사용 안 함 | 개별옵션 코드만 종료합니다. 기본옵션 코드는 영향이 없습니다. |

- 기본옵션·개별옵션 팝업의 옵션 설정 안내에 "옵션값 이름을 바꾸거나 지우면 해당 옵션은 새 옵션코드가 부여됩니다."를 추가합니다. 하이브리드는 이름을 바꿔도 유지하므로 넣지 않습니다.

관련 정책: POL-013, POL-014, POL-015, POL-016, POL-017, POL-018, POL-019, POL-020, POL-021, POL-040, POL-051

### 4.4 재조합 확인창

기본옵션 팝업에 조합 목록이 있는 상태에서 [옵션 재조합]을 누르면 옵션 팝업 안에 레이어 팝업을 띄웁니다. 특별처리 상점을 뺀 전체 상점에 같게 적용합니다.

| 항목 | 내용 |
| --- | --- |
| 문구 | "재조합 시 기존 데이터를 유지할까요?" (제목 없음) |
| 버튼 | [기존 데이터 유지] [초기화] [취소]. 강조(기본 선택) 버튼을 두지 않습니다. |
| 대체하는 확인창 | "수량 및 상태값등 저장된 정보가 초기화 됩니다. 재조합 하시겠습니까?" |
| 적용하지 않는 상점 | 특별처리 상점. 기존 확인창을 그대로 띄웁니다. |
| 띄우지 않는 경우 | 처음 조합할 때([선택된 옵션 조합하기])는 기존 조합이 없으므로 띄우지 않습니다. |

버튼별 처리는 옵션값이 같은 조합에만 적용합니다.

| 항목 | 기존 데이터 유지 | 초기화 |
| --- | --- | --- |
| 재고 | 유지 | 0 |
| 판매상태 | 유지 | 판매 |
| 판매중지·확인요청 수량, 최소·최대 주문수량, 관리코드, 비고 | 유지 | 초기화 |
| 옵션코드 | 유지 | 유지 |
| 옵션 가격, 원클릭 이미지·색상 | 옵션 설정 값 | 옵션 설정 값 |

- 새로 생긴 조합은 어느 버튼을 눌러도 초기값이며, 저장할 때 새 코드를 받습니다.
- [취소]와 Esc는 재조합하지 않고 확인창만 닫습니다. 입력한 옵션값은 그대로 둡니다.
- 재조합 결과는 [저 장]을 눌러야 반영됩니다. 저장하지 않고 닫으면 아무것도 바뀌지 않습니다.

관련 정책: POL-022, POL-023, POL-024, POL-025

### 4.5 상품 복사·삭제·복구

상품 단위 작업에서 옵션코드를 처리하는 기준입니다.

| 작업 | 처리 |
| --- | --- |
| 상품 복사 | 복사한 상품은 새 상품번호를 받고 원본의 순번을 그대로 씁니다. 상품번호가 달라 코드가 겹치지 않습니다. 원본 상품의 코드는 그대로입니다. |
| 상품 삭제(복구할 수 있는 상태) | 옵션코드를 그대로 보관합니다. |
| 삭제한 상품 복구 | 삭제 전 옵션코드를 그대로 다시 씁니다. |
| 상품 완전 삭제 | 옵션코드를 모두 종료하고 다시 쓰지 않습니다. |

관련 정책: POL-026, POL-027, POL-028, POL-029

### 4.6 표시

운영자가 옵션코드를 확인하는 화면과 표시 방식입니다. 모든 화면에서 읽기 전용이며 선택·복사는 되고 수정은 안 됩니다. 운영자가 입력하는 관리코드와는 별도 항목입니다.

| 화면 | 위치 |
| --- | --- |
| 기본옵션 팝업 > 옵션 조합 확인 및 관리 | 맨 앞 열(선택 칸 다음) |
| 하이브리드 옵션 팝업 > 옵션값 표 | 맨 앞 열(삭제 버튼 다음) |
| 개별옵션 팝업 > 옵션 조합 확인 및 관리 | 맨 앞 열(선택 칸 다음) |
| 재고 일괄 관리 > 옵션별 재고 수정 팝업 | 맨 앞 열. 조합 이후의 목록이라 이 팝업에서는 코드가 바뀌지 않습니다. |
| 상품 수정 > 등록상품 수정 요약 | 미조합 옵션·옵션 사용 안 함 상품만 "옵 션 코 드" 1줄 |

| 상태 | 표시 |
| --- | --- |
| 저장 전 새 옵션 | 실제 값이 없으므로 비활성 칸에 "자동생성" 안내만 표시합니다. |
| 번호가 없는 판매 단위(비정상 데이터) | 빈 값으로 표시하고 "자동생성" 안내를 쓰지 않습니다. 판매와 상품 수정은 평소처럼 할 수 있습니다. |
| 종료된 옵션코드 | 관리자 화면에 표시하지 않습니다. 운영·CS·장애 대응용 내부 조회는 가능해야 합니다. |

**옵션 목록 표시 순서**

| 옵션 유형 | 표시 순서 |
| --- | --- |
| 기본옵션 · 조합, 개별옵션 | 순번 오름차순입니다. 나중에 추가한 옵션값의 조합은 기존 조합 뒤에 표시됩니다. |
| 하이브리드 옵션 | 운영자가 이동 기능으로 정한 순서를 가장 우선합니다. |
| 저장 전 새 옵션 | 기존 옵션 뒤에 추가된 순서대로 표시합니다. |

- 이 기준은 관리자 옵션 목록에만 적용합니다. 구매자 화면의 옵션 노출 순서는 바꾸지 않습니다.
- 도움말 문구: "상품 저장이 완료되면 옵션코드가 자동으로 부여됩니다. 코드는 수정할 수 없으며, 운영자가 입력하는 관리코드와 다릅니다. 옵션값 이름을 바꾸거나 지우면 해당 옵션은 새 옵션코드가 부여됩니다."
- 하이브리드 옵션 팝업 도움말: "상품 저장이 완료되면 옵션코드가 자동으로 부여됩니다. 코드는 수정할 수 없으며, 운영자가 입력하는 관리코드와 다릅니다. 하이브리드 옵션은 옵션값 이름을 바꿔도 옵션코드를 유지합니다." 하이브리드는 옵션값 이름을 바꿔도 코드를 유지하기 때문입니다.

관련 정책: POL-030, POL-031, POL-032, POL-033, POL-034, POL-035, POL-036, POL-037, POL-038, POL-039, POL-040

### 4.7 옵션코드로 상품 검색

상품 메뉴 3곳의 검색 조건에 "옵션코드"를 추가합니다.

| 메뉴 | 추가 위치 | 검색 결과 |
| --- | --- | --- |
| 상품 > 상품 관리 > 전체 상품 관리 | 상품 검색 선택 항목, 상품번호 다음 | 옵션코드를 가진 상품 |
| 상품 > 상품 관리 > 삭제 상품 조회 | 상품 검색 선택 항목, 상품번호 다음 | 옵션코드를 보관 중인 삭제 상품 |
| 상품 > 일괄 관리 > 재고 일괄 관리 | 상품검색 선택 항목, 상품번호 다음 | 옵션코드가 있는 상품 리스트 |

- 앞뒤 공백을 지우고 부분 일치로 찾습니다. 옵션코드에 상품번호가 들어 있어 상품번호만 넣어도, 코드 전체를 넣어도 같은 상품이 나옵니다.
- 결과는 상품 단위이며 각 화면의 기존 목록 형태를 그대로 씁니다.
- 현재 사용 중인 옵션코드만 찾습니다. 종료된 코드로는 찾지 않습니다. 삭제 상품 조회에서는 삭제 상품이 보관 중인 코드로 찾습니다.
- 검색 결과가 없으면 각 화면의 기존 "결과 없음" 안내를 그대로 표시합니다. 다른 검색 조건과 함께 쓰면 모든 조건을 만족하는 결과만 표시합니다.

관련 정책: POL-041, POL-042, POL-043

### 4.8 Open API

Open API는 옵션코드를 조회만 합니다.

- 판매 단위 번호를 이미 응답하는 조회 API에 옵션코드를 함께 응답합니다.
- Open API로 옵션코드를 수정할 수 없습니다. 수정 요청에 옵션코드 값이 있어도 반영하지 않습니다.
- 기존 연동(네이버페이·Open API)이 쓰는 번호와 응답은 바꾸지 않습니다.

관련 정책: POL-044

### 4.9 특별처리 상점

기존에 상점별로 다르게 동작하던 화면을 아래처럼 정리합니다.

| 대상 | 처리 |
| --- | --- |
| 같은 번호를 "옵션코드" 열로 노출하던 상점(약 50곳) | 열 1개만 맨 앞에 둡니다. 전체 상점과 같은 화면이 됩니다. |
| 특별처리 상점(재조합 시 기존 데이터 가져오기 확인창, 관리코드 자동 입력) | 기존 특별처리를 모두 그대로 유지합니다. 재조합하면 기존 확인창이 기존처럼 뜨고 4.4 재조합 확인창은 적용하지 않습니다. 옵션코드는 기존 확인창에서 고른 결과에 따른 기존 번호를 그대로 따릅니다. 관리코드도 기존대로 자동 입력하며, 옵션코드는 관리코드와 별도로 표시합니다. |
| 개별옵션 관리코드 노출 상점(16곳) | 옵션코드를 맨 앞 열에 두고 관리코드는 기존 위치에 둡니다. |
| 상점 전용 "옵션코드" 항목이 있는 상점(세일·덴탈·BDS) | 검색 조건 "옵션코드"는 메이크샵 옵션코드로 찾습니다. |

관련 정책: POL-047, POL-048

### 4.10 오류 및 예외

저장이 실패하거나 판단할 수 없는 경우의 처리입니다.

| 상황 | 처리 |
| --- | --- |
| 저장 결과에 같은 조합·같은 옵션값이 새로 중복됨 | 저장 오류로 처리하고 기존 옵션코드를 바꾸지 않습니다. |
| 저장이 실패하거나 저장 전에 닫음 | 옵션코드와 가장 큰 번호를 바꾸지 않습니다. |
| 번호 부여가 실패함 | 저장 성공으로 안내하지 않습니다. 옵션코드가 없거나 잘못 연결된 옵션이 저장된 상태로 남지 않게 합니다. |

관련 정책: POL-045, POL-046

## 5. 고객 영향 및 안내

운영자와 구매자에게 달라지는 점입니다.

- 구매자 화면은 바뀌지 않습니다.
- 운영자는 옵션 팝업, 상품 수정 화면, 옵션별 재고 수정 팝업에서 옵션코드를 확인할 수 있습니다. 옵션코드는 수정할 수 없습니다.
- 운영자는 전체 상품 관리, 삭제 상품 조회, 재고 일괄 관리에서 옵션코드로 상품을 검색할 수 있습니다.
- 재조합할 때 확인창이 바뀝니다. [초기화]를 고르면 지금과 같게 처리됩니다. 특별처리 상점은 지금 쓰는 확인창이 그대로 뜹니다.
- 기본옵션·개별옵션의 옵션값 이름을 바꾸면 그 옵션은 새 옵션코드를 받습니다.
- 기존 관리코드와 기존 기능은 그대로 동작합니다.
