# 묶음상품 엑셀 업로드 등록/수정 — PRD 분석 · 문제 정의 · 해결 방향

이 문서는 요구사항·AS-IS 분석서(Confluence)와 기획 하위 작업(Jira 기획 하위 작업)을 분석해 문제를 정의하고, 해결 방향과 검토 포인트(R-01~R-10)·기획 확인사항(Q-01~Q-05)의 검토 결과를 정리한 문서입니다. 구현 방식은 개발 판단 영역(6장)으로 넘기며, 정책서(05_Policy)와 사양 정의서는 이 문서를 기준으로 작성합니다.

## 1. PRD 분석

## 2. 문제 정의

### 2-1. AS-IS

| 순서 | 현재 처리 | 한계 |
|---|---|---|
| 1 | 일반 판매상품은 엑셀 업로드로 일괄 등록·수정합니다(엑셀 → 임시테이블 → 상품 등록 → 큐). | 묶음상품은 업로드 대상이 아닙니다. |
| 2 | 업로드 결과는 외부 excel 서버의 업로드 내역 화면에서 확인합니다. | 핵심 파싱이 외부 서버에 있습니다. |
| 3 | 묶음상품 가격이 바뀌면 묶음상품 수정 화면에서 건별로 수기 수정합니다. | 대량·빈번한 변경에 맞지 않습니다. |
| 4 | 상품 세부 정보(가격) 일괄관리 메뉴로 일부만 수정합니다. | 묶음상품 수정에 적합하지 않습니다. |
| 5 | 기존 상품을 엑셀로 수정하면 변경된 필드만이 아니라 엑셀에 담긴 전체 필드 값으로 상품정보를 다시 갱신합니다. 선택 입력 필드가 공란이면 기존값이 유지되지 않습니다. | [확정] 개발 담당자 확인 — 묶음상품도 같은 방식을 따릅니다(4-4). |

### 2-2. 문제

| ID | 문제 | 영향 |
|---|---|---|
| PROB-001 | 묶음상품은 엑셀로 등록·수정할 수 없습니다. | 수기 수정 공수가 크고 가격 반영이 누락될 위험이 있습니다. |
| PROB-002 | 다른 일괄관리 메뉴로도 묶음상품을 대량 처리하기 어렵습니다. | 묶음상품 비중이 커질수록 운영 부담이 늘어납니다. |

### 2-3. 원인 — 현행 엑셀 양식 분석 결과

| 원인 | 양식에서 확인한 사실 | 상태 |
|---|---|---|
| 상품 유형을 구분하는 값이 없습니다. | 66개 컬럼 중 일반상품과 묶음상품을 구분하는 컬럼이 없습니다. 지금까지 엑셀은 일반상품만 다뤘기 때문입니다. | [확정] |
| 묶음상품 전용 데이터를 담을 컬럼이 없습니다. | 구성상품, 묶음수량 컬럼이 없습니다. | [확정] |
| 공통 필드는 이미 대부분 있습니다. | 상품명·판매가격·소비자가격·구매원가·가격대체문구·적립금 등 묶음상품 수정 요청 항목 대부분이 기존 컬럼에 있습니다. | [확정] |

**문제 정의 요약:** 묶음상품을 엑셀로 다룰 수 없는 이유는 공통 필드가 부족해서가 아닙니다. ① 행이 묶음상품인지 판별할 기준이 없고, ② 묶음상품의 필수 구성 정보(구성상품·묶음수량)를 담을 컬럼이 없기 때문입니다.

### 4-3. 행 처리 흐름 [확정]

```
엑셀 업로드
 └ 행별 판별
    ├ product_uid 공란 (신규 등록)
    │   ├ 67·68 둘 다 공란 → 일반상품 등록 (현행과 동일)
    │   ├ 67·68 둘 다 입력 → 필수값·구성상품 검증 → 묶음상품 등록
    │   └ 67·68 중 하나만 입력 → 오류
    └ product_uid 입력 (기존 상품 수정) → 기존 상품 유형 조회 후 유지
        ├ 기존 = 일반상품 → 67·68 중 하나라도 입력 → 오류 (Q-01, 묶음상품 전환 불가)
        │                  67·68 둘 다 공란 → 일반상품 전체 필드 갱신 (현행과 동일)
        └ 기존 = 묶음상품 → 67·68 필수 검증 → 공통 필드 + 구성정보 전체 갱신
                              (67·68 중 하나라도 공란 → 필수값 누락 오류, 일반상품 전환 불가)
 └ 묶음상품 행: 필수값 = 상품명(4)·판매가격(32, 0원 허용)·상품진열여부(42)·67·68(수량 0 허용)
               옵션 필수 검증(16번 opt_use 등) 생략 — 일반상품 행은 기존 옵션 검증 유지
               옵션 컬럼(6~31)·stock(33)·sell_accept(41) 입력값은 오류 없이 무시
 └ 필수값 검증에 실패한 상품은 최종 저장하지 않음
```

| Q-02 | 묶음상품의 판매가격 필수 여부 | **필수 (0원 허용)** | 판매가격 공란은 오류, 0원 입력은 허용해 0원 저장, 0원 초과는 입력값 그대로 저장합니다. 소비자가격·구입원가 공란은 허용하고 0원으로 저장합니다. "판매가 공란 = 0원" 규칙은 폐기합니다. |
| Q-03 | 상품진열여부·판매가능여부 | **진열여부 반영 / 판매가능여부 무시** | 상품진열여부는 필수이며 묶음상품 자체 설정값으로 저장합니다(공란 오류). 판매가능여부는 구성상품 상태 기준으로 산정하므로 Y·N·공란 모두 오류 없이 무시합니다. |
| Q-04 | 31번 `option_display_type` | **옵션 컬럼으로 분류, 무시** | 옵션 관련 컬럼으로 보고 R-06에 따라 입력값을 무시합니다. |
| Q-05 | 모든 묶음수량이 0인 묶음상품 | **허용** | 모든 구성상품의 묶음수량이 0이어도 등록·수정을 허용합니다(P-06 운영 안내 대상). |
