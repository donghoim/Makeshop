## 2. 문제 정의

### 2-1. AS-IS

| 순서 | 현재 처리 | 한계 |
|---|---|---|
| 1 | 일반 판매상품은 엑셀 업로드로 일괄 등록·수정합니다(엑셀 → 임시테이블 → 상품 등록 → 큐). | 묶음상품은 업로드 대상이 아닙니다. |
| 2 | 업로드 결과는 외부 엑셀 처리 서버의 업로드 내역 화면에서 확인합니다. | 핵심 파싱이 외부 서버에 있습니다. |
| 3 | 묶음상품 가격이 바뀌면 묶음상품 수정 화면에서 건별로 수기 수정합니다. | 대량·빈번한 변경에 맞지 않습니다. |
| 4 | 상품 세부 정보(가격) 일괄관리 메뉴로 일부만 수정합니다. | 묶음상품 수정에 적합하지 않습니다. |

### 2-2. 문제

| ID | 문제 | 영향 |
|---|---|---|
| PROB-001 | 묶음상품은 엑셀로 등록·수정할 수 없습니다. | 수기 수정 공수가 크고 가격 반영이 누락될 위험이 있습니다. |
| PROB-002 | 다른 일괄관리 메뉴로도 묶음상품을 대량 처리하기 어렵습니다. | 묶음상품 비중이 커질수록 운영 부담이 늘어납니다. |

### 2-3. 원인 — 현행 엑셀 양식 분석 결과

분석서의 원인 가설(CAUSE-001: 엑셀 파서·양식이 묶음상품 구조를 다루도록 설계되지 않음)을 현행 양식(`sample.xml`)으로 확인했습니다.

| 원인 | 양식에서 확인한 사실 | 상태 |
|---|---|---|
| 상품 유형을 구분하는 값이 없습니다. | 66개 컬럼 중 일반상품과 묶음상품을 구분하는 컬럼이 없습니다. 지금까지 엑셀은 일반상품만 다뤘기 때문입니다. | [확정] |
| 묶음상품 전용 데이터를 담을 컬럼이 없습니다. | 구성상품, 묶음수량 컬럼이 없습니다. | [확정] |
| 공통 필드는 이미 대부분 있습니다. | 상품명·판매가격·소비자가격·구매원가·가격대체문구·적립금 등 묶음상품 수정 요청 항목 대부분이 기존 컬럼에 있습니다. | [확정] |

**문제 정의 요약:** 묶음상품을 엑셀로 다룰 수 없는 이유는 공통 필드가 부족해서가 아닙니다. ① 행이 묶음상품인지 판별할 기준이 없고, ② 묶음상품의 필수 구성 정보(구성상품·묶음수량)를 담을 컬럼이 없기 때문입니다.

## 4. 해결 방향 [제안]

### 4-1. 핵심 방향

일반상품과 묶음상품은 공유하는 필드가 대부분이므로, **별도 양식을 만들지 않고 기존 판매상품 엑셀 양식에 묶음상품 전용 컬럼 2개를 추가**합니다. 두 컬럼에 값이 있으면 그 행을 묶음상품으로 등록합니다.

| 방향 | 내용 | 상태 |
|---|---|---|
| 양식 | 기존 판매상품 엑셀 양식을 그대로 사용하고 묶음상품 전용 컬럼 2개를 추가합니다. | [제안] |
| 신규 컬럼 1 | **구성상품 상품번호** — 구성상품의 상품 고유번호를 콤마(,)로 구분해 입력합니다. 예) `1001,1002,1003` | [제안] |
| 신규 컬럼 2 | **묶음수량** — 구성상품별 수량을 같은 순서로 콤마(,)로 구분해 입력합니다. 예) `1,2,1` | [제안] |
| 유형 판별 | 신규 컬럼 2개에 값이 있는 행은 묶음상품, 비어 있는 행은 일반상품으로 처리합니다. | [제안] |
| 구성상품 필수 | 묶음상품은 등록 화면에서도 구성상품이 필수이므로, 엑셀로 묶음상품을 등록할 때도 구성상품과 묶음수량을 반드시 입력해야 합니다. 구성상품 없이 묶음상품을 등록하는 경우는 허용하지 않습니다. | [확정] 묶음상품 등록 화면 기준 |
| 입력 형식 | 기존 양식의 옵션값(`S,M,L,XL`)·옵션 가격(`100,200,300`)과 같은 콤마 구분 관례를 따릅니다. | [제안] |

**대안 비교**

| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| A. 기존 양식 + 전용 컬럼 2개 추가 (채택안) | 공통 필드를 재사용하고 운영자가 양식 하나만 관리합니다. 파서 변경 범위가 작습니다. | 묶음상품 행에서 옵션 컬럼을 막는 검증이 필요합니다. | **채택 [제안]** |
| B. 상품 유형 컬럼(일반/묶음) 추가 | 유형이 명시적입니다. | 구성상품이 필수라서 유형 값과 구성 컬럼이 중복 정보가 되고, 둘이 어긋나는 경우를 따로 처리해야 합니다. | 미채택 |
| C. 묶음상품 전용 양식 분리 | 컬럼이 단순합니다. | 공통 필드 대부분이 중복되고 양식·파서·결과 화면을 따로 유지해야 합니다. 통합 엑셀 양식 체계와도 멀어집니다. | 미채택 |

### 4-2. 방향 보완이 필요한 검토 포인트

채택안을 정책으로 옮기기 전에 아래 항목의 결정이 필요합니다. 각 항목은 정책서 작성 시 규칙으로 확정합니다.

| No | 검토 포인트 | 왜 필요한가 | 제안 | 상태 |
|---|---|---|---|---|
| R-01 | **수정 행의 유형 판별 기준** | "값이 있으면 묶음상품" 규칙만 쓰면, 기존 묶음상품을 수정하면서 구성 컬럼을 비워 둔 행이 일반상품으로 바뀔 수 있습니다. | `product_uid`가 있는 수정 행은 **기존 상품의 유형을 따릅니다**. 구성 컬럼 값으로 판별하는 것은 `product_uid`가 빈 신규 등록 행에만 적용합니다. 엑셀로 유형을 바꾸는 것(일반↔묶음)은 허용하지 않습니다. | [제안] |
| R-02 | **수정 시 구성 컬럼이 비어 있을 때** | 판매가만 바꾸려는 운영자가 구성 정보까지 다시 입력해야 하면 사용성이 떨어집니다. | 공란이면 기존 구성상품·묶음수량을 유지합니다. 값이 있으면 입력값으로 **전체 교체**합니다. | [제안] |
| R-03 | **두 컬럼의 짝 규칙** | 상품번호와 수량은 순서로 대응하므로 개수가 다르면 해석할 수 없습니다. | 두 컬럼은 둘 다 입력하거나 둘 다 비워야 합니다. 콤마로 나눈 개수가 같아야 하며, 같은 순서끼리 대응합니다. | [제안] |
| R-04 | **구성상품이 옵션 상품일 때** | 상품번호만으로는 구성상품의 어느 옵션(품목)을 묶는지 특정할 수 없습니다. 현재 묶음상품이 구성상품을 옵션 단위로 지정하는지 확인해야 합니다. | 옵션 단위 지정이 필요하면 식별값 체계를 옵션 구조 개선 프로젝트과 함께 정해야 하므로 1차 범위를 따로 판단합니다. | [확인 필요] 개발 |
| R-05 | **구성상품 유효성** | 존재하지 않거나 다른 상점의 상품, 묶음상품을 구성상품으로 넣는 경우를 막아야 합니다. | 구성상품은 같은 상점의 일반상품이어야 합니다. 묶음상품 안에 묶음상품은 넣을 수 없고, 같은 상품번호는 중복 입력할 수 없습니다. 묶음수량은 1 이상의 정수입니다. | [제안] — 묶음상품 등록 화면 규칙과 대조 필요 |

| R-10 | **재고 컬럼** | 묶음상품 재고가 구성상품 재고로 결정된다면 `stock` 입력값은 의미가 없습니다. | 구성상품 재고 기반이면 묶음상품 행의 `stock`은 무시하거나 입력 시 실패 처리합니다. | [확인 필요] 개발 |

### 4-3. 처리 흐름 (안)

```
엑셀 업로드
 └ 행별 판별
    ├ product_uid 있음 (수정)
    │   ├ 기존 상품 = 일반상품 → 구성 컬럼에 값 있으면 실패(유형 변경 불가), 없으면 일반상품 수정
    │   └ 기존 상품 = 묶음상품 → 구성 컬럼 공란이면 구성 유지, 값 있으면 검증 후 전체 교체 + 공통 필드 수정
    └ product_uid 없음 (신규)
        ├ 구성 컬럼 둘 다 공란 → 일반상품 등록 (현행과 동일)
        ├ 구성 컬럼 둘 다 입력 → 구성상품·묶음수량 검증 → 묶음상품 등록
        └ 한쪽만 입력 → 실패 (R-03)
 └ 결과: 행 단위 성공/실패·사유 기록 (부분 성공)
```
