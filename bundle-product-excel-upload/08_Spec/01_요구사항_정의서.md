# 01. 요구사항 정의서 (묶음상품 엑셀 등록·수정)

## 1. 문서 목적

판매상품 엑셀 업로드·다운로드에서 묶음상품을 등록·수정할 수 있도록 하는 요구사항을 정의합니다.
상점의 요청 내용, 현행 기능의 한계, 필요한 기능과 검토 결과를 정리해 정책서·사양정의서의 기준으로 활용합니다.

## 2. 요청 배경 및 목표

### 2.1. 요청 배경

묶음상품은 가격 변동이 잦지만 엑셀 일괄 등록·수정을 지원하지 않아, 운영자가 묶음상품 수정 화면에서 한 건씩 수기로 수정하고 있습니다. 상품 세부 정보(가격) 일괄관리 메뉴도 묶음상품을 대량으로 처리하기에 적합하지 않습니다.
요청 상점는 묶음상품 비중 확대를 앞두고 묶음상품의 판매 정보를 엑셀로 일괄 수정할 수 있도록 요청했습니다.

| 항목 | 내용 |
|---|---|
| 원 요청 Jira | 요구사항·AS-IS 분석 이슈 [요청 상점] 묶음상품 일괄 수정 기능 개선 요청 |
| Epic | 원 요청 이슈 묶음상품 엑셀 일괄 수정 기능 |
| 기획 Task | 기획 에픽 묶음상품 엑셀 일괄 수정 기능 기획 · 기획 하위 작업 요구사항·정책 정리 |
| 요구사항·AS-IS 분석서 | [요구사항·AS-IS 분석서] 요구사항·AS-IS 분석 이슈 |
| 요청 상점 | 대형 운영 상점(VVIP) |
| 적용 대상 | UTF-8 전체 상점 |
| 목표 일정 | 11월 내 제공(원 요청 duedate 2026-11-23) |

### 2.2. 상점이 필요한 결과

- 가격이 바뀐 여러 묶음상품을 엑셀 한 번으로 수정할 수 있어야 합니다.
- 수정 대상은 묶음수량·소비자가·판매가·구입원가·가격대체문구·적립금 등 묶음상품의 판매 정보입니다.
- 현재 등록된 묶음상품을 엑셀로 내려받아 필요한 값을 바꾼 뒤 다시 올릴 수 있어야 합니다.
- 신규 묶음상품도 엑셀로 등록할 수 있어야 합니다.

## 3. 현행 기능 및 해결 과제

### 3.1. 현행 처리

| 순서 | 현재 처리 | 한계 |
|---|---|---|
| 1 | 일반상품은 판매상품 엑셀 업로드로 일괄 등록·수정합니다. | 묶음상품은 업로드 대상이 아닙니다. |
| 2 | 업로드 결과는 업로드 내역 화면에서 확인합니다. | — |
| 3 | 묶음상품 가격이 바뀌면 묶음상품 수정 화면에서 건별로 수정합니다. | 대량·빈번한 변경에 맞지 않습니다. |
| 4 | 기존 상품을 엑셀로 수정하면 바뀐 필드만이 아니라 엑셀에 담긴 전체 필드 값으로 상품정보를 다시 갱신합니다. | 묶음상품도 같은 방식을 따라야 합니다. |

### 3.2. 문제 원인

현행 판매상품 엑셀 양식(66개 컬럼)을 분석한 결과, 묶음상품을 엑셀로 다룰 수 없는 이유는 공통 필드가 부족해서가 아닙니다.

| 원인 | 내용 |
|---|---|
| 상품 유형 판별 기준이 없습니다. | 양식에 일반상품과 묶음상품을 구분하는 값이 없습니다. 지금까지 엑셀은 일반상품만 다뤘습니다. |
| 묶음상품 전용 컬럼이 없습니다. | 묶음상품의 필수 정보인 구성상품과 묶음수량을 담을 컬럼이 없습니다. |
| 공통 필드는 이미 있습니다. | 상품명·판매가격·소비자가격·구매원가·가격대체문구·적립금 등 수정 요청 항목 대부분이 기존 컬럼에 있습니다. |

| REQ-002 | 신규 묶음상품을 엑셀 업로드로 등록할 수 있어야 합니다. | 필수 | 확정 |
| REQ-003 | 묶음상품의 판매 정보(판매가·소비자가·구입원가·가격대체문구·적립금 등)와 구성정보(구성상품·묶음수량)를 엑셀로 수정할 수 있어야 합니다. | 필수 | 확정 |

| REQ-006 | 기존 일반상품 엑셀 업로드·다운로드는 변경 전과 똑같이 동작해야 합니다. | 필수 | 확정 |

## 5. 대표 사용자 시나리오

### 5.1. 상점 운영 시나리오

| 시나리오 | 운영자 행동 | 기대 결과 |
|---|---|---|
| 묶음상품 가격 일괄 수정 | 엑셀 양식관리에서 "묶음 구성상품"·"묶음수량"을 포함한 양식으로 묶음상품을 다운로드 → 판매가·소비자가 수정 → 업로드 | 수정한 묶음상품의 판매 정보가 일괄 반영되고, 구성정보는 그대로 유지됩니다. |
| 묶음 구성 변경 | 다운로드한 파일에서 묶음 구성상품·묶음수량 수정 → 업로드 | 입력한 구성으로 구성정보 전체가 교체됩니다. |
| 신규 묶음상품 등록 | 상품 고유번호를 비우고 상품명·판매가격·상품진열여부·묶음 구성상품·묶음수량 입력 → 업로드 | 묶음상품이 신규 등록됩니다. |
| 오류 확인 | 업로드 결과 확인 | 실패한 행과 사유(필수값 누락, 구성상품 등록 불가 등)를 확인하고 수정 후 다시 업로드합니다. |

### 5.2. 고객 구매 흐름

해당 없음. 엑셀로 등록·수정한 묶음상품은 묶음상품 등록 화면에서 등록한 묶음상품과 같게 쇼핑몰에 노출·판매되며, 구매 흐름은 바뀌지 않습니다.

## 6. 구현 방향 검토

### 6.1. 대안 비교

| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| A. 기존 양식 + 묶음상품 전용 컬럼 2개 추가 | 공통 필드와 기존 처리 방식을 재사용하고, 운영자는 양식 하나만 관리합니다. 변경 범위가 작습니다. | 묶음상품 행에서 옵션·재고 컬럼을 처리하지 않는 분기가 필요합니다. | **채택** |
| B. 상품 유형 컬럼(일반/묶음) 추가 | 유형이 명시적입니다. | 묶음상품은 구성상품이 필수라서 유형 값과 구성 컬럼이 중복 정보가 되고, 둘이 어긋나는 경우를 따로 처리해야 합니다. | 미채택 |
| C. 묶음상품 전용 양식 분리 | 컬럼이 단순합니다. | 공통 필드 대부분이 중복되고 양식·처리·결과 화면을 따로 유지해야 합니다. 통합 엑셀 양식 체계와도 멀어집니다. | 미채택 |

### 6.2. 검토 방향

- 기존 판매상품 엑셀 양식(66개 컬럼)의 순서와 구조를 유지하고, 67번째 "묶음 구성상품", 68번째 "묶음수량" 컬럼을 추가합니다.
- 두 컬럼은 기존 옵션값처럼 한 셀 안에 콤마(`,`)로 구분해 입력하고, 입력 순서대로 1:1로 대응합니다. 예) `101,102,103` / `2,1,1`
- 신규 등록 행은 두 컬럼에 값이 있으면 묶음상품으로 등록합니다. 기존 상품 수정 행은 기존 상품 유형을 유지합니다.
- 기존 일반상품 엑셀과 묶음상품 등록 화면에서 처리하는 사항은 "기존 기능과 동일"하게 처리합니다.

| 포함 | 판매상품 엑셀 업로드 양식에 묶음 구성상품·묶음수량 컬럼 추가, 예제 양식 제공 |

| 제외 | 관련상품·추가구성상품 묶음 설정 기능(관련상품 설정 과제) 자체의 개선 |
| 제외 | 일반상품의 기존 엑셀 검증·저장 정책 변경 |

## 8. 영향 영역

| 영역 | 영향 | 확인 방법 |
|---|---|---|
| 판매상품 엑셀 업로드 | 묶음상품 처리 분기와 신규 컬럼 2개가 추가됩니다. 일반상품 처리는 바뀌지 않아야 합니다. | 일반상품 업로드 회귀 테스트 |
| 상품 엑셀 다운로드·양식관리 | 선택 항목 2개가 추가됩니다. | 기존 양식 다운로드 회귀 테스트 |
| 묶음상품 등록·수정 화면 | 변경 없음. 엑셀로 저장한 값이 화면에 같게 보여야 합니다. | 업로드 후 화면 대조 |
| 관련상품·추가구성상품 묶음 노출(관련상품 설정 과제) | 변경 없음. 묶음상품을 대량 수정해도 연결·노출이 유지돼야 합니다. | QA 확인 |
| 통합 엑셀 PJ(통합 엑셀 프로젝트) | 파일 형식·파싱 규칙을 통합 엑셀과 맞춥니다. 편입되더라도 이 기능의 판정·검증·저장 규칙은 유지합니다. | 일정 조율 |

## 9. 정책 검토 항목

요구사항 분석 단계에서 검토한 항목과 결과입니다. 상세 규칙은 02. 정책서에 정리했습니다.

| No | 검토 항목 | 결과 |
|---|---|---|
| 1 | 상품 유형 판별 | 상품 고유번호 공란 = 신규 등록, 입력 = 수정. 신규 행은 묶음 전용 컬럼 입력 여부로 유형을 정하고, 수정 행은 기존 유형을 유지합니다. 일반↔묶음 전환은 허용하지 않습니다. |
| 2 | 수정 시 구성 컬럼 공란 | 기존 엑셀이 전체 갱신 방식이므로 묶음상품 수정 시에도 두 컬럼은 필수입니다. 입력값으로 구성정보 전체를 교체합니다. |
| 3 | 두 컬럼 매칭 | 콤마 구분, 순서대로 1:1, 개수 일치. 같은 상품번호 중복 입력 허용, 묶음수량 0 이상 정수(0 허용) |
| 4 | 옵션 상품 구성 | 구성상품은 상품 고유번호로만 지정하고, 구성상품의 기존 옵션 구조를 그대로 사용합니다. |
| 5 | 구성상품 유효성 | 이미 등록된 같은 상점 일반상품만 지정할 수 있으며, 묶음상품 등록 화면과 같은 구성상품 등록 조건을 적용합니다. |
| 6 | 묶음상품 행의 옵션 컬럼 | 입력할 필요가 없고, 값이 있어도 오류 없이 무시합니다. 옵션 필수 검증도 하지 않습니다. |
| 7 | 신규 컬럼 위치 | 67번째 묶음 구성상품, 68번째 묶음수량. 엑셀 양식관리에도 같은 항목을 추가합니다. |
| 8 | CSV 전환 시 콤마 | 별도 구분자를 두지 않고, CSV 적용 시 표준 인용 규칙을 따릅니다. |
| 9 | 가격 저장 | 입력값을 저장합니다. 판매가격은 필수(0원 허용), 소비자가·구입원가는 공란이면 0원입니다. 자동계산 금액은 저장하지 않습니다. |
| 10 | 묶음상품 행의 재고 컬럼 | 입력할 필요가 없고, 값이 있어도 오류 없이 무시합니다. |
| 11 | 진열여부·판매가능여부 | 상품진열여부는 필수이며 입력값을 반영합니다. 판매가능여부는 구성상품 기준으로 산정되므로 입력값을 무시합니다. |
