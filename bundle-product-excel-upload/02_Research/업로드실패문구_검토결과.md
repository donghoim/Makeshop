## 4. 권장 노출 문구

아래는 모두 [제안] 문구이며 새로운 검증 조건을 만들지 않습니다. 중괄호는 설명용 치환값입니다. 실제 화면에는 해당 컬럼명이나 제한값을 표시합니다.

| 발생 조건 | 권장 문구 | 근거 |
|---|---|---|
| 묶음상품 행에서 두 컬럼 중 누락된 컬럼이 있음. 신규 행에서 한쪽만 입력한 경우도 동일 안내 | ‘묶음 구성상품은 필수 입력 필드입니다.’ / ‘묶음수량은 필수 입력 필드입니다.’ | POL-008·010 |
| 두 컬럼 자체가 없는 파일로 기존 묶음상품 수정 | ‘묶음상품을 수정하려면 묶음 구성상품과 묶음수량 컬럼이 포함된 양식을 사용해 주세요.’ | POL-010 |
| 기존 일반상품 수정 행에 두 컬럼 중 하나 이상 입력 | ‘일반상품은 엑셀 업로드로 묶음상품으로 변경할 수 없습니다. 묶음 구성상품과 묶음수량을 비워 주세요.’ | POL-009 |
| 구성상품 번호와 수량의 항목 개수 불일치 | ‘묶음 구성상품과 묶음수량의 개수가 일치하지 않습니다. 같은 개수로 입력해 주세요.’ | POL-021 |
| 콤마 사이 또는 끝에 빈 항목 존재 | ‘{컬럼명}에 입력하지 않은 항목이 있습니다. 콤마로 구분한 각 항목을 입력해 주세요.’ | POL-003 |
| 같은 상점에 없는 구성상품 번호 또는 숫자가 아닌 값 | ‘묶음 구성상품에 사용할 수 없는 상품번호가 있습니다. 같은 상점에 등록된 일반상품의 상품 고유번호를 입력해 주세요.’ | POL-013·018 |
| 구성상품 번호로 묶음상품 지정 | ‘묶음상품은 구성상품으로 등록할 수 없습니다. 일반상품의 상품 고유번호를 입력해 주세요.’ | POL-014 |
| 공급자·하이브리드/DIY·정기배송 전용·분류 미지정 또는 현행 화면 선택 불가 상태 | ‘묶음 구성상품에 등록할 수 없는 상품이 포함되어 있습니다. 묶음상품 등록 화면에서 선택 가능한 상품인지 확인해 주세요.’ | POL-015·017 |
| 구성상품 간 부가세 구분 불일치 | ‘구성상품의 부가세 구분이 서로 다릅니다. 부가세 구분이 같은 상품으로 구성해 주세요.’ | POL-016 |
| 현행 구성상품 최대 개수 초과 | ‘묶음 구성상품은 최대 {현행 허용 개수}개까지 입력할 수 있습니다.’ | POL-022 |
| 수량이 음수·소수·숫자가 아닌 값 | ‘묶음수량은 0 이상의 정수로 입력해 주세요.’ | POL-019·020 |

- [제안] 수정 전용 문구는 ‘컬럼이 없는 파일로 기존 묶음상품 수정’처럼 조건상 필요한 경우만 사용합니다. 구성상품 검증 문구는 신규 등록에도 동일하게 적용합니다.
- [확정 기준 유지] 수량 0·전체 수량 0·동일 구성상품 번호 중복은 정상입니다. 묶음상품 행의 옵션·재고·판매가능여부 입력값에는 오류를 추가하지 않습니다.
- [제안] 복수 오류 표시 개수·형식은 현행 방식을 유지합니다. 한 건만 표시하는 방식이라면 상품 유형 판정 → 컬럼/필수값 → 빈 항목·개수·수량 형식 → 구성상품 유효성 순으로 안내하면 후속 판정의 불필요한 오류를 줄일 수 있습니다. 이는 권장 검증 순서이며 확인된 현행 구현은 아닙니다.
- [확정 기준 유지] 검증 실패한 상품은 저장하지 않습니다. 수정 전 상품정보와 구성정보를 유지하며 다른 행의 처리 범위는 현행 방식을 따릅니다.

## 6. Claude 전달 사항

1. 사양 정의서 6장 FR-011·7장에 실제 오류 문구와 기존 POL 참조를 연결합니다. 정책 조건은 14장 기존 POL을 유지합니다.
2. 정책서 4.9절의 사유 표를 ‘발생 조건 / 노출 문구 / 관련 POL’로 보완하고, CS 가이드 5장의 표시 문구를 맞춥니다. 로컬 `08_Jira/00`, `08_Jira/02`, `08_Jira/03`, `05_Policy/01`에도 같은 변경이 필요합니다.
3. QA 담당자는 기존 TC에서 AC-003·005·007·008·009·011·012·016에 대응하는 행을 찾아 문구 기대결과를 보완합니다. 컬럼 없음, 빈 항목, 최대 개수 초과도 확인합니다. 수량 0·중복 구성 허용, 무시 컬럼 입력, 실패 시 기존 상품 보존은 회귀 항목으로 유지합니다. 상세 TC 신규 작성이나 기존 TC 검증은 이번 작업에서 수행하지 않았습니다.

### 개발자 회신 초안

> 한가빈님, 묶음상품 관련 오류도 기존 ‘업로드 실패 내역 보기’ 팝업에 표시하는 방향으로 정리하겠습니다. 필수값 누락은 기존 ‘[필드]는 필수 입력 필드입니다.’ 형식을 재사용하고, 구성상품·수량 검증 오류는 정책서 4.9절의 조건별 문구를 보완하겠습니다. 말씀하신 세트상품(문서상 묶음상품)을 구성상품으로 지정하는 경우도 기존 금지 정책에 포함돼 있어 ‘묶음상품은 구성상품으로 등록할 수 없습니다. 일반상품의 상품 고유번호를 입력해 주세요.’로 안내하면 됩니다. 구성상품·수량 검증 문구는 신규 등록과 수정에 동일하게 적용하고, 기존 공통 항목 오류와 결과 표시 방식은 유지하겠습니다.

별도의 사용자 정책 결정 질문은 없습니다. 위 내용은 검토 권고·회신 초안이며 Jira·Confluence에는 게시하지 않았습니다. 검토 대상 원본과 README는 수정하지 않았습니다.
