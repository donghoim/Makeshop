# 프로토타입 — 분류 검색 필터 관리 개선

## 실행 방법

`index.html`을 브라우저(Chrome 권장)에서 더블클릭으로 직접 열면 동작합니다. 별도 서버 실행이나 빌드 과정이 필요 없습니다. (fetch/CORS 제약을 피하기 위해 목업 데이터는 `src/data/*-data.js`에 JS 전역 변수로 내장되어 있습니다.)

- `index.html` : SCR-FILTER-001 분류 검색 필터 설정 (+ SCR-FILTER-002 생성 팝업, SCR-FILTER-003 수정 팝업 — 모달로 구현)
- `src/html/bulk-management.html` : SCR-FILTER-004 검색 필터 일괄 관리 (+ SCR-FILTER-005 일괄 변경 팝업 — 모달로 구현)

두 화면은 좌측 사이드바 메뉴로 서로 이동할 수 있습니다. (단, 정적 프로토타입이므로 두 페이지 간 데이터는 공유되지 않고 각자 새로고침됩니다 — 실제 서비스에서는 동일 DB를 참조)

## 구현된 인터랙션 (05_Policy, 04_Screen-Spec 기준)

- SCR-FILTER-001 상단에 "필터값에 마우스를 올린 후 수정 아이콘을 클릭하면 명칭을 수정할 수 있습니다." 안내문구를 화면 진입 시부터 상시 노출(닫기 불가)
- 필터값 칩 Hover/Focus 시 수정 아이콘 노출, 더블클릭·Enter 포커스 진입
- 인라인 편집: Enter/확인 아이콘 저장, Esc/취소 아이콘/외부 클릭 취소, 다른 값 편집 진입 시 기존 편집 자동 취소
- 저장 전 검증: 필수값, 최대 30자(필터값 기준. 필터명 자체는 25자), 동일 필터 내 중복값(대소문자·공백 정규화)
- SCR-FILTER-001은 즉시 저장(모의 서버 지연, 성공 시 별도 토스트 없음, 실패 시에만 오류 토스트), SCR-FILTER-002/003은 팝업 내부 임시 상태 후 하단 버튼으로 일괄 저장
- 생성/수정 팝업은 입력·변경 내용 유무와 무관하게 별도 확인 팝업 없이 즉시 닫힘. 필터 전체 삭제만 확인 팝업 노출
- 생성/수정 팝업의 등록·수정 버튼은 필터명+상세값 1개 이상 조건만 충족하면 활성화(노출여부/노출분류는 기본값 존재로 조건에서 제외, 수정 버튼은 변경사항 유무와 무관하게 항상 활성)
- 필터 상세값 드래그 정렬(SCR-FILTER-001), 편집 중 드래그 비활성화
- 검색 필터 일괄 관리: 선택 상품 수 표시, 페이지네이션, 필터 적용 현황 패널
- 일괄 변경 팝업: 작업 유형 4종(상품 적용값 변경/필터값명 수정/필터값 추가/필터값 적용 해제) 전환, 유형별 활성조건, 사전 처리대상 미리보기, 처리결과 토스트, 필터값명 수정 확인 팝업

## 테스트용 매직 값 (QA 시나리오 재현용)

| 위치 | 입력값 | 재현되는 상황 |
|---|---|---|
| SCR-FILTER-001 필터값 인라인 수정 입력창 | `오류유발` | 저장 API 실패 시나리오 (QA-Inline-Edit #17) — 편집 상태 유지 + 오류 토스트 |
| SCR-FILTER-005 필터값명 수정 팝업의 '변경할 명칭' | `충돌테스트` | 동시 수정 충돌 시나리오 (QA-Bulk-Operations #19) — 확인 팝업에서 '수정' 클릭 후 충돌 오류 토스트 |

- 노출 분류 트리의 하위 카테고리 펼치기(+) 상세 동작
