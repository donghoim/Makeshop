>

## 1. 배경

메이크샵 MCP는 메이크샵을 이용하는 개별 입점사 운영자가 자신이 운영하는 상점의 데이터를 외부 AI 서비스에서 조회하기 위해 사용하는 기능입니다. MCP를 통해 외부 AI가 메이크샵 데이터에 접근하게 되면, 특히 회원 관련 개인정보와 결제 관련 민감정보가 의도치 않게 AI 서비스로 전달될 위험이 있고, 여러 상점을 관리하는 계정에서는 상점 간 데이터가 섞일 위험도 있습니다. AI가 대화 과정에서 조회 결과를 그대로 노출하거나 재가공할 수 있으므로, 메이크샵 MCP 서버 단계에서부터 제공 데이터의 범위를 명확히 제한해야 합니다.

## 2. 목적

이 정책의 목적은 다음과 같습니다.

- 상점 간 데이터가 섞이지 않도록 조회 범위를 상점 단위로 격리합니다.
- 사용자가 동의한 최소 범위(Scope) 내에서만 데이터를 제공합니다.
- 회원 개인정보와 결제·인증 관련 민감정보가 어떤 Tool 응답에도 포함되지 않도록 원천적으로 제한합니다.

## 3. 정책

### 3-1. 상점 데이터 분리

인증된 사용자가 접근 권한을 보유한 상점의 데이터만 조회할 수 있도록 하는 기준입니다.

| 항목 | 내용 |
|---|---|
| 격리 기준 | 상점 단위로 데이터를 격리합니다. 한 번의 조회는 항상 하나의 상점 데이터만 대상으로 합니다 |
| 연결 단위 | MCP 연결 1건은 상점 1개에 귀속됩니다. 하나의 계정이 여러 상점을 관리하더라도, 다른 상점 데이터가 필요하면 그 상점에 대한 별도 연결을 새로 생성해야 하며, 기존 연결로 상점을 전환할 수는 없습니다 |
| 검증 시점 | 모든 Tool 호출마다 인증 Token에 귀속된 상점 ID를 확인해, 요청 주체가 그 상점에 대한 접근 권한을 보유하고 있는지 검증합니다 |

### 3-2. 최소 권한(Scope) 원칙

연결 시 사용자가 승인한 권한 범위 내에서만 데이터를 제공하는 원칙입니다.

| Scope | 조회 가능 데이터 |
|---|---|
| `orders.read` | 주문 목록, 주문 건수, 주문 상태, 결제 금액, 결제수단, 취소/반품/교환 상태 |
| `products.read` | 상품명, 상품번호, 판매가, 재고, 판매 상태, 카테고리, 옵션 (상품 마스터 정보만 포함, 판매 실적 제외) |
| `members.read` | 전체 회원 수, 신규 회원 수, 회원 등급, 가입일, 가입 경로 (통계·목록 수준까지만) |
| `analytics.read` | 매출, 주문 건수, 객단가, 취소 금액, 환불 금액, 기간별 증감, 상품별 판매수량·주문건수·매출액, 판매 순위 |

동의하지 않은 Scope에 속한 데이터는 어떤 경우에도 제공하지 않습니다. 상품별 판매수량·매출액 등 실적 데이터는 `products.read`가 아니라 `analytics.read`에 속합니다[확정] — 상품명이 함께 포함되더라도 이는 식별을 위한 부가 정보일 뿐, 값의 본질이 상품 마스터 정보가 아닌 판매 실적(분석 데이터)이기 때문입니다.

### 3-3. 개인정보 제공 최소화

회원 데이터는 기본적으로 통계 중심으로 제공하는 원칙입니다.

| 항목 | 제공 여부(MVP 기준) |
|---|---|
| 이름 | 미제공 |
| 전화번호 | 미제공 |
| 이메일 | 미제공 |
| 주소 | 미제공 |
| 계좌정보 | 미제공 |
| 인증정보 | 미제공 |

예를 들어 "이번 주 신규 회원 몇 명이야?"라는 요청에는 개별 회원 정보를 제공하지 않고 신규 회원 수(집계값)만 반환합니다. 회원 등급별·가입경로별 회원 수처럼 집계 결과라도 대상 인원이 극소수(예: 1~2명)여서 사실상 특정 개인을 식별할 수 있게 되는 경우의 처리 기준은 [확인 필요]입니다.

회원 목록을 반환하는 Tool(개별 회원 단위 Raw 데이터를 다루는 Tool 포함)에서도 위 표의 기준을 그대로 적용해 이름·전화번호·이메일·주소·계좌정보·인증정보는 제공하지 않습니다. **1차 MVP에서는 마스킹을 전혀 사용하지 않고, 이름 계열 필드를 완전히 미제공하는 것으로 확정합니다.** 마스킹(예: "홍*동")은 부분적으로라도 개인을 특정할 단서를 남기므로, 굳이 마스킹 형태를 설계·구현하기보다 처음부터 미제공하는 편이 더 단순하고 안전합니다. 마스킹 옵션은 2단계(실행형 MCP) 이후 특정 회원을 지목해 처리해야 하는 액션(예: 특정 회원 등급 변경)이 생겨 회원을 식별할 최소한의 단서가 불가피해지는 경우에만 재검토합니다. AI가 분석에 필요로 하지 않는 개인정보는 어떤 Tool 응답에도 포함하지 않는 것을 원칙으로 합니다.

회원 단위 Tool(`get_members`)이 검색을 위해 반환하는 내부 식별자 `member_id`는 로그인 ID·이메일 등 실제 인증 자격증명이 아니라, MCP가 회원마다 별도로 발급하는 **불투명(opaque) 내부 식별자**(예: `mem_8f3a2c1d`)입니다. 이 값만으로는 실제 회원을 역으로 식별할 수 없고, 메이크샵 내부 시스템과 연계해야만 특정 회원과 매칭할 수 있으므로, 개인정보 제공 최소화 원칙과 상충하지 않는 것으로 확정합니다. `member_id`는 회원마다 고정된 값을 유지하며(조회할 때마다 값이 바뀌지 않음), 로그인 ID·이메일이 변경되어도 값이 바뀌지 않습니다.

### 3-4. 민감정보 제한

아래 정보는 Scope 동의 여부와 관계없이 어떤 MCP Tool 응답에도 포함하지 않습니다.

| 구분 | 항목 |
|---|---|
| 민감정보 | 비밀번호, 인증키, 결제수단 원문 정보, 계좌정보, 기타 보안 및 인증 데이터 |

결제수단의 "명칭"(예: 네이버페이, 신용카드)은 `orders.read` 범위에서 제공하되, 카드번호·계좌번호 등 "원문 정보"는 제공하지 않습니다. 이 경계가 실제 데이터 필드 단위에서 명확히 분리되는지는 [확인 필요]입니다.

### 3-5. Tool별 개인정보 필드 제공 범위

8개 Tool 각각에 대해, 응답에 개인정보가 포함될 가능성이 있는 필드를 전수 점검하고 제공 여부를 확정합니다.

| Tool | 잠재적 개인정보 필드 | 제공 여부 | 비고 |
|---|---|---|---|
| `get_orders` | 주문자명, 수취인명, 수취인 연락처, 배송지 주소 | 미제공 | 응답 필드에 `order_id`/`order_created_at`/`order_status`/`payment_method`/`order_amount`/`paid_amount` 등 주문 자체의 정보만 포함하며, 주문자·수취인 관련 필드는 처음부터 응답 스키마에 포함하지 않음 |
| `get_order_detail` | 주문자명, 수취인명, 수취인 연락처, 배송지 주소 | 미제공 | 주문 상품 목록(상품명/옵션/수량/금액)은 개인정보가 아니므로 제공. 주문자·수취인 관련 필드는 응답 스키마에 포함하지 않음 |
| `get_order_summary` | 해당 없음 | — | 집계값(건수·금액)만 반환하는 Tool이라 개인정보 필드 자체가 존재하지 않음 |
| `get_sales_summary` | 해당 없음 | — | 집계값(금액)만 반환하는 Tool이라 개인정보 필드 자체가 존재하지 않음 |
| `get_members` | 이름, 전화번호, 이메일, 주소, 생년월일, 성별 등 | 미제공 | `member_id`(불투명 내부 식별자, 3-3 참고), `member_grade`, `joined_at`, `join_channel`만 제공 |
| `get_member_summary` | 해당 없음 | — | 집계값(회원 수)만 반환하는 Tool이라 개인정보 필드 자체가 존재하지 않음 |
| `get_products` | 해당 없음 | — | 상품 데이터에는 개인정보가 포함되지 않음 |
| `get_product_sales` | 해당 없음 | — | 상품별 판매실적 데이터에는 개인정보가 포함되지 않음 |

주문 관련 Tool(`get_orders`, `get_order_detail`)의 "미제공" 필드는 향후 실행형 MCP(Phase 3, `orders.write` 등)에서 배송 관련 작업을 지원하게 되면 재검토가 필요할 수 있으나, 1차 MVP(조회형)에서는 예외 없이 미제공합니다.

### 3-6. 개인정보 처리 동의 [확정 — 개발/보안 리뷰 완료]

MCP 연결을 통해 외부 AI 서비스에 데이터가 제공된다는 사실을 사용자에게 명시적으로 알리는 절차입니다.

| 항목 | 내용 |
|---|---|
| 제공 시점 | MCP를 처음 연결하는 시점에 개인정보 처리 관련 약관·동의 문구를 제공합니다 |
| 고지 내용 | 연결되는 외부 AI 서비스(예: ChatGPT)로 메이크샵 데이터(3-5의 제공 가능 범위 내)가 전달된다는 사실과, 동의한 Scope 범위를 안내합니다 |
| 재동의 | 신규 Scope 추가 시 05_Policy 인증·권한 정책 3-9에 따라 재동의를 받으며, 이때도 동일한 고지 문구를 함께 노출합니다 |
| 문구 확정 | 정확한 약관 문구는 법무 검토 후 확정합니다(§10) |

## 4. 우선순위

아래 원칙은 항상 이 순서로 우선 적용되며, 상위 원칙이 하위 원칙보다 항상 우선합니다.

| 우선순위 | 원칙 |
|---|---|
| 1 | 상점 데이터 분리(3-1) — 다른 상점의 데이터는 어떤 경우에도 노출하지 않습니다 |
| 2 | 민감정보 제한(3-4) — Scope 동의 여부와 무관하게 절대 제공하지 않습니다 |
| 3 | 개인정보 제공 최소화(3-3) — 회원 개별 식별정보는 기본적으로 제공하지 않습니다 |
| 4 | 최소 권한(Scope) 원칙(3-2) — 동의된 Scope 범위 내에서만 데이터를 제공합니다 |

즉 사용자가 Scope에 동의했더라도 민감정보·상점 경계·개인정보 최소화 원칙을 넘어서는 데이터는 제공하지 않습니다.

## 5. 예외

현재 정의된 예외는 없습니다. 운영자 본인이 자신이 관리하는 상점의 개별 회원 개인정보를 직접 조회하고 싶다는 요청이 있을 경우 예외를 둘지 여부는 [확인 필요]입니다.

## 6. 운영

Tool 응답 필드가 신규로 추가되거나 변경될 때마다, 배포 전에 민감정보·개인정보 포함 여부를 검수하는 절차를 둡니다. [확정] 검수는 서비스 기획과 개발이 공동으로 수행하며, 신규·변경 필드마다 3-5 표(Tool별 개인정보 필드 제공 범위)를 기준으로 "제공 가능 필드 목록에 있는가"를 체크리스트 방식으로 확인합니다. 목록에 없는 신규 필드는 배포 전 본 정책에 먼저 추가·검토합니다.

## 7. 권한

본 정책(제공 데이터 범위, 민감정보 기준)을 설정·변경할 수 있는 주체는 [확인 필요]입니다. 서비스 기획과 법무 조직의 협의가 필요합니다.

## 8. 로그

어떤 필드가 실제로 Tool 응답에 포함되어 반환되었는지에 대한 기록은 본 정책이 다루는 범위가 아니며, 별도의 로그·예외처리 정책이 다룹니다. 본 정책은 제공 가능한 데이터 범위 자체를 규정합니다.

## 9. 이력

정책 변경 이력은 본 문서에 직접 기록하지 않습니다. 본 문서에는 항상 최신 확정 내용만 반영합니다.
