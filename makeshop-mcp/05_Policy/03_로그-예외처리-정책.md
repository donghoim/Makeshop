## 1. 배경

MCP를 통한 데이터 접근은 외부 AI가 사용자를 대신해 메이크샵 데이터를 호출하는 새로운 경로입니다. 보안 사고나 오남용이 발생했을 때 원인을 추적할 수 있어야 하고, 인증 만료·권한 부족·조회 실패·조회 범위 초과처럼 정상적으로 발생할 수 있는 예외 상황에서는 AI와 사용자에게 정확한 실패 상태를 전달해야 합니다.

## 2. 목적

이 정책의 목적은 다음과 같습니다.

- MCP를 통한 모든 데이터 접근을 추적 가능하도록 기록합니다.
- 인증 만료, 권한 부족, 조회 실패, 조회 범위 초과 상황에서 임의로 가공된 결과 대신 명확한 실패 상태를 반환합니다.

## 3. 정책

### 3-1. 호출 로그 기록 항목 [확정 — 개발/보안 리뷰 완료]

MCP Tool이 호출될 때마다 아래 항목을 기록합니다. 로그는 **중앙 Audit Log 시스템**에 저장하며, Token 원문과 이름·전화번호 등 직접 식별 개인정보는 어떤 로그 항목에도 남기지 않습니다.

| 항목 | 설명 |
|---|---|
| 상점 ID | 조회 대상 상점 |
| 사용자 ID | 요청을 수행한 메이크샵 사용자 |
| 연결된 AI 서비스 | ChatGPT, Claude 등 호출 주체 AI 서비스 |
| 호출 Tool | 호출된 MCP Tool 이름 |
| 호출 일시 | Tool이 호출된 시각 |
| 조회 데이터 범위 | 요청에 사용된 조건(예: 조회 기간) |
| 처리 결과 | 성공/실패 여부 |

기록 예시는 다음과 같습니다.

| 항목 | 값 |
|---|---|
| 호출 일시 | 2026.09.22 14:30 |
| 호출 Tool | `get_sales_summary` |
| 조회 범위 | 2026.09.15 ~ 2026.09.22 |
| 처리 결과 | Success |

### 3-2. 인증 만료

연결 인증이 만료된 경우의 처리 기준입니다.

| 항목 | 내용 |
|---|---|
| 판정 기준 | 인증 토큰의 유효기간이 지난 경우 |
| 처리 | Tool을 호출하지 않고 AI 서비스에서 재연결(재인증)을 안내하도록 실패 상태를 반환합니다 |

### 3-3. 권한 부족

사용자가 요청한 데이터에 대한 Scope를 보유하지 않은 경우의 처리 기준입니다.

| 항목 | 내용 |
|---|---|
| 판정 기준 | 호출하려는 Tool이 속한 Scope에 사용자가 동의하지 않은 경우 |
| 처리 | 해당 데이터를 제공하지 않고, 권한이 없다는 안내 메시지를 반환합니다 |
| 안내 문구 예시 | "회원 정보를 조회할 수 있는 권한이 연결되어 있지 않습니다." |
| 다국어 지원 | 1차 MVP는 한국어 안내 문구만 제공합니다. 다국어 지원은 범위 외입니다 |

### 3-4. 데이터 조회 실패

메이크샵 API 또는 내부 데이터 서비스 호출에 실패한 경우의 처리 기준입니다.

| 항목 | 내용 |
|---|---|
| 판정 기준 | 메이크샵 API·내부 데이터 서비스 호출이 정상 응답을 반환하지 못한 경우 |
| 처리 | 임의의 결과(추정치, 이전 캐시 값 등)를 생성하지 않고, 조회 실패 상태를 그대로 반환합니다 |

### 3-5. 조회 범위 초과 [확정]

대량 데이터를 요청하는 경우의 처리 기준입니다.

| 항목 | 내용 |
|---|---|
| 판정 기준 | 조회 기간이 최대 조회 기간(집계형 Tool 기준 90일)을 초과하거나, 목록형 Tool의 반환 건수(`limit`)가 최대값(100)을 초과하는 경우 |
| 처리 | 요청을 자동으로 보정(분할 조회, limit 축소 등)하지 않고, 초과 사실을 알리는 실패 상태를 반환합니다 |
| 상한값 | 집계형 Tool(주문/매출/회원/상품 판매실적 현황 조회)의 기본 조회 기간은 미입력 시 최근 7일, 최대 90일입니다. 목록형 Tool(주문/회원/상품/상품 판매실적 목록 조회)의 반환 건수는 기본 50건, 최대 100건입니다 |

### 3-6. Retry [확정]

Tool 호출이 실패했을 때 서버가 자동으로 재시도할지 여부의 기준입니다.

| 항목 | 내용 |
|---|---|
| 기본 원칙 | 모든 실패에 대해 재시도하지 않습니다 |
| 자동 Retry 허용 대상 | 일시적 네트워크 오류, 502, 503, 504, 메이크샵 API·내부 서비스의 일시적 응답 지연 |
| Retry 불가 대상 | 인증 만료(3-2), 권한 부족(3-3), 조회 범위 초과(3-5), Validation 오류, 데이터 없음(3-7) |
| Retry 횟수 | 최대 1회 |
| 처리 위치 | 재시도는 서버 내부에서 처리하며, 사용자·AI에게 중복된 결과가 노출되지 않도록 합니다 |

### 3-7. 조회 결과 없음(NO_DATA) [확정]

조회 조건에 해당하는 데이터가 없는 경우의 처리 기준입니다.

| 항목 | 내용 |
|---|---|
| 판정 기준 | 주문 0건, 신규 회원 0명, 상품 판매실적 없음 등 조회 조건에 해당하는 데이터가 존재하지 않는 경우 |
| 처리 | 시스템 오류나 예외로 처리하지 않고 **정상 응답**으로 처리합니다. 목록형 Tool은 빈 배열, 집계형 Tool은 0 값으로 반환합니다 |
| 원칙 | 조회 결과가 없는 것은 실패가 아니므로, 이 상황을 위한 별도의 실패 상태(Error)를 두지 않습니다 |

## 4. 우선순위

Tool 호출 시 아래 순서로 조건을 확인하며, 앞 단계에서 예외 조건에 해당하면 즉시 해당 예외를 반환하고 뒤 단계로 진행하지 않습니다.

| 순서 | 확인 항목 |
|---|---|
| 1 | 인증 만료 여부(3-2) |
| 2 | 권한(Scope) 보유 여부(3-3) |
| 3 | 조회 범위 초과 여부(3-5) |
| 4 | 실제 데이터 조회 성공 여부(3-4) |

## 5. 예외

여러 예외 조건이 동시에 발생하더라도 위 §4의 확인 순서를 그대로 따르며, 별도의 예외 처리는 두지 않습니다.
