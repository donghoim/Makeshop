# 2026-09-22 논의 — OAuth 인증 아키텍처 결정안

## 논의 배경

이전 논의(2026-09-22_다음단계-논의.md)에서 MCP 연결 단위(상점)와 `get_product_sales`의 Scope(analytics.read)를 확정한 데 이어, 인증/연결 아키텍처 전반에 대한 결정안이 공유되어 이를 검토하고 정책 문서에 반영했습니다.

## 결정 사항 요약

| 항목 | 결정 내용 |
|---|---|
| 기본 인증 방식 | 메이크샵 기존 입점사 관리자 계정 로그인 체계를 재사용. MCP 전용 별도 계정/비밀번호는 만들지 않음 |
| OAuth 구조 | OAuth 2.x Authorization Code 방식(PKCE 적용) 기준. 메이크샵이 Authorization Server 역할 수행 |
| 연결 주체 | 메이크샵 본사/슈퍼어드민이 아닌 개별 입점사 운영자. 본인이 접근 권한을 가진 상점만 연결 가능 |
| 연결 단위 | 상점 단위(연결 1건 = 상점 1개) — 기존 결정 재확인 |
| 인증/연결 Flow | 연결 시작 → 로그인 → 접근 가능 상점 목록 조회 → 상점 1개 선택 → Scope 동의 → Authorization Code 발급 → Access/Refresh Token 발급 → AI 서비스로 복귀 |
| Scope 동의 정책 | 4종 Scope(orders.read/products.read/members.read/analytics.read) 단위 동의. 미동의 Scope의 Tool은 호출 불가 |
| Token 정책 | Access Token(짧은 만료) + Refresh Token(별도 만료 정책) 사용. 구체적 만료시간은 [확인 필요]로 유지 |
| Token 귀속 기준 | 사용자 계정, 상점 ID, 승인된 Scope, 연결된 외부 AI Client — 상점별로 별도 Token 관계 |
| 연결 해제/revoke | 해제 시 해당 상점 연결 건의 Token만 revoke, 다른 상점 연결에는 영향 없음 |
| Scope 변경 | 신규 Scope 추가 시 재동의 필요. 철회 시 해당 Scope의 Tool 즉시 사용 불가. Token 재발급 여부는 [확인 필요] |
| 관리자 권한 | 해당 상점 접근 권한을 가진 관리자만 연결 가능. 대표 관리자/부운영자 허용 범위는 [확인 필요] |
| 세션 정책 | 기존 로그인 세션이 유효해도 MCP Scope 동의는 항상 별도로 진행. 로그인 상태와 MCP 연결 권한은 별도 개념 |
| 보안 기본 원칙 | HTTPS 필수, Authorization Code 1회성, PKCE 기본 적용, Token 원문 미노출, 탈취 의심 시 즉시 revoke, 매 호출마다 Token/상점ID/Scope 검증 |

## 계속 [확인 필요]로 유지되는 항목

- Access Token 만료시간
- Refresh Token 만료시간
- 대표 관리자/부운영자 연결 허용 범위
- Scope 변경 시 Token 재발급 정책
- 기존 인증 서버 재사용 방식의 기술 구조
