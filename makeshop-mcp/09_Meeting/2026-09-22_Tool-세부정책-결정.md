# 2026-09-22 논의 — MCP Tool 세부 정책 결정안

## 논의 배경

OAuth 인증 아키텍처 결정(2026-09-22_OAuth-인증-아키텍처-결정.md)에 이어, 06_Data-API에 남아 있던 Tool 세부 정책 Open Issue(Timezone, 기간 기준, 매출 정의, Tool 책임 분리, limit/Pagination/정렬/검색어, Timeout/Retry/Error 코드, NO_DATA, AI 분석 책임 범위)에 대한 결정안이 공유되어 검토·반영했습니다.

## 결정 사항 요약

| 항목 | 결정 내용 |
|---|---|
| Timezone | 상점 설정 Timezone 우선, 기본값 `Asia/Seoul`. 자연어 기간 해석도 동일 기준 |
| 기간 파라미터 | `start_date`/`end_date` 포함 기준, 역전 시 오류, 기간 미입력 Tool은 임의 전체기간 조회 금지 |
| 주문 조회 기준일 | 주문 생성일(`order_created_at`)로 통일 (결제일 등은 후속 확장 가능) |
| 매출 정의 | `gross_sales`/`discount_amount`/`canceled_amount`/`refunded_amount`/`net_sales` 5개 필드로 구분. "매출" 단독 언급 시 `net_sales` 기준. 정확한 산식은 [확인 필요] |
| 배송비/포인트 | 기본 매출 지표는 상품 기준, 배송비 포함 결제총액은 별도 필드로 제공. 포인트·적립금 반영 방식은 [확인 필요] |
| get_orders vs get_order_summary | 목록/조건 조회는 get_orders, 집계 조회는 get_order_summary |
| get_products vs get_product_sales | 마스터 정보는 get_products(products.read), 판매실적은 get_product_sales(analytics.read) — 기존 결정 재확인 |
| 기본/최대 조회 기간 | 집계형 Tool 4종: 기본 7일, 최대 90일(초과 시 분할 없이 오류) |
| limit | 목록형 Tool 4종: 기본 50, 최대 100(초과 시 자동 보정 없이 오류) |
| Pagination | Cursor 기반(`items`/`next_cursor`/`has_more`). 첫 호출은 cursor 없음 |
| 정렬 | Tool별 기본 정렬 고정(get_orders: order_created_at DESC 등), sort_by/sort_order 확장 가능 |
| 검색어 | Tool별 검색 대상 필드 제한(get_products: 상품명/번호, get_members: 회원ID 등, get_orders: 주문번호 등). 개인정보 기반 검색 미제공 |
| 개인정보 반환 | 이름 마스킹/미제공, 전화번호·이메일·주소·계좌·인증정보 미제공. 필요하지 않은 개인정보는 응답에 미포함 |
| Timeout | 일반 조회 Tool 10초, 집계/분석형 Tool 15초 |
| Retry | 일시적 네트워크/5xx/Upstream Timeout만 서버 내부 최대 1회. 인증/권한/Validation/범위초과/데이터없음은 재시도 안 함 |
| Error 코드 | AUTH_REQUIRED/TOKEN_EXPIRED/INVALID_TOKEN/PERMISSION_DENIED/INVALID_SCOPE/INVALID_PARAMETER/DATE_RANGE_INVALID/DATE_RANGE_EXCEEDED/LIMIT_EXCEEDED/RESOURCE_NOT_FOUND/RATE_LIMITED/UPSTREAM_TIMEOUT/INTERNAL_ERROR. Error 응답은 code/message/retryable/request_id 포함 |
| NO_DATA | Error 코드로 사용하지 않고 정상 빈 응답(빈 배열/0 값)으로 처리 |
| Rate Limit | 사용자/상점/AI Client 단위 적용, 초과 시 RATE_LIMITED. 구체 수치는 [확인 필요] |
| AI 분석 책임 범위 | MCP는 데이터·집계값 제공까지 담당하고 자연어 해석 문장은 생성하지 않음. 해석·분석은 AI Client 담당 |

## 계속 [확인 필요]로 유지되는 항목

- 메이크샵 내부 공식 매출 산식과 `net_sales` 최종 정의
- 배송비 포함 여부(정확한 산정 기준)
- 포인트/적립금/예치금 매출 반영 방식
- 부분취소/부분환불의 내부 집계 기준
- 실제 인프라 기준 Rate Limit 수치
- 기존 API가 Cursor Pagination을 지원하지 않을 경우의 내부 구현 방식
- 회원ID 등 검색용 식별자 반환이 개인정보 최소화 원칙과 상충하지 않는지
