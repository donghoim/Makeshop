# MakeShop MCP — 개발/보안 리뷰 요청

> **리뷰 완료 (2026-09-22). 전체 상태: 수정 후 승인.** 결과는 §8을 참고하십시오. 반영된 정책 문서: `05_Policy/01_인증-권한-정책.md`, `05_Policy/02_개인정보-보안-정책.md`, `05_Policy/03_로그-예외처리-정책.md`, `06_Data-API/MCP-Tools-Definition.md`.

## 1) 리뷰 목적

- MakeShop MCP MVP 서비스 기획안의 구현 가능성 검토
- 기존 MakeShop 인증/API/데이터 구조와의 정합성 확인
- 보안 및 개인정보 정책 검토
- 현재 `[제안]` 상태의 수치/정책 최종 확정

## 2) 서비스 핵심 구조

```
GPT 등 MCP Client
  ↓
MakeShop MCP Server
  ↓
OAuth 인증 / Scope 검증
  ↓
연결된 상점 식별
  ↓
MakeShop 내부 API / 데이터 조회
  ↓
MCP Tool Response
  ↓
AI가 사용자에게 결과 제공
```

## 3) 현재 확정된 주요 정책

| 구분 | 내용 |
|---|---|
| 연결 주체 | 메이크샵 개별 입점사 운영자(본사/슈퍼어드민 아님) |
| 연결 단위 | 상점 단위(연결 1건 = 상점 1개) |
| MVP 연결 권한 | 대표 관리자만 (개발/보안 리뷰 승인) |
| Scope 4종 | `orders.read`, `products.read`, `members.read`, `analytics.read` |
| 서비스 범위 | 조회형 MCP만 MVP 제공(분석형·실행형은 후속 단계) |
| 개인정보 원칙 | 최소 제공 — 이름/전화번호/이메일/주소 등 직접 식별정보 미제공 |
| 회원 식별자 | `member_id`는 불투명 내부 식별자(로그인ID/이메일 아님) |
| Tool 구성 | 8종(`get_orders`/`get_order_detail`/`get_order_summary`/`get_sales_summary`/`get_members`/`get_member_summary`/`get_products`/`get_product_sales`) |
| 조회 기간 | 집계형 Tool 4종 최대 90일 |
| 목록 건수 | 기본 limit 50 / 최대 100 |
| Pagination | Cursor 기반 |
| 시간 기준 | 상점 설정 Timezone 우선(기본 `Asia/Seoul`) |
| 감사 로그 | Tool 호출 로그 저장(상점ID/사용자ID/AI서비스/Tool/일시/범위/결과) |
| 연결 해제 | 해제 시 해당 상점 연결 건의 Token만 revoke |

## 4) 개발팀 확인 필요 사항

기획에서 임의로 구현 방식을 확정하지 않고, 아래 항목을 개발팀 검토 대상으로 정리합니다.

### 인증

- 기존 MakeShop 로그인 인증 체계 재사용 가능 여부
- OAuth Authorization Server 신규 구현 필요 여부
- Authorization Code + PKCE 구조 적용 가능 여부
- 기존 인증/세션 시스템과 MCP OAuth 연결 방식
- 상점 목록 조회 및 상점 권한 확인 API 존재 여부

### Token

- Access Token 1시간 적용 가능 여부
- Refresh Token Idle 90일 / 절대 1년 적용 가능 여부
- Refresh Token Rotation 지원 가능 여부
- Token 재사용 탐지 구현 가능 여부
- revoke 처리 구조

### MCP Server

- 별도 MCP Server 구축 방식
- 기존 MakeShop API Gateway 또는 내부 API 활용 가능 여부
- Tool 호출 시 상점 컨텍스트 전달 방식
- Tool별 Scope 검증 위치
- 호출 로그 저장 위치

### Data/API

- Tool 8종 구현 시 기존 API 재사용 가능 여부
- 신규 API가 필요한 Tool 식별
- Cursor Pagination 적용 가능 여부
- 집계성 API 성능 검토
- 90일 조회 제한 적정성
- Timeout 10초/15초 적정성
- Retry 1회 정책 적정성

## 5) 데이터/통계 담당 확인 필요 사항

다음 항목은 실제 MakeShop 운영 통계 기준과 반드시 대조합니다.

- `gross_sales` 정확 정의
- `discount_amount` 포함 범위
- `canceled_amount` 처리 기준
- `refunded_amount` 처리 기준
- `net_sales` 공식
- 배송비 포함 여부
- 쿠폰 할인 처리
- 적립금/포인트/예치금 처리
- 부분취소/부분환불 반영 방식
- 주문 생성일 기준 집계가 기존 통계와 일치하는지 여부

특히 현재 정의한 아래 산식은 **기획 제안안**입니다.

```
net_sales = gross_sales - discount_amount - canceled_amount - refunded_amount
```

실제 MakeShop 내부 집계 기준과 다를 경우 내부 기준을 우선 적용합니다.

## 6) 보안팀 확인 필요 사항

- OAuth 구조 적정성
- Token 저장/전송 정책
- Refresh Token Rotation
- Token 탈취 대응
- Scope 최소권한 원칙
- 상점 간 데이터 격리
- MCP Client별 Token 귀속 방식

- 외부 AI 서비스로 전달 가능한 데이터 범위
- 개인정보 처리 관련 약관/동의 추가 필요 여부

| 항목 | 제안값 | 최종 확정값 |
|---|---|---|

## 8) 리뷰 결과 기록 영역

각 항목은 아래 5개 상태 중 하나로 기록합니다: **확정 / 수정 필요 / 추가 확인 필요 / 구현 불가 / 후속 검토**

**전체 상태: 수정 후 승인** — 아래 3건만 원안에서 수정되었고, 그 외 전 항목은 기획 구조 그대로 승인되었습니다.

1. Refresh Token: Idle 90일/절대 1년 → **Idle 30일/절대 180일**
2. Rate Limit 적용 단위: 상점 단위 → **상점 + MCP Client 단위**
3. Timeout: 일반 10초/집계 15초 → **MVP 10초로 통일**

