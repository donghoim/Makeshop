# Security & Compliance (로그인 보안 강화 · 휴면회원 정책 전환 · 사업자 인증 개선)

메이크샵에서 진행한 보안·컴플라이언스 관련 기능 기획 3건을 한 프로젝트로 묶은 공개본입니다. 세 건은 계기가 달랐지만, 보안·법령 요구를 운영자가 실제로 지킬 수 있는 관리자 기능으로 바꿨다는 점이 같습니다. 3건 모두 배포를 마쳤습니다.

## 배경

| 건 | 계기 | 문제 |
|---|---|---|
| 로그인 보안 강화 (2026) | 해킹 공격 증가, ISMS 대응 | 로그인 로그를 한 건씩만 볼 수 있어 크리덴셜 스터핑 패턴을 알아챌 수 없었고, 보안 기능은 여러 메뉴에 흩어져 있었습니다 |
| 휴면회원 정책 전환 (2023–2024) | 개인정보보호법 개정(개인정보 유효기간제 폐지) | 휴면 분리 의무가 없어졌는데도 관리자 기능은 그 의무를 전제로 동작했습니다 |
| 사업자 인증 개선 (2023) | 판매자 신원 확인 | 신청 경로가 제각각이라 고객센터가 사업자 정보를 수기로 입력했습니다 |

## 설계 원칙

- **위험은 먼저 보이게 하고, 그다음 막는다** — 로그인 보안을 탐지(1차)와 차단(2차)으로 나눠 배포
- **막기보다 절차로 통제한다** — 법령 기준과 충돌하는 휴면 일괄 해제를 금지하지 않고 동의·고지·전환일 제약으로 통제
- **새로 만들기보다 검증된 체계를 재사용한다** — 기존 다운로드 잠금, Google reCAPTCHA, OCR, 국세청 사업자 상태 조회 API
- **편의를 깨지 않는 대체 경로를 둔다** — 캡챠는 상점이 선택, OCR 실패 시 직접 입력, 휴면 회원은 로그인 시 활성 전환

## 주요 결정

| 대안 | 판단 기준 | 결정 |
|---|---|---|
| 개별 로그 조회 vs 공격 패턴 지표화 | 한 건씩 보는 로그로는 동일 IP의 다계정 시도가 보이지 않음 | 기간별·IP별 2개 탭, 동일 IP에서 5개 이상 계정을 시도한 "다중 계정 시도 IP", 성공률·실패율·전기간 대비 증감률 지표. 일반·SNS 로그인 5종의 시도·성공·실패 집계 기준 통일 |
| 흩어진 보안 메뉴 유지 vs "사이트 보안 설정" 단일 체계 | 외부 접근 제어(누가 접속할 수 있는가)와 내부 계정 보호(어떻게 보호할 것인가)는 관심사가 다름 | 접속 관리·보안 설정 2개 탭으로 통합. reCAPTCHA는 상점 키 입력과 연결 검증 후 활성화, 키가 없으면 저장 불가, 기본값 비활성화 |
| 휴면 일괄 해제 거절 vs 통제된 일괄 해제 | 법령 해설 기준(본인 확인 후 전환)과 상점의 일괄 해제 요구가 충돌 | 책임 동의, 약관(30일)·처리방침(7일) 사전 고지 확인, 전환일은 신청일 포함 5일 이후, 같은 전환일 중복 신청 불가, 대상 10만 명 초과 시 수기 처리, 주문서 정보는 복원 제외 |

휴면 기능 사용 여부는 설정 후 60일 동안 다시 바꿀 수 없게 했습니다. 정책이 자주 바뀌면 분리 보관·파기 배치와 휴면 전환 30일 전 사전 고지 일정이 엉킬 수 있기 때문입니다.

## 결과

| 건 | 결과 |
|---|---|
| 로그인 보안 강화 | ISMS 심사 통과. 공격 의심 지표, 로그인 방식 5종 집계 기준, 로그 다운로드 잠금 연동, 사이트 보안 설정 통합, reCAPTCHA 도입 |
| 휴면회원 정책 전환 | 영향 메뉴 11곳 재설계, 상점별 사용 여부 선택, 고지 템플릿(메일·알림톡·SMS), 통제된 일괄 해제까지 3단계 배포 |
| 사업자 인증 개선 | OCR 자동 입력(실패 시 직접 입력), 국세청 상태 조회로 폐업 사업자 저장 차단, 인증 상태 5단계별 수정 범위 정의 |

보안·컴플라이언스 과제라 전환율 같은 운영 지표는 따로 집계하지 않았습니다.
