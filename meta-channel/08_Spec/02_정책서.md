## 2. 변경 사항 요약

### 2.1 한 줄 요약

Meta 비즈니스 연동에서 커머스 계정 연동을 빼고(Shops 관리 탭은 커머스 계정 없이 유지), 상품 전송을 "저장 후 운영자가 직접 전송"하던 방식에서 "상품 피드 반영 시 큐로 자동 전송"하는 방식으로 바꿉니다. 기존 상점의 연동 정보는 이관하며 신규 메뉴에서는 약관부터 재연동합니다.

### 2.2 변경 목적

- 메이크샵 앱 권한으로는 커머스 계정을 받아올 수 없고, 화면에서 커머스 계정 ID를 쓰는 기능도 없어 연동 대상에서 뺍니다.
- 대량 업데이트도 큐에 담아 순차 처리할 수 있으므로, 운영자가 미전송 상품을 골라 다시 보내던 단계를 없앱니다.
- 기존 페이스북 연동 상점의 연동을 끊으면 운영 중인 광고와 전환 추적이 멈추므로, 연동을 유지한 채 새 메뉴로 옮겨 오도록 안내합니다.

## 3. 적용 대상 및 범위

### 적용 대상

- 메이크샵 입점 쇼핑몰(UTF-8, D4, 주문 2.0·통합옵션, 모바일 4.0)
- 관리자: 부가서비스 > 부가서비스 > 채널 > Meta 비즈니스
- 쇼핑몰: 상품 상세, 검색, 장바구니, 관심상품, 주문서, 주문 완료, 회원가입 완료, 외부 주문서(네이버페이 주문형·톡 체크아웃)

### 포함 범위

- FBE 연동·재설정·연결 해제, 자산 정보 조회·상태·바로가기, 도메인 인증 안내
- 카테고리 단위·상품 단위 매칭(GPC·성별·연령대·사용여부)
- 상품 피드 상태 판정, 전송 큐, 상품 변경 자동 동기화, 카탈로그 변경 재동기화
- 광고 계정 정보, 캠페인 성과 요약·목록, 항목 설정, 전환 추적 설정
- Pixel·CAPI 이벤트와 외부 결제 Purchase 서버 전송
- Shops 관리: Instagram Shop 연결 상태 조회, Meta 관리 화면 바로가기
- 기존 페이스북 연동 상점 전환: 연동 정보 이관, 전환 안내 얼럿, 재연동 성공 후 신규 상품 피드 전송 시작

### 제외 및 예외 범위

- Meta 커머스 계정 연동
- 기존 [페이스북 연동] 메뉴의 사용 이벤트 선택 기능
- 기존 정보 삭제·기존 연동 강제 해제
- Shop·판매 채널 생성·설정·삭제(Meta Commerce Manager에서 진행)
- 운영자가 상품을 골라 Meta로 보내는 선택 전송·재전송
- Meta 자산 생성·수정·삭제, 광고 캠페인·소재·예산 관리, 도메인 인증 처리
- Meta에 직접 등록한 상품의 조회·수정·삭제, 카탈로그 전체 삭제 후 재등록
- 광고 성과의 자체 귀속 판단

### 이용 조건

- 상품 피드·광고 관리·Shops 관리는 FBE 연동 완료 후 사용할 수 있습니다.
- CAPI 이벤트는 FBE 연동 완료, Pixel/Dataset 연결, 인증 정상 조건을 모두 충족할 때 전송합니다.

## 4. 상세 정책

### 4.1 FBE 연동

연결 관리 탭의 최초 연동 가이드에서 FBE 연동을 시작합니다. Meta 팝업 안의 단계와 화면은 Meta가 제공하며 메이크샵이 바꿀 수 없습니다.

| 단계 | 처리 주체 | 내용 |
| --- | --- | --- |
| 0. 개인정보 동의 | 메이크샵 | [Facebook Business Extension 시작하기] 클릭 시 동의 팝업을 띄웁니다. 필수 동의 3개(① 메이크샵 개인정보 수집·이용 ② 쇼핑몰 정보 제3자 제공 및 국외 이전 ③ 쇼핑몰 이용자 정보 전송 위탁 확인)를 모두 체크해야 [동의하고 시작하기]가 활성화되고, [전체 동의]는 3개를 한 번에 체크합니다. 동의 이력(동의 일시·약관 버전·동의 운영자 계정·항목별 동의 여부)은 연동 해제 후에도 보존합니다. |
| 1. Facebook 로그인 | Meta 팝업 | 계정 로그인 |
| 2. 비즈니스 선택 | Meta 팝업 | 비즈니스 포트폴리오 선택 또는 생성 |
| 3. 페이지·Instagram 선택 | Meta 팝업 | 페이지 선택·생성, Instagram은 건너뛸 수 있습니다. |
| 4. 데이터 자산 선택 | Meta 팝업 | 픽셀·카탈로그·광고 계정 선택·생성 |
| 5. 권한 동의 | Meta 팝업 | 선택한 자산의 접근·관리 권한을 한 번에 허용합니다. 위저드에서 새로 만든 자산도 같은 권한 범위에 포함됩니다. |
| 6. 연동 완료 | 메이크샵 | 팝업 종료 후 결과를 받아 아래 조건을 검증하고, 충족하면 자산 식별값과 토큰을 저장합니다. |

연동 완료 조건은 아래를 모두 충족하는 것입니다. 서버에서 검증하며, 화면에서 넘어온 값만으로 판단하지 않습니다.

- OAuth와 FBE 설치 완료
- Business Manager, Facebook Page, Meta Pixel/Dataset, Catalog, Ad Account 정보 수신

Instagram Business Account는 선택 자산입니다. 건너뛰어도 연동은 완료되며, 연결 관리에 '미연동'으로 표시하고 [설정]으로 나중에 연결할 수 있습니다. 커머스 계정은 연동 대상이 아니므로 받지도, 저장하지도, 표시하지도 않습니다.

연동이 완료되면 연결 관리 화면을 연동 완료 상태로 바꾸고, 상품 카테고리 매칭 모달을 1회 자동으로 띄웁니다.

관련 정책: POL-001, POL-002, POL-004, POL-005, POL-006

### 4.2 연결 관리

연동된 Meta 자산 정보와 상품 피드·광고 운영 현황을 요약해 보여줍니다. 자산 정보는 조회 전용입니다. FBE 연동 완료 시 저장한 자산 식별값으로 화면에 들어올 때마다 Meta API를 조회해 최신 정보를 보여주며, 메이크샵에서 자산 값을 수정하지 않습니다.

| 자산 | 표시 내용 | 바로가기 |
| --- | --- | --- |
| Facebook Account | 유저명, 이메일 또는 휴대폰번호, '연결됨' 라벨 | 없음 |
| Business Manager | 비즈니스 관리자명 | 비즈니스 관리자 |
| Facebook Page | 페이지명 | 페이지 |
| Meta Pixel | 픽셀 ID: {pixel_id} | 이벤트 관리자 |
| Instagram Business Account | @{username}, 건너뛴 경우 '미연동' | 인스타그램 설정(미연동이면 미노출) |
| Ad Account | 광고 계정명 + 광고 계정 ID | 광고 계정 |

자산마다 상태를 아래 기준으로 판정합니다.

| 상태 | 판정 기준 | 화면 처리 |
| --- | --- | --- |
| 정상 | 자산 조회 성공 | 자산 정보 표시 |
| 미연동 | FBE 응답에 해당 자산 필드가 없음(삭제·건너뜀). 값이 null인지가 아니라 필드가 있는지로 판정합니다. | '미연동' 표시, 바로가기 미노출, [설정]으로 재연동 |
| 확인불가 | 자산은 있으나 조회 실패(권한 부족 코드 200, 토큰 만료, API 오류) | '확인불가' 표시, 권한 재승인·재설정 안내 |

한 자산의 조회가 실패해도 다른 자산은 그대로 표시합니다.

**바로가기**: 새 탭으로 엽니다. Business Manager 기반 URL에는 business_id를 붙이고, 페이지 공개 URL에는 붙이지 않습니다. act= 파라미터에는 act_ 접두어를 뺀 숫자만 넣습니다. URL에 필요한 자산 ID가 없으면 바로가기를 띄우지 않습니다. URL 경로는 Meta가 바꿀 수 있으므로 상수로 관리하고, 적용 전 실제 연동 계정으로 동작을 확인합니다. Meta 로그인 상태와 권한에 따라 Meta 쪽에서 로그인·권한 화면이 나올 수 있으며, 메이크샵은 Meta 화면 진입 결과를 보장하지 않습니다.

| 위치 | 항목 | URL 패턴 |
| --- | --- | --- |
| 연결 관리 | 비즈니스 관리자 | business.facebook.com/settings?business_id={business_id} |
| 연결 관리 | 페이지 | facebook.com/{page_id} |
| 연결 관리 | 이벤트 관리자 | business.facebook.com/events_manager2/list/dataset/{pixel_id}?business_id={business_id} |
| 연결 관리 | 인스타그램 설정 | business.facebook.com/settings/instagram-account-v2s?business_id={business_id} |
| 연결 관리 | 광고 계정 | adsmanager.facebook.com/adsmanager/manage/campaigns?act={ad_account_id}&business_id={business_id} |
| 상품 피드 | 카탈로그 | business.facebook.com/commerce/catalogs/{catalog_id}/products?business_id={business_id} |
| 광고 관리 | 결제 수단 관리 | adsmanager.facebook.com/adsmanager/manage/billing_payments?act={ad_account_id}&business_id={business_id} |
| 광고 관리 | 계정 상태 확인 | adsmanager.facebook.com/adsmanager/manage/accounts?act={ad_account_id}&business_id={business_id} |

**[설정]**: Meta 팝업을 다시 실행해 비즈니스 포트폴리오·페이지·Instagram·카탈로그·광고 계정·픽셀을 바꿀 수 있습니다. 완료되면 바뀐 식별값을 저장하고 자산 영역을 다시 조회합니다. 재설정을 중간에 닫으면 기존 연결을 유지합니다. 일반 재설정은 최신 동의 이력이 있으면 동의를 생략합니다. 전환 대상의 신규 재연동은 약관부터 시작합니다.

**카탈로그 변경**: 재설정으로 카탈로그가 바뀌면, 메이크샵에 저장된 상품 피드 상태와 전송 정보는 이전 카탈로그 기준이므로 초기화합니다. 이전에 연결했던 카탈로그로 되돌아가는 경우도 같습니다. 초기화한 상품 중 전송 조건을 충족하는 상품은 반영대기로 바꿔 큐에 다시 넣고 새 카탈로그로 전송합니다. 카탈로그에 기존 상품이 남아 있을 수 있으므로 UPDATE(없으면 생성) 방식으로 보내며, retailer_id는 카탈로그와 관계없이 같은 값을 유지해 중복 등록을 막습니다.

| 해제 성공 | 미연동으로 바꾸고 최초 연동 가이드로 돌아갑니다. 상품 피드 동기화, 광고 계정 조회, Pixel·CAPI 서버 전송을 중단합니다. |
| 이미 해제됨 | 해제 목적이 달성된 것으로 보고 정상 처리합니다. |
| 일부 자산이 Meta에서 삭제됨 | FBE 설치가 유효하면 정상 해제합니다. |
| 통신·서버 오류 | 연동 상태를 유지하고 얼럿 "연결 해제에 실패했습니다. 잠시 후 다시 시도해 주세요." |
| 인증·권한 오류 | 연동 상태를 유지하고 얼럿 "연결 해제 권한이 만료되었습니다. 다시 로그인 후 시도해 주세요." |

**도메인 인증 안내**: 도메인 인증은 운영자가 Meta 비즈니스 관리자에서 직접 진행합니다. 메이크샵은 인증 여부를 내부적으로 조회해, 인증되지 않은 경우에만 안내 영역과 바로가기(business.facebook.com/settings/owned-domains)를 띄웁니다. 인증 여부를 별도 상태값으로 보여주지 않습니다.

**상품 피드 요약**: 상태별 건수를 비율 바와 범례로 보여주고 총 상품 수와 최근 업데이트 일시를 함께 표시합니다. [상품 카테고리 매칭] 버튼으로 카테고리 매칭 모달을 엽니다.

**광고 요약**: 연동된 광고 계정명을 보여주고 광고 계정 바로가기를 제공합니다.

관련 정책: POL-007, POL-008, POL-009, POL-010, POL-011, POL-012, POL-013, POL-014, POL-015, POL-016, POL-017, POL-018, POL-057

### 4.3 미연동 상태의 상품 피드·광고 관리·Shops 관리

연동하지 않은 상점이 상품 피드, 광고 관리, Shops 관리 탭에 들어오면 기능 대신 안내 카드를 보여줍니다.

- 안내 문구: "비즈니스 자산 연동 후 광고 관리를 사용할 수 있습니다." (상품 피드·Shops 관리는 화면설계서 문구)
- [비즈니스 자산 설정하기]를 누르면 연결 관리 탭으로 이동하고, 이동 직후 개인정보 동의 팝업을 자동으로 띄웁니다.

관련 정책: POL-019, POL-085

### 4.4 카테고리 매칭

메이크샵 쇼핑몰 카테고리를 Google Product Category(GPC)에 연결합니다. GPC 분류표는 메이크샵 DB에 적재한 데이터를 쓰며 Meta API를 실시간으로 호출하지 않습니다.

**매칭 단위**: 기본분류의 최하위 분류(자식 분류가 없는 분류)에만 GPC를 지정합니다. 단계가 고르지 않으면 각 가지의 마지막 분류가 기준입니다. 화면에는 전체 분류 경로(예: 여성의류 > 아우터 > 코트)로 보여줍니다. 가상분류는 매칭 대상이 아니며, 여러 분류에 속한 상품은 기본분류에 매칭된 GPC를 보냅니다.

| 쇼핑몰 카테고리 | 하위 분류 | 매칭 대상 |
| --- | --- | --- |
| 여성의류 | 있음 | X |
| 여성의류 > 아우터 | 있음 | X |
| 여성의류 > 아우터 > 코트 | 없음 | O |
| 악세서리 > 가방 | 없음 | O |

**카테고리 단위 매칭(연결 관리)**: 연동 직후 자동으로 뜨는 모달 또는 [상품 카테고리 매칭]으로 엽니다.

| 동작 | 처리 |
| --- | --- |
| [상품 피드 반영] | 선택한 GPC를 해당 카테고리 상품마다 저장하고, 전송 조건을 충족한 상품을 큐에 넣어 반영대기로 바꿉니다. 얼럿 "선택한 카테고리가 상품 피드에 반영되었습니다." 후 모달을 닫습니다. |
| [다음에 반영]·X (미매칭 카테고리 있음) | 컨펌 "카테고리를 매칭하지 않은 상품은 피드에서 제외되어 Meta에 노출되지 않습니다. 다음에 반영하시겠습니까?" 확인 시 저장하지 않고 닫으며, 미매칭 상품은 노출제한입니다. |

**상품 단위 매칭(상품 피드)**: [상세]는 해당 상품 1개, [선택 수정]은 체크한 상품 전체가 대상입니다. 기존 값이 있으면 그 값을 기본으로 보여줍니다.

| 항목 | 규칙 |
| --- | --- |
| 사용여부 | ON 피드 사용, OFF 피드 제외(GPC와 관계없이 사용안함) |
| 페이스북 카테고리 | GPC 선택. 상품 단위 값이 카테고리 단위 값보다 우선합니다. |
| 성별 | 최상위 분류가 Apparel & Accessories(의류/액세서리)인 GPC일 때만 활성. 기본 남녀공용(unisex), 선택 남성(male)·여성(female) |
| 연령대 | 의류 GPC일 때만 활성. 기본 전연령(all ages), 선택 성인(adult)·청소년(teen)·어린이(kids)·유아(toddler)·영아(infant)·신생아(newborn) |
| [상품 피드 반영] | 위 값을 상품마다 저장하고, 전송 조건을 충족한 상품을 큐에 넣어 반영대기로 바꿉니다. 얼럿 "선택한 상품이 상품 피드에 반영되었습니다." |

- 선택한 상품이 없으면 얼럿 "선택된 상품이 없습니다."를 띄웁니다.
- 사용여부가 ON인데 페이스북 카테고리가 없으면 반영하지 않고 얼럿을 띄웁니다.
- 의류 GPC에서 성별·연령대를 바꾸지 않으면 기본값을 보냅니다.

**Google·Meta 공통 GPC**: GPC는 채널별 값이 아니라 상품·카테고리 공통값입니다. Google 채널에서 먼저 설정한 값은 Meta에서 기본 선택값으로, Meta에서 먼저 설정한 값은 Google에서 기본 선택값으로 보여줍니다. 값이 없으면 '카테고리를 선택해주세요'로 보여줍니다. 한쪽에서 바꾸면 공통값이 바뀌어 두 채널에 같이 적용됩니다.

관련 정책: POL-044, POL-045, POL-046, POL-047, POL-048, POL-049, POL-050, POL-051, POL-052

### 4.5 상품 피드 상태

상품 피드 목록은 Meta 카탈로그 전체가 아니라 메이크샵 상품을 기준으로 구성합니다. 상품마다 현재 상태 1개를 보여줍니다.

| 상태 | 결정 주체 | 의미 |
| --- | --- | --- |
| 활동중 | Meta | Meta 승인이 끝나 정상 노출 가능한 상태 |
| 검토중 | Meta | Meta 전송 요청이 접수되어 Meta가 검토 중인 상태 |
| 미승인 | Meta | Meta 정책에 따라 노출이 거부된 상태 |
| 노출제한 | 메이크샵 | 카테고리 미매칭 또는 메이크샵 전송 조건 미충족으로 전송이 제한된 상태 |
| 사용안함 | 메이크샵 | 운영자가 사용여부를 OFF로 설정한 상태 |
| 반영대기 | 메이크샵 | 전송 조건을 충족해 전송 큐에 등록되었고 아직 Meta로 전송되기 전인 상태 |

상태는 아래 순서로 판정합니다. 앞 단계에 해당하면 뒤 단계는 보지 않습니다.

| 순서 | 확인 | 해당 시 결과 |
| --- | --- | --- |
| 1 | 사용여부 OFF | 사용안함 |
| 2 | 페이스북 카테고리(GPC) 없음 | 노출제한 |
| 3 | 노출제한 조건 해당(아래 표) | 노출제한 |
| 4 | 전송할 변경이 있음 | 전송 큐 등록 → 반영대기 |
| 5 | Meta 전송 접수 | 검토중 |
| 6 | Meta 처리 결과 | 활동중 또는 미승인 |

**노출제한 사유**

| 조건 | 사유 문구 |
| --- | --- |
| 페이스북 카테고리 미설정 | 페이스북 카테고리가 설정되지 않았습니다. 페이스북 카테고리를 설정해 주세요. |
| 노출상태 '노출 안함' | 노출하지 않은 상품입니다. 상품을 노출함 상태로 변경해 주세요. |
| 판매상태 '판매불가능' | 판매하지 않는 상품입니다. 상품을 판매함 상태로 변경해 주세요. |
| 품절 | 품절 상품입니다. |
| 판매가 0원 | 판매가가 0원입니다. 정상 판매가를 입력해 주세요. |
| 판매가 대체문구 사용 | 판매가에 대체문구가 설정되어 있습니다. 숫자 판매가로 변경해 주세요. |
| 기본 분류 없음(분류 미지정) | 상품 분류가 지정되지 않았습니다. 기본 분류를 설정해 주세요. |
| 상품명에 '개인결' 포함 | 개인결제 상품은 피드에 연동되지 않습니다. |
| 상품 이미지 없음 | 상품 이미지가 없습니다. 이미지를 등록해주세요. |
| 상세설명 없음 | 상품 상세설명이 없습니다. 상세설명을 입력해 주세요. |
| 특정 회원 등급 전용(도매회원 포함) | 특정 회원 등급만 접근할 수 있는 상품입니다. 전체 공개 상품만 피드에 연동됩니다. |
| 로그인 후 가격 노출 | 로그인 후에만 가격이 노출되는 상품입니다. 비로그인 상태에서도 가격이 노출되도록 설정해 주세요. |
| 옵션 조합(에디션) 300개 초과 | 전송 가능한 옵션 에디션 수를 초과한 상품입니다. 옵션 조합 수를 300개 이하로 조정해 주세요. |

에디션 300개 제한은 Meta 한도가 아니라 연동 안정성을 위한 메이크샵 자체 제한입니다. 실제로 Meta에 보내는 옵션 조합 수로 셉니다. 이미 등록된 상품이 300개를 넘으면 이후 신규·수정 전송을 멈추고 노출제한으로 바꿉니다. 다시 300개 이하가 되면 상태를 다시 판정합니다.

**미승인 사유**

| Meta 사유 | 표기 문구 |
| --- | --- |
| COMMERCE_POLICY_VIOLATION | Meta 커머스 정책에 위반되어 거부되었습니다. Meta 커머스 정책을 확인해 주세요. |
| INVALID_PRODUCT_CATEGORY | 상품 카테고리가 올바르지 않습니다. 페이스북 카테고리를 다시 매칭해 주세요. |
| MISSING_PRICE | 가격 정보가 누락되었습니다. 판매가를 확인해 주세요. |
| MISSING_BRAND | 브랜드 정보가 누락되었습니다. 브랜드 값을 등록해 주세요. |
| IMAGE_NOT_ACCESSIBLE | 상품 이미지에 접근할 수 없습니다. 이미지 경로를 확인해 주세요. |
| INVALID_IMAGE | 이미지 형식이 올바르지 않습니다. 이미지를 다시 등록해 주세요. |
| OUT_OF_STOCK | 품절 상태로 Meta에서 노출이 제한되었습니다. 재고를 확인해 주세요. |
| RESTRICTED_PRODUCT | Meta에서 판매가 제한된 상품입니다. Meta 제한 상품 정책을 확인해 주세요. |
| DUPLICATE_ITEM | 중복 상품으로 판단되었습니다. 동일 상품 여부를 확인해 주세요. |
| MISSING_DESCRIPTION | 상품 설명이 누락되었습니다. 상세설명을 입력해 주세요. |

표에 없는 사유 코드는 Meta가 돌려준 사유를 그대로 보여줍니다.

**현황·탭·목록**

- 요약 바와 범례는 6개 상태의 건수를 보여줍니다.
- 상태 탭은 전체·활동중·검토중·미승인·노출제한·사용안함·반영대기이며 탭마다 건수를 보여줍니다. 탭 건수와 목록은 검색·필터 조건을 적용한 결과입니다.
- 반영대기 탭은 조회만 합니다. 운영자가 상품을 골라 보내는 기능은 없고, 큐가 자동으로 보냅니다.
- 목록 컬럼: 체크박스, 상품 정보(이미지·상품명·분류, 분류가 없으면 '분류 미지정'), 연동 상품 수(옵션 단위 카탈로그 item 수), 가격(쇼핑몰 판매가), 페이스북 카테고리(전체 경로, 없으면 '미설정'), 상태, 사유(미승인·노출제한·반영대기), [상세]
- 상품 피드 탭 툴팁에 "메타 상품 연동 이용 시 유의사항"을 안내합니다: 메이크샵 자동 연동을 쓰는 동안 Meta Commerce Manager에서 상품을 직접 등록·수정하지 않도록 하고, 직접 등록한 상품은 메이크샵에 표시되지 않으며, 같은 상품번호로 등록하면 자동 연동 값으로 덮어써질 수 있고, 상품 추가·수정·삭제는 메이크샵 관리자에서 하도록 안내합니다.

관련 정책: POL-020, POL-021, POL-022, POL-023, POL-024, POL-025, POL-026, POL-027, POL-028, POL-029, POL-030, POL-031, POL-032, POL-033, POL-034, POL-038, POL-039, POL-040, POL-041, POL-056, POL-057

### 4.6 상품 전송과 동기화

메이크샵 상품은 Meta가 가져가지 않고 메이크샵이 Meta 카탈로그로 보냅니다. 상품을 보내는 일(전송)과 Meta 처리 결과를 다시 조회해 상태를 바꾸는 일(상태 동기화)을 나눠 처리합니다.

**전송이 생기는 경우**: 아래 경우에 상태를 다시 판정하고, 전송 조건을 충족하면 상품을 전송 큐에 넣어 반영대기로 바꿉니다.

| 발생 | 대상 |
| --- | --- |
| 카테고리 매칭 [상품 피드 반영] | 해당 카테고리 상품 |
| [상세]·[선택 수정] [상품 피드 반영] | 해당 상품 |
| 상품 신규 등록 | 해당 상품 |
| 상품 수정 | 상품명, 판매가, 할인판매가, 재고, 대표이미지, 추가이미지, 상품설명, 진열상태, 판매상태, 옵션 정보가 바뀐 상품. 관리자 상품목록 일괄처리, 상품 일괄관리·할인설정, 재고 일괄관리, 엑셀·OpenAPI 상품 연동, 주문·주문취소에 따른 재고 변동을 포함합니다. |
| 카탈로그 변경 | 전송 조건을 충족하는 전체 상품 |

**큐 처리**

- 큐에서 보낼 때 등록 당시 상태를 그대로 쓰지 않고, 보내는 시점의 최신 상품 정보로 다시 판정합니다. 그사이 사용여부가 OFF가 됐으면 사용안함, 노출제한 조건에 해당하게 됐으면 노출제한으로 바꾸고 보내지 않습니다.
- 같은 상품이 보내기 전에 여러 번 바뀌어도 변경마다 보내지 않고, 보내는 시점의 최신 정보 1건만 보냅니다.
- 카탈로그 호출 한도에 맞춰 나눠 보냅니다: 배치당 최대 5,000건, 카탈로그당 시간당 100 요청(넘으면 429).
- 전송 요청이 접수되면 검토중으로 바꾸고, Meta 처리 결과를 조회해 활동중 또는 미승인으로 바꿉니다. Meta 처리는 비동기이므로 응답의 handles로 처리 상태를 확인합니다.
- 전송이 실패하면 반영대기를 유지하고 다시 보냅니다.

**옵션 변경**

| 상황 | 처리 |
| --- | --- |
| 옵션 추가 | 해당 Variant 신규 등록 |
| 옵션 정보 수정 | 해당 Variant 갱신 |
| 옵션 삭제 | 해당 Variant 삭제(DELETE) |
| 옵션 판매불가·품절 | 판매 가능 여부 갱신 |
| 옵션 조합 300개 초과 | 노출제한, 신규·수정 전송 중단(Meta 호출 없음) |
| 300개 초과에서 300개 이하로 | 상태 재판정 후 반영대기, 현재 유효한 Variant 기준으로 다시 동기화 |

**상품 삭제**: 메이크샵에서 상품을 삭제하면 그 상품의 retailer_id를 지정한 DELETE 요청만 보냅니다. 카탈로그를 비우거나 전송 목록에 없는 item을 한꺼번에 지우지 않습니다.

**전송 데이터**: retailer_id, title, image_link, link, price, availability, google_product_category, gender, age_group. 실제 필수·선택 필드와 형식은 적용 시점의 Meta API 규격을 따릅니다.

관련 정책: POL-035, POL-036, POL-037, POL-038, POL-042, POL-043, POL-055

### 4.7 상품 식별과 관리 범위

카탈로그에는 메이크샵이 자동으로 보낸 상품과 운영자가 Meta에서 직접 등록한 상품이 함께 있을 수 있습니다. 메이크샵은 자기가 보낸 상품에만 소유권을 가집니다.

| 구분 | 출처 | retailer_id | 메이크샵 관리 대상 |
| --- | --- | --- | --- |
| 동기화 상품 | 메이크샵 자동 동기화 | 메이크샵 상품번호(옵션 상품은 옵션 조합 식별값) | O |
| 직접 등록 상품 | 운영자가 Meta에서 수동 등록 | 상품번호와 무관한 임의 값 | X |

- 옵션이 없는 상품은 메이크샵 상품번호를 retailer_id로 씁니다. 옵션 상품은 옵션 조합마다 고유하게 구분되는 값을 씁니다. 접두사·임의값을 붙이지 않고, 같은 retailer_id를 다른 옵션 조합에 다시 쓰지 않습니다.
- 조회·상태 표시·집계·전송·삭제는 메이크샵 retailer_id와 일치하는 item만 대상입니다. 카탈로그 전체를 읽어 목록을 만들지 않고, 상품번호를 키로 조회합니다. 조회 결과 0건은 정상(아직 미연동)이며 오류·재시도 대상이 아닙니다.
- 직접 등록 상품은 목록에 나오지 않고 집계에도 들어가지 않으며, 수정·삭제 요청도 보내지 않습니다.
- 운영자가 Meta에서 직접 등록하면서 retailer_id를 메이크샵 상품번호와 같게 넣으면 메이크샵 상품으로 매칭되고, 전송 시 메이크샵 값으로 덮어씁니다. 이 경우는 상품 피드 탭 툴팁으로 미리 안내합니다.
- 전송은 매칭 대상 item만 UPDATE(없으면 생성)로 보냅니다. 카탈로그 전체를 지우고 다시 올리는 방식(full replace·전체 sync)은 쓰지 않습니다. 직접 등록 상품이 함께 지워지기 때문입니다.

관련 정책: POL-053, POL-054, POL-055, POL-056

### 4.8 광고 관리

연동된 광고 계정의 운영 상태와 캠페인 성과를 보여주고, 외부 결제 전환 추적을 설정합니다. 성과 데이터는 Meta Marketing API 기준이며 Meta 반영까지 최대 1일 이상 걸릴 수 있습니다. 통화는 광고 계정 통화를 따르며 통화 기호는 표시하지 않습니다.

**광고 계정 정보** (접기·펼치기 가능)

| 항목 | 표시 내용 |
| --- | --- |
| 광고 계정명 | 광고 계정명 + 광고 계정 ID (예: neotest17 (act_123456789012345)) |
| 계정 상태 | 활성(광고 집행 가능), 차단(정책 위반 등으로 Meta가 비활성화), 비활성(해지·종료), 미결제(결제 실패 등으로 중단), 펜딩(Meta 검토 중) 중 현재 상태 1개 |
| 이번달 광고 지출 | 이번 달 1일부터 현재까지 지출 합계 |
| 잔여 크레딧 | 선불 계정은 잔여 금액, 후불 계정은 0과 '후불' 표기 |
| 결제 수단 관리·계정 상태 확인 | Meta 광고 관리자 해당 화면 새 탭 |

[설정]은 연결 관리의 [설정]과 같이 Meta 팝업을 다시 실행합니다.

**조회기간·검색**

- 조회기간: 오늘, 어제, 최근 7일, 최근 30일, 이번 달, 직접 설정. 기본값은 어제입니다. 기간을 바꾸면 성과 요약 카드와 캠페인 목록을 다시 조회합니다.
- 직접 설정: 시작일과 종료일을 모두 고르면 조회합니다. 미래 날짜는 고를 수 없고, 종료일은 시작일 이전으로 고를 수 없습니다. 시작일을 바꿔 기존 종료일보다 늦어지면 종료일을 지우고 다시 고르게 합니다.
- 키워드 검색: 캠페인명 부분 일치. 엔터 또는 돋보기 클릭으로 실행합니다.

**성과 요약 카드**: 노출수, 클릭수, CTR, 전환(구매), 광고 지출(하단에 ROAS 병기)의 조회기간 합계와 직전 같은 길이 기간 대비 증감률을 보여줍니다. 증가는 초록 상승 화살표, 감소는 빨강 하락 화살표입니다. ROAS는 배수(x)로 표시하고 3.0x 이상은 초록, 미만은 빨강입니다.

**캠페인 목록**

- 조회기간과 캠페인 운영기간(시작일부터 종료일까지)이 겹치는 캠페인을 보여줍니다. 종료·일시중지 캠페인도 그 기간에 운영 이력이 있으면 포함합니다.
- 기본 정렬은 광고 비용 높은 순입니다. 페이지 번호 없이 무한 스크롤로 더 불러옵니다. 조회 개수(20·30·50·70·100개, 기본 20개)는 한 번에 불러오는 건수이며, 바꾸면 처음부터 다시 조회합니다.
- 금액은 통화 기호 없이 천 단위 콤마로 표시합니다(예: 1,247,500).
- 캠페인 목록은 각 캠페인이 목표로 설정한 전환 이벤트 기준으로 집계됩니다.

| 컬럼 | Meta 값·계산 |
| --- | --- |
| 캠페인명 | campaign_name. 고정 컬럼으로 뺄 수 없습니다. |
| 목표 | objective |
| 시작일시·종료일시 | start_time·stop_time, 종료일 미설정 시 - |
| 노출수·클릭수·도달수·빈도 | impressions·clicks·reach·frequency |
| CPM·CPC·CTR | cpm·cpc·ctr |
| 광고비용 | spend |
| 구매수 | actions의 offsite_conversion.fb_pixel_purchase value |
| 매출 | action_values의 Purchase value |
| 장바구니 추가·결제 시작 | actions의 fb_pixel_add_to_cart·fb_pixel_initiate_checkout value |
| 전환율 | 구매수 ÷ 클릭수 × 100 (메이크샵 계산) |
| CPA | 광고비용 ÷ 구매수 (메이크샵 계산) |
| ROAS | 매출 ÷ 광고비용, 배수 표기 (메이크샵 계산) |

계산식의 분모가 0이면 계산하지 않고 '-'로 표시합니다. 예: 구매수 30, 클릭수 1,000이면 전환율은 3.00%입니다.

**항목 설정**: [항목]을 누르면 컬럼 선택 레이어를 띄웁니다.

- 캠페인명을 뺀 모든 항목을 추가·제외할 수 있습니다. 현재 노출 중인 항목은 '선택한 타이틀', 제외한 항목은 '선택 가능한 타이틀' 목록에 보입니다. 기본 항목을 제외해도 다시 추가할 수 있습니다.
- 선택한 항목의 순서를 바꿀 수 있고, 그 순서가 목록 컬럼 순서가 됩니다.
- [기본값으로 초기화]는 캠페인명·목표·노출수·클릭수·구매수·ROAS·매출·광고비용 순서로 되돌립니다. 초기화만으로는 저장되지 않습니다.
- [저장]을 눌러야 목록에 반영되고, 이후 다시 들어와도 유지됩니다. 저장하지 않고 닫으면 직전 저장값을 유지합니다.
- 항목 설정은 캠페인 목록에만 적용되며 성과 요약 카드에는 영향이 없습니다.

관련 정책: POL-058, POL-059, POL-060, POL-061, POL-062, POL-063, POL-064, POL-065, POL-066, POL-067, POL-068, POL-069, POL-070, POL-071, POL-072

### 4.9 전환 추적 (Pixel·CAPI)

Meta Pixel은 브라우저에서 고객 행동을 보내고, 전환 API(CAPI)는 메이크샵 서버에서 확인한 고객 행동을 Meta 서버로 직접 보냅니다. CAPI는 Pixel을 대체하지 않고 함께 씁니다. 브라우저 환경·쿠키 제한·광고 차단으로 Pixel이 놓치는 이벤트를 보완하기 위함입니다.

**CAPI 전송 조건**: FBE 연동 완료, Pixel/Dataset 연결, 인증·연결 정보 정상을 모두 충족하면 보냅니다. 운영자가 CAPI 전체를 켜고 끄는 설정은 두지 않으며, 연결을 해제하면 전송을 멈춥니다. 이벤트별 사용 여부를 고르는 기능도 제공하지 않습니다. Pixel은 Pixel 연결 상태에 따라 동작합니다.

**대상 이벤트**

| 고객 행동 | Meta 이벤트 | 발생 기준 | 주요 전송 데이터 |
| --- | --- | --- | --- |
| 상품 상세 조회 | ViewContent | 상품 상세 페이지 진입 | 상품 ID, 상품명, 가격, 통화 |
| 상품 검색 | Search | 검색 결과 조회 | 검색어 |
| 장바구니 담기 | AddToCart | 장바구니 추가 성공 | 상품 ID, 수량, 금액, 통화 |
| 관심상품 추가 | AddToWishlist | 관심상품 등록 성공 | 상품 ID, 금액, 통화 |
| 주문서 진입 | InitiateCheckout | 주문서 진입 | 상품 ID, 수량, 주문 예정금액, 통화 |
| 결제정보 입력 | AddPaymentInfo | 결제수단 입력·선택 완료 | 주문 예정금액, 통화 |
| 구매 완료 | Purchase | 구매 완료 기준 충족 | 주문 식별정보, 상품 ID, 수량, 결제금액, 통화 |
| 회원가입 완료 | CompleteRegistration | 회원가입 정상 완료 | 가입 완료 이벤트 정보 |

이벤트는 버튼 클릭이 아니라 메이크샵에서 그 행동이 정상 처리된 것을 확인한 시점에 만듭니다. 실제 적용 이벤트는 메이크샵 서버가 발생 여부와 필요한 데이터를 확인할 수 있는 범위로 한정합니다.

**Purchase 발생 기준**

- 일반 주문: PG 결제는 결제 성공과 주문 완료가 확인된 시점, 무통장입금 등 후입금 결제는 입금 또는 구매 완료로 판단할 수 있는 시점입니다.
- 외부 주문: 네이버페이 주문형·톡 체크아웃 주문의 구매 완료 상태를 메이크샵 서버에서 확인한 시점입니다. 외부 주문서 이동, 결제수단 선택, 구매 버튼 클릭만으로는 만들지 않습니다.

**외부 결제 구매전환 설정**: 광고 관리의 전환 추적 설정은 CAPI 전체 ON/OFF가 아니라 외부 결제수단 Purchase의 서버 전송 여부를 정하는 영역입니다.

| 항목 | 활성화 조건 | 값 | 기본값 |
| --- | --- | --- | --- |
| 네이버페이 구매 전환 | 네이버 연동 설정 > 기본 설정에서 '주문형 네이버페이' 체크 + 공통 인증키 입력 | 사용 / 사용안함 | 사용안함 |
| 톡 체크아웃 구매 전환 | 카카오 연동 설정에서 '톡 체크아웃' 연동 | 사용 / 사용안함 | 사용안함 |

- 활성화 조건을 충족하지 못하면 토글을 비활성으로 둡니다.
- 사용으로 두면 해당 결제수단의 구매 완료 건을 CAPI Purchase로 보냅니다. 결제수단별로 따로 적용하며, custom_data의 payment_method(naver_pay·kakao_checkout)로 구분합니다. 화면에서 결제수단별로 나눠 보여주지는 않습니다.
- [저장]은 전환 추적 설정값만 저장하고 얼럿 "전환 추적 설정이 저장되었습니다."를 띄웁니다.

**중복 제거**: 같은 행동을 Pixel과 CAPI가 각각 보내면 같은 event_name과 event_id를 넣어 Meta가 하나로 처리하게 합니다. Purchase의 event_id는 주문을 고유하게 식별하는 주문 식별값으로 만들고, 외부 결제 주문도 메이크샵 주문 고유값을 씁니다. 장바구니·관심상품처럼 반복되는 이벤트는 발생 건마다 고유한 event_id를 만듭니다. 실제 중복 제거 결과는 Meta 처리 기준을 따릅니다.

**전송 정보**: 이벤트 정보(event_name, event_time, event_id, action_source=website, event_source_url), 사용자 매칭 정보(이메일·전화번호·external_id는 SHA-256 해시, fbp·fbc는 주문 시작 시 저장해 결제 콜백 때 재사용, IP Address·User Agent는 수집·연결 가능한 범위), 이벤트 상세 정보(상품 ID·수량·금액, 구매 금액, 통화, 주문 식별정보). 실제 필수·권장 파라미터는 적용 시점의 Meta CAPI 규격을 따릅니다.

**광고 성과와의 관계**: CAPI로 이벤트를 보냈다고 메이크샵이 광고 전환으로 판단하지 않습니다. 광고 성과 귀속은 Meta가 자체 기준으로 판단하므로 보낸 이벤트가 모두 전환으로 집계되지는 않습니다. 광고 관리의 구매수·매출·ROAS는 메이크샵이 원시 이벤트를 합산한 값이 아니라 Meta Marketing API 집계값입니다.

관련 정책: POL-073, POL-074, POL-075, POL-076, POL-077, POL-078, POL-079, POL-080, POL-081, POL-082

### 4.10 Shops 관리

Shops 관리 탭은 Instagram Shop 연결 상태를 확인하고 Meta 관리 화면으로 이동하는 조회 전용 화면입니다. 메이크샵은 Shop과 판매 채널을 만들거나 바꾸지 않으며, 커머스 계정도 받지 않습니다.

| 영역 | 표시·동작 | 사용하는 값 |
| --- | --- | --- |
| Shops 정보 | [커머스 관리자 바로가기]: 연결된 카탈로그의 상품 화면을 새 탭으로 엽니다. | catalog_id, business_id |
| Instagram Shop | FBE에서 Instagram 계정을 연결했으면 @계정명과 '연결중', 건너뛰었으면 "연결된 계정이 없습니다."와 '미연결'을 표시합니다. | Instagram Business Account |
| Instagram Shop [설정] | Meta Commerce Manager 화면을 새 탭으로 엽니다. | business_id |

- 바로가기에 필요한 ID가 없으면 해당 버튼을 표시하지 않습니다.
- Instagram 계정은 있으나 조회에 실패하면 연결 관리와 같이 '확인불가'로 처리합니다.
- 홈 탭의 Shops 관리 카드는 미연동이면 [설정하기], 연동 완료면 [자세히 보기]를 표시합니다.

관련 정책: POL-011, POL-083, POL-084, POL-085

### 4.11 기존 페이스북 연동 상점 전환

배포 시 기존 FBE 연동 중인 상점은 연동 정보·네이버페이 구매전환 설정·도메인 인증 코드·픽셀 ID를 이관합니다. 기존 연동이 없거나 이미 해제한 상점은 전환 대상이 아닙니다. 사용 이벤트 선택값은 이관하지 않습니다.

| 대상·행동 | 처리 결과 |
|---|---|
| 기존 [페이스북 연동] 메뉴 | 모든 상점에 노출하지 않음 |
| 기존 상점 → Meta 비즈니스 진입(어느 탭이든) | 재연동 안내 얼럿 → [확인] → 연결 관리 탭에서 약관 → Meta 재연동(로그인부터) |
| 같은 메뉴 안 탭 이동 | 얼럿을 반복하지 않음. 재연동 전에는 각 탭에 미연동 안내 |
| 기존 연동이 없는 상점 | 얼럿·팝업 없이 미연동 화면. [Facebook Business Extension 시작하기] 클릭 시 약관부터 최초 연동 |
| 약관 닫기 | 미연동 화면 유지. 새 동의 이력 미저장, Meta 팝업 미실행. 이관 정보·기존 연동 유지 |
| FBE 중단·실패 | 미연동 화면 유지. 이미 저장한 동의 이력·이관 정보 유지. 신규 큐 보류 |
| 닫기·중단 후 Meta 비즈니스 재진입 | 재연동 안내 얼럿 확인 후 약관부터 다시 진행 |
| 재연동 성공 | 기존 정보 갱신(새 연결 추가 아님), 이후 얼럿 미노출, 신규 큐 전송 및 카테고리 매칭 1회 |

얼럿 문구: “페이스북 연동 기능이 Meta 비즈니스로 업그레이드되었습니다. 약관에 동의한 후 연동을 진행해 주세요.”

안내 확인 이력을 따로 저장하지 않으며 재연동 성공으로 전환 완료를 판단합니다. 미연동 표시는 기존 연결 해제를 뜻하지 않습니다. 기존 픽셀·CAPI 등 전송은 유지하고 신규 상품 피드 큐만 성공 전까지 보류합니다. 카탈로그가 바뀌면 카탈로그 변경 재동기화 정책을 적용합니다. 이관 설정은 성공 후 기존 설정 영역에서 사용하며 네이버페이 활성 조건은 유지합니다.

관련 정책: POL-001, POL-086, POL-087, POL-088, POL-089, POL-090, POL-091, POL-092, POL-093, POL-094, POL-095

### 4.12 처리 흐름

**최초 연동과 카테고리 매칭**

1. 채널 > Meta 비즈니스 진입, 연결 관리 최초 연동 가이드 표시
2. [시작하기] → 개인정보 동의 → Meta 팝업에서 자산 선택·권한 동의
3. 필수 자산 5종 검증 후 저장, 연동 완료 화면 전환
4. 카테고리 매칭 모달 자동 노출 → [상품 피드 반영]
5. 매칭값 상품별 저장, 전송 조건 충족 상품 반영대기(큐 등록)
6. 큐 자동 전송 → 검토중 → 활동중 또는 미승인

**상품 등록·수정**

1. 상품 저장
2. 사용여부·GPC·노출제한 조건 재판정
3. 전송 대상이면 큐 등록(반영대기)
4. 큐 전송 시점 최신 정보로 재판정 후 전송 → 검토중
5. Meta 결과 조회 후 활동중 또는 미승인
