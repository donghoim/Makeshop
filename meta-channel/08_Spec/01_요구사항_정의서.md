# [요구사항 정의서] Epic 메타 비즈니스 연동

> Confluence 사내 위키에 게시했습니다(v2, 2026-10-20). 2026-10-19·20 결정(커머스 계정 제외, 반영대기·자동 전송, 상품 피드 반영, Shops 관리 유지)을 반영했습니다. 정책 기준은 사양 정의서 14장입니다.

## 1. 개요

### 1-1. 프로젝트 배경

메이크샵 입점 쇼핑몰 운영자는 Meta(페이스북·인스타그램)로 상품 광고를 하려면 Meta 비즈니스 관리자에서 자산을 하나씩 설정하고 관리해야 합니다.

이 과정에서 쇼핑몰 상품과 Meta 카탈로그 연동, 광고 계정 연결, 전환 이벤트 추적, 광고 성과 확인이 각각 분리되어 있어 운영과 관리가 불편합니다.

Meta가 제공하는 FBE(Facebook Business Extension) 기반 연동을 도입해, 메이크샵 관리자에서 Meta 비즈니스 자산을 연결하고 상품 피드와 광고 성과를 함께 관리할 수 있게 합니다.

### 1-2. 프로젝트 목적

운영자가 외부 관리 도구에 반복해서 들어가지 않고 상품과 광고 운영 정보를 관리할 수 있게 합니다.

| 구분 | 개선 목적 |
| --- | --- |
| 연동 편의성 | FBE로 Meta 비즈니스 자산 일괄 연결 |
| 자산 통합 관리 | Meta 계정과 연결된 자산 정보 조회·관리 |
| 상품 피드 관리 | 메이크샵 상품과 Meta Catalog 연동, 상태 관리, 큐 기반 자동 전송 |
| 카테고리 매칭 | Google Product Category 기반 상품 분류 |
| 광고 성과 관리 | Meta 광고 계정과 캠페인별 성과 통합 조회 |
| 전환 추적 | Meta Pixel과 전환 API(CAPI)로 이벤트 전송 |

## 2. 현황 및 문제점 (AS-IS)

| 구분 | 현황 및 문제점 |
| --- | --- |
| Meta 자산 연결 | 운영자가 Meta에서 필요한 자산을 하나씩 설정해야 해서 연동 과정이 복잡합니다. |
| 연동 정보 관리 | Meta 자산 연결 정보와 상태를 메이크샵에서 한 번에 확인하기 어렵습니다. |
| 상품 카탈로그 | 메이크샵 상품과 Meta Catalog 간 정보 연동을 관리하는 기능이 필요합니다. |
| 상품 분류 | Meta 상품 분류 체계에 맞는 카테고리 매칭과 속성 관리가 필요합니다. |
| 상품 연동 상태 | Meta 심사 결과와 메이크샵 자체 전송 제한 상태를 구분해 관리해야 합니다. |
| 광고 성과 조회 | Meta 광고 관리자에 따로 접속해 캠페인 성과를 확인해야 합니다. |
| 구매 전환 추적 | 브라우저 환경에 영향을 받는 Pixel 외에 서버 기반 전환 추적이 필요합니다. |

기존 서비스에 해당 기능이 전혀 없었다는 뜻이 아니라, 이번 프로젝트에서 해결하려는 운영상의 문제를 중심으로 정리했습니다.

## 3. 개선 방향 (TO-BE)

### 3-1. 핵심 개선 사항

| 구분 | 개선 방향 |
| --- | --- |
| Meta 연동 | FBE로 필수 자산 5종(비즈니스·페이지·픽셀·카탈로그·광고 계정) 일괄 연결, 연동 완료 여부 관리 |
| 연결 관리 | 연동된 비즈니스 자산과 연결 상태를 한 화면에서 조회 |
| 상품 피드 | 메이크샵 상품 기준으로 Meta 연동 상품과 피드 상태 관리 |
| 카테고리 매칭 | 카테고리 단위 일괄 매칭과 상품별 개별 수정, [상품 피드 반영]으로 반영 |
| 상품 동기화 | 카테고리 매칭·상품 등록·수정 시 전송 큐에 등록해 자동 전송(반영대기 → 검토중) |
| 광고 관리 | Meta 광고 계정 정보와 캠페인별 성과 조회 |
| 전환 추적 | Pixel과 CAPI로 고객 행동·구매 이벤트 전송 |
| 연동 해제 | Meta 연결 해제 시 관련 기능 중단, 미연동 상태 전환 |

### 3-2. 설계 기본 원칙

- Meta 원천 데이터 활용: 자산 상태, 상품 심사 결과, 광고 성과는 Meta API 정보를 기준으로 조회합니다.
- 메이크샵 상품 기준 관리: 상품 피드 목록은 메이크샵 상품으로 구성하고, Meta에 직접 등록된 상품은 관리 대상에서 제외합니다.
- 상품 단위 데이터 관리: 카테고리 매칭은 일괄 설정을 지원하되 GPC 값은 상품 단위로 관리합니다.
- 전송과 상태 조회 분리: 상품을 Meta로 보내는 작업과 Meta 처리 결과를 조회하는 작업을 나눕니다.
- 자동 전송: 운영자가 상품을 골라 다시 보내는 단계 없이, 전송 대상은 큐가 순차적으로 보냅니다.
- 기존 데이터 보호: 카탈로그 전체 삭제·재등록 방식을 쓰지 않고 메이크샵 관리 대상 상품만 갱신합니다.
- 외부 시스템 책임 분리: Meta 자산 생성·수정, 광고 집행, 성과 귀속 판단은 Meta의 기능과 정책을 따릅니다.

## 4. 기능별 요구사항 정의

요구사항 ID는 `META-REQ-001` 형식이며, 사양 정의서의 REQ·FR, QA 테스트 케이스와 연결합니다.

### 4-1. Meta 비즈니스 계정 연동

| 요구사항 ID | 요구사항명 | 요구사항 정의 |
| --- | --- | --- |
| META-REQ-001 | Meta 연동 진입 | Meta 비즈니스 메뉴 진입 시 FBE 연동 여부에 따라 최초 가이드 또는 연결 완료 화면 제공 |
| META-REQ-002 | 개인정보 동의 | FBE 시작 전 필수 동의 3개(수집·이용, 쇼핑몰 정보 제3자 제공·국외 이전, 이용자 정보 전송 위탁 확인)와 전체 동의 처리, 동의 이력이 최신 기준 버전이 아닌 연동 상점 재동의 |
| META-REQ-003 | FBE 위저드 실행 | Meta Embedded Signup으로 로그인·자산 선택·권한 동의 진행 |
| META-REQ-004 | 필수 자산 검증 | Business Manager·Facebook Page·Pixel/Dataset·Catalog·Ad Account 5종 수신 여부 확인 |
| META-REQ-005 | 연동 정보 저장 | FBE 설치 결과, 자산 식별 정보, 서버 연동 인증 정보 저장 |
| META-REQ-006 | 연동 완료 처리 | 필수 조건 충족 시 연결 완료 화면 전환 |
| META-REQ-007 | 연동 실패 처리 | 중단·실패·필수 자산 누락 시 미연동 상태 유지 |
| META-REQ-008 | 최초 카테고리 매칭 | 연동 완료 직후 카테고리 매칭 모달 자동 노출 |

상세 처리 기준

1. 최초 연동은 연결 관리 탭에서 시작하며, 개인정보 동의를 마친 경우에만 Meta FBE 위저드를 실행합니다.
2. 운영자는 위저드에서 비즈니스 포트폴리오와 필요한 Meta 자산을 선택하거나 새로 만들 수 있습니다.
3. Business Manager, Facebook Page, Pixel/Dataset, Catalog, Ad Account가 정상 수신되어야 연동 완료로 판정합니다.
4. Instagram Business Account는 선택 자산으로, 연결하지 않아도 연동 완료가 가능합니다.
5. Meta 커머스 계정은 연동 대상이 아닙니다. 메이크샵 앱 권한으로 받아올 수 없고, 화면에서 커머스 계정 ID를 쓰는 기능도 없습니다.
6. 정상 연동 완료 시 연동 정보와 토큰을 저장하고 연결 완료 화면을 보여줍니다.
7. 연동 완료 직후 카테고리 매칭 모달을 1회 자동 노출하며, 운영자는 매칭을 나중에 해도 됩니다.

조회 대상 자산

| 구분 | 주요 표시 정보 |
| --- | --- |
| Facebook Account | 계정명과 연결 여부 |
| Business Manager | 비즈니스 관리자 계정명 |
| Facebook Page | 페이지명 |
| Pixel/Dataset | 픽셀 식별값 |
| Instagram Business Account | 사용자명과 연결 여부 |

자산 상태 정의

| 상태 | 판정 기준 |
| --- | --- |
| 정상 | 자산 정보가 정상 조회되는 경우 |
| 미연동 | 자산이 연결되지 않았거나 선택 자산 연결을 건너뛴 경우 |
| 확인불가 | 자산은 있으나 권한 부족, 토큰 만료, API 오류로 조회할 수 없는 경우 |

자산 정보는 조회 전용이며 화면 진입 시 Meta API로 최신 정보를 조회합니다. 자산 변경은 FBE 재설정으로 하고, 생성·수정·삭제는 Meta 관리 화면에서 합니다.

연결 해제 정책

- 연결 해제 확인 후 FBE 해제 API를 호출합니다.
- 해제 성공 시 연결 관리·상품 피드·광고 관리를 미연동 상태로 바꿉니다.
- 상품 피드 동기화와 CAPI 이벤트 전송을 멈춥니다.
- 해제 실패 시 기존 연동 상태를 유지하고 원인별로 안내합니다.
- 이미 Meta에 전달된 상품·이벤트 정보의 삭제는 Meta 정책을 따릅니다.

상품 피드 상태 정의

| 상태 | 결정 주체 | 처리 기준 |
| --- | --- | --- |
| 활동중 | Meta | 상품 승인 완료, 정상 노출 가능 |
| 검토중 | Meta | 전송 요청 접수 후 Meta 검토 진행 |
| 미승인 | Meta | Meta 정책 또는 상품 정보 문제로 승인 거부 |
| 노출제한 | 메이크샵 | 카테고리 미매칭 또는 내부 전송 조건 미충족 |
| 사용안함 | 메이크샵 | 운영자가 상품 피드 사용을 OFF로 설정 |
| 반영대기 | 메이크샵 | 전송 조건을 충족해 전송 큐에 등록되었고 아직 Meta로 전송되기 전 |

전체를 포함해 7개 필터 탭을 제공하며, 실제 상품 상태값은 6종입니다.

| 5 | Meta 전송 접수 | 검토중 |
| 6 | Meta 처리 결과 | 활동중 / 미승인 |

상세 처리 기준

- 카테고리 매칭은 기본분류의 최하위 분류를 기준으로 합니다.
- 한 상품이 여러 분류에 속하면 대표 기본분류를 기준으로 GPC를 적용합니다.
- 카테고리 일괄 매칭은 여러 상품에 같은 GPC를 적용하는 입력 방식이며, 실제 값은 상품 단위로 저장합니다.
- 상품별 [상세]·[선택 수정]으로 GPC를 바꿀 수 있고, 상품 단위 값이 카테고리 단위 값보다 우선합니다.
- 의류 계열 GPC를 고르면 성별은 기본 `unisex`, 연령대는 기본 `all ages`를 적용합니다.
- Google 채널에서 설정한 GPC는 Meta에서도 기본 선택값으로 보여주며 반대도 같습니다.
- 카테고리 매칭 모달과 선택 상품 매칭 팝업의 버튼은 [상품 피드 반영]입니다. 누르면 매칭값을 저장하고, 전송 조건을 충족한 상품을 큐에 넣어 반영대기로 바꿉니다. 이후 큐가 자동으로 보냅니다.

Purchase 처리 기준

- 일반 주문은 결제 또는 구매 완료가 확인된 시점에 Purchase를 만듭니다.
- 네이버페이 주문형과 톡 체크아웃은 각 결제수단에서 구매 완료가 확인된 시점에 처리하고, `payment_method`로 결제수단을 구분합니다.
- 같은 구매 이벤트가 Pixel과 CAPI로 함께 발생하면 같은 `event_name`과 `event_id`를 보내 Meta가 중복 제거하게 합니다.
- Meta에 이벤트를 보낸 사실만으로 광고 전환으로 보지 않으며, 광고 성과는 Meta의 귀속 결과를 기준으로 합니다.
- 일반 CAPI는 사용 설정 없이 연동 완료 상태면 전송하고, 외부 결제 Purchase만 결제수단별 구매전환 사용 여부를 따릅니다.
