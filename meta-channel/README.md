## 실행 방법

- [GitHub Pages에서 바로 보기](https://donghoim.github.io/Makeshop/meta-channel/) 또는 `index.html`을 브라우저로 바로 열면 동작합니다(외부 의존: Pretendard 웹폰트 CDN만 사용).
- 우측 하단 **[⚙ 시나리오 패널]**(Drawer)로 연동 상태·자산 조회 실패·도메인 인증·연결 해제 결과·광고 계정 상태·결제 방식·네이버/카카오 선행 조건 등을 전환하며 QA 시나리오를 재현할 수 있습니다. 실제 서비스 화면에는 없는 도구입니다.
- 상태는 `localStorage`에 저장되어 새로고침 후에도 유지됩니다. 처음부터 다시 보려면 시나리오 패널 > **미연동(최초 진입)** 또는 **저장 데이터 전체 초기화**를 누릅니다.

## 문서 간 차이에 대한 구현 판단

> 화면설계서의 예시 데이터(상품명·카테고리·수치·뱃지 동시 노출 등)는 예시로 간주하고 실제 커머스 데이터로 치환했습니다. 아래는 예시가 아닌 **규칙 자체가 문서 간 다른 부분**에 대한 구현 기준입니다.

| 항목 | 문서 간 차이 | 프로토타입 구현 | 근거 |
|---|---|---|---|
| 카테고리 단위 매칭 저장 | 정책 3-2-4 "저장 = 즉시 전송" vs 정책 5-2-6·5-4-3·화면 3-3-2 "미전송 상태로 저장" | 저장 시 **미전송**으로 전환(즉시 전송 X) | 화면설계서 + 정책 5장(상세) 일치 |

## 알려진 한계 (Prototype 특성상 의도된 단순화)

- Backend/DB 없음. 외부(Meta) 링크는 실제 이동 대신 **바인딩된 URL을 토스트로 표시**합니다(URL 바인딩 검증용).
- 상품 등록/수정 이벤트 기반 자동 전송, 배치 보정, Webhook, CAPI 서버 이벤트 전송은 화면이 없는 백엔드 로직이라 시뮬레이션하지 않습니다(TC에는 포함).
- Meta 심사 결과는 시나리오 패널 [Meta 심사 결과 동기화]로 수동 반영합니다.
- 캠페인 성과는 Mock 일 평균 지표 × 조회기간 운영일수로 산출한 값이며 실제 Marketing API 값이 아닙니다.
- 브라우저 기본 alert/confirm은 테스트 편의상 동일 모양의 커스텀 다이얼로그로 재현했습니다.
